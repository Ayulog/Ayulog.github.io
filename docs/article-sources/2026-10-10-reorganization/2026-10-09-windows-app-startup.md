网速监控、同步工具、远程连接等软件，经常需要跟着电脑一起启动。Windows 提供了好几种设置方式，先看软件有没有内置开关；没有的话，普通桌面程序用启动文件夹通常就够了，需要延迟启动或更多控制时再用任务计划程序。

这里整理 Windows 10 / 11 下的常用方法。文中的 `ExampleApp` 和路径均为示例，使用时换成自己的程序名称与实际位置。

## 先分清开机启动与登录启动

日常说的“开机自启”，很多其实是**用户登录后启动**：电脑开机后，还要进入自己的 Windows 账户，程序才会运行。启动文件夹、注册表 `Run` 项以及系统设置中的启动应用，都属于这一类。

如果希望电脑停留在登录界面时，后台任务就已经开始运行，则需要考虑任务计划程序的“启动时”触发器，或软件本身提供的 Windows 服务。

| 方法               | 主要触发时机           | 适合的用途                         |
| ------------------ | ---------------------- | ---------------------------------- |
| 软件或系统启动开关 | 通常在用户登录后       | 软件已有自启动功能                 |
| 启动文件夹         | 用户登录后             | 普通桌面程序、便携软件             |
| 任务计划程序       | 登录时、系统启动时等   | 延迟启动、脚本、需要特定权限的任务 |
| 注册表 Run 项      | 用户登录后             | 手动登记程序启动命令               |
| 组策略脚本         | 计算机启动或用户登录时 | 有组策略环境的脚本管理             |
| Windows 服务       | 可在系统启动阶段运行   | 原生支持服务的后台程序             |

这些方法没有通用的固定执行顺序。Windows 可能延后部分登录启动项；如果程序之间存在依赖，应通过程序自身的就绪检测、脚本检查或服务依赖来处理，不能仅靠放进不同的自启动位置来保证先后关系。

## 方法一：软件自带设置与系统启动开关

优先打开软件自己的设置，查找“开机启动”“随 Windows 启动”“登录时启动”等选项。有些软件还可以同时设置启动后最小化、隐藏主窗口或仅显示托盘图标。

Windows 也提供了统一管理入口：

1. 打开 **设置 → 应用 → 启动**。
2. 找到目标程序，将开关设为开启。
3. 下次登录后检查程序是否已运行。

也可以按 `Ctrl + Shift + Esc` 打开任务管理器，在 Windows 11 的“启动应用”或 Windows 10 的“启动”选项卡中启用目标项。

这里主要用于管理已经登记的启动应用。列表里找不到某个程序时，可以使用下面的启动文件夹方法；系统服务和任务计划程序中的任务也不都显示在这份列表里。

**取消方法**：关闭软件里的自启动选项，或在系统启动应用列表中禁用对应项目。

## 方法二：启动文件夹

这是给普通桌面程序增加登录自启动的简单办法：把程序的**快捷方式**放进启动文件夹。

### 只对当前用户生效

1. 按 `Win + R`，输入 `shell:startup`，回车。
2. 在打开的文件夹中，右键空白处，选择 **新建 → 快捷方式**。
3. 浏览并选择要启动的程序 `.exe`，完成快捷方式创建。
4. 双击这个快捷方式，先确认它能够正常打开程序。
5. 注销并重新登录，检查是否自动启动。

如果手边已有可用的快捷方式，直接复制进来即可。也可以通过 `Win + R` 输入 `shell:appsfolder` 打开应用列表，从中为应用创建快捷方式。

不要为了自启动而移动整个软件目录或单独复制程序文件，原程序仍应保留在正常安装位置。

### 对这台电脑的所有用户生效

按 `Win + R`，输入：

```text
shell:common startup
```

在这个文件夹中添加快捷方式，会影响使用这台电脑的其他用户，写入时通常需要管理员权限。它仍然在用户登录后触发，程序路径也需要对相应用户可访问。

**取消方法**：从对应启动文件夹中删除自己添加的快捷方式，原程序不受影响。

## 方法三：任务计划程序

需要延迟启动、指定运行账户，或者程序确实需要管理员权限时，可以使用任务计划程序。下面以“当前用户登录后，启动一个有界面的桌面程序”为例。

### 创建登录任务

1. 按 `Win + R`，输入 `taskschd.msc`，回车。
2. 在“任务计划程序库”中选择 **创建任务**。
3. 在“常规”中填写容易识别的名称，例如 `ExampleApp 登录启动`，确认运行账户是自己的账户，并选择 **只在用户登录时运行**。
4. 在“触发器”中点击“新建”，将“开始任务”设为 **登录时**，指定自己的用户。如果想等桌面加载后再启动，可设置延迟，例如 30 秒。
5. 在“操作”中新建 **启动程序**，分别填写程序路径、参数和工作目录。

例如程序位于 `C:\Apps\ExampleApp\ExampleApp.exe`，可以这样填写：

- **程序或脚本**：通过“浏览”选择 `C:\Apps\ExampleApp\ExampleApp.exe`。
- **添加参数**：没有参数就留空；需要参数时，以软件文档为准。
- **起始于**：填写 `C:\Apps\ExampleApp`，只填目录，不加引号。

不要把带参数的整条命令都挤进“程序或脚本”字段。依赖相对路径读取配置的程序，尤其需要正确设置“起始于”。

### 核对运行条件

- **权限**：普通程序不必勾选“使用最高权限运行”。只有程序确实需要提升权限时才启用，并使用有相应权限的账户创建任务；这个选项不会把普通用户变成管理员。
- **电源**：如果希望笔记本使用电池时也能启动，检查“条件”中的交流电源限制是否符合需要。
- **运行时长**：常驻程序要检查“设置”中的超时停止条件，避免运行一段时间后被任务计划程序结束。
- **重复运行**：通常选择“如果任务已在运行，则不启动新实例”，同时确认没有用其他方式重复登记自启动。

保存后右键任务，选择“运行”，检查程序能否打开。手动运行只能验证任务的动作；还需要注销并重新登录，确认触发器有效。

### 如果需要登录前执行

后台脚本可以使用“启动时”触发器，但需要另外配置合适的运行账户、权限和登录方式。创建系统启动触发器需要管理员权限。

带窗口、需要托盘图标的普通软件，通常应使用上面的“登录时 + 只在用户登录时运行”。选择“不管用户是否登录都要运行”，并不意味着它的窗口会出现在自己的桌面上。

**取消方法**：在任务计划程序库中找到自己创建的任务，先“禁用”；确定不再需要后再删除。

## 方法四：注册表 Run 项

`Run` 项用于登记用户登录后执行的命令。一般个人使用选择当前用户的 `HKEY_CURRENT_USER` 即可，修改前可在注册表编辑器中导出要操作的键作为备份。

1. 按 `Win + R`，输入 `regedit`，回车。
2. 在地址栏中定位到：

```text
HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run
```

3. 在右侧空白处右键，选择 **新建 → 字符串值**，名称填写 `ExampleApp`。
4. 双击新建的值，将“数值数据”设为程序的完整路径，例如：

```text
"C:\Apps\ExampleApp\ExampleApp.exe"
```

程序路径用双引号包起来，可以正确处理路径中的空格。如果需要启动参数，把软件支持的参数放在闭合引号后，不要把参数也包进程序路径的引号里。

对所有用户登记启动项，对应的位置是：

```text
HKEY_LOCAL_MACHINE\Software\Microsoft\Windows\CurrentVersion\Run
```

写入这个位置通常需要管理员权限，但其中的程序仍在用户登录时运行，也不会因为写进 `HKEY_LOCAL_MACHINE` 就自动获得管理员权限。

`Run` 用于每次登录启动；`RunOnce` 主要用于安装收尾等一次性操作，不适合这里的长期自启动需求。同一个 `Run` 键下多个项目的执行顺序也没有保证。

**取消方法**：删除自己新增的那个字符串值，保留 `Run` 键和其他软件的项目。

## 方法五：组策略脚本

需要统一管理登录脚本或计算机启动脚本时，可以使用本地组策略编辑器。Windows 家庭版不提供这个编辑器，家庭电脑可直接选择启动文件夹或任务计划程序。

按 `Win + R`，输入 `gpedit.msc`，根据需求选择位置：

- **用户配置 → Windows 设置 → 脚本（登录/注销）→ 登录**：用户登录时执行，适合用户环境中的脚本。
- **计算机配置 → Windows 设置 → 脚本（启动/关机）→ 启动**：计算机启动时执行，使用本地系统账户，适合不需要用户界面的系统初始化操作。

“用户配置”不代表只对当前这一个账户生效，具体范围取决于所编辑的本地组策略。只想为自己的账户启动程序，使用当前用户启动文件夹或指定用户的计划任务更直接。

例如，希望用一个登录脚本打开程序，可以新建 `start-example.cmd`：

```bat
@echo off
start "" /D "C:\Apps\ExampleApp" "C:\Apps\ExampleApp\ExampleApp.exe"
```

`start` 后面的第一对空引号是窗口标题占位，`/D` 指定工作目录，最后才是程序路径。保存时确认文件扩展名是 `.cmd`，而不是 `.cmd.txt`。

在“登录”属性中点击“显示文件”，把脚本放到打开的目录，再通过“添加”选择该脚本。应用设置后，注销并重新登录检查效果。

登录脚本还可能受到“配置登录脚本延迟”策略影响，进入桌面后不一定立即执行；排查时先确认延迟设置，参见[微软的登录脚本延迟说明](https://learn.microsoft.com/en-us/troubleshoot/windows-client/group-policy/logon-scripts-not-run-for-long-time)。

计算机启动脚本运行在系统上下文，不能把它当作给当前用户打开桌面窗口的通用办法；只想打开一个软件时，启动文件夹通常更容易维护。

**取消方法**：回到相应脚本列表，移除自己添加的脚本条目。

## 方法六：软件提供的系统服务

同步、网络或服务器类软件，有些本身支持安装为 Windows 服务。这种方式可以在没有用户登录时运行，适合长期驻留的后台组件。

优先使用软件安装器或官方文档提供的服务安装方式。安装完成后，按 `Win + R` 输入 `services.msc`，找到这个软件对应的服务，查看状态和启动类型；确实需要随系统启动时，可按软件说明使用“自动”或“自动（延迟启动）”。

需要特别区分：`sc.exe create` 只是向服务控制管理器登记服务，并不会把任意 `.exe` 转换成 Windows 服务。普通桌面程序通常没有实现服务入口和控制接口，直接登记可能出现启动失败或超时。

服务也不用于直接显示用户桌面上的窗口。支持后台服务的软件，往往另有一个前台界面或托盘程序，两者可能需要分别设置。

**取消方法**：使用软件提供的服务卸载方式；如果只是暂停自动启动，可调整该软件服务的启动类型。已经运行的实例需要另行停止。

## 设置后没有启动，怎么排查

1. **先确认触发时机。** 登录自启动要在注销并重新登录后验证；锁屏再解锁通常不算一次新登录。系统启动任务则用“重启”验证。
2. **手动运行同一个入口。** 双击快捷方式、执行脚本，或右键运行计划任务，先排除程序自身启动失败的问题。
3. **检查路径与工作目录。** 软件移动、升级换目录、外接磁盘未连接，都可能让旧入口失效；路径含空格时还要检查引号。
4. **检查账户与权限。** 任务是否用了正确的用户，程序是否需要提升权限，后台账户能否访问依赖的目录和网络资源。
5. **检查禁用状态与条件。** 查看启动应用开关、计划任务是否启用，以及电源、空闲、网络和延迟等条件；有需要时查看任务的“上次运行结果”和历史记录。
6. **排除重复登记。** 软件自带开关、启动文件夹、注册表和计划任务可能同时存在。已经能自动启动，就没有必要再叠加另一种方式。

如果只是想让常用软件在进入桌面后自动打开，优先使用软件设置或启动文件夹；需要更多控制，再考虑任务计划程序。注册表、组策略和服务各有用途，按实际需求选择即可。
