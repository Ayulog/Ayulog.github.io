## 先分清发布名与入库名

| 名称         | 主要用途                                   | 优先保留的信息                                   |
| ------------ | ------------------------------------------ | ------------------------------------------------ |
| 资源发布名   | 描述资源来源与制作规格，区分不同发布       | 片名、年份、季集、片源、编码、音轨、版本、发布组 |
| 媒体库入库名 | 让 Emby 等软件匹配作品、分季分集和关联字幕 | 片名、年份、季集，必要时增加数据库 ID 与版本标记 |

发布名里的技术信息可以帮助筛选资源，但**文件名只是标签，不能替代文件本身的媒体信息**。同样，名字越长也不代表越容易刮削；匹配一部电影时，作品名和年份通常比音轨、制作组更重要。

资源名没有一套覆盖所有站点和发布组的强制标准。字段顺序、分隔符和缩写都会变化，下面介绍的是常见习惯。

## 拆开一条资源文件名

先看一条虚构的电影发布名：

```text
Example.Movie.2024.2160p.UHD.BluRay.REMUX.HDR.HEVC.TrueHD.7.1.Atmos-Group.mkv
```

| 字段               | 含义                                               |
| ------------------ | -------------------------------------------------- |
| `Example.Movie`    | 片名，单词间常用英文句点代替空格                   |
| `2024`             | 作品年份，用来辅助区分同名影片                     |
| `2160p`            | 分辨率档位，常见于家用 4K UHD 资源                 |
| `UHD.BluRay`       | 来源标记，这里指 UHD 蓝光                          |
| `REMUX`            | 重新封装，通常表示保留所选原始音视频流而不重新编码 |
| `HDR`              | 高动态范围标记，具体格式还需查看媒体信息           |
| `HEVC`             | 视频编码标准 H.265                                 |
| `TrueHD.7.1.Atmos` | Dolby TrueHD 音轨、7.1 声道相关信息及 Atmos 标记   |
| `-Group`           | 发布或制作组名称，这里只是占位示例                 |
| `.mkv`             | Matroska 容器扩展名                                |

再看剧集：

```text
Example.Series.2024.S02E03.1080p.WEB-DL.DDP5.1.H.264-Group.mkv
```

`S02E03` 表示第二季第三集；`WEB-DL` 表示网络来源；`DDP5.1` 通常指 Dolby Digital Plus 5.1 音轨；`H.264` 是视频编码。音频、视频字段交换位置很常见，不影响理解。

## 片名、年份与季集

### 片名和年份用于定位作品

片名可以是中文名、原名或常用译名。英文名不一定就是作品原名，也不能保证唯一识别；同名电影、翻拍作品，以及不同地区的译名，都可能造成匹配错误。

整理前先到所用元数据源确认作品条目，例如 [TMDB][tmdb] 或 [IMDb][imdb]，再使用相应片名和年份。不同地区上映年份不一致时，以准备匹配的条目为准；仍有歧义时，直接指定数据库 ID 更可靠。

电影文件名中的年份通常是作品上映年份，**不是蓝光发行、修复版推出或文件下载的年份**。剧集总目录通常使用整部剧的首播年份，后续季通过季号区分；发布名也可能携带某一季的年份，需要结合条目核对。

### 季和集是剧集识别的关键

| 标记                    | 常见含义               | 整理时注意                                         |
| ----------------------- | ---------------------- | -------------------------------------------------- |
| `S01E01`                | 第一季第一集           | 适合逐集命名                                       |
| `S01`                   | 第一季                 | 可能是整季包名，不能替代每个文件的集号             |
| `S01E01-E02`            | 同一文件包含第一、二集 | 仅在确实合并了两集、且服务器支持时使用             |
| `S00E01`                | 特别篇中的第一集       | 必须与所选元数据源的特别篇编号对应                 |
| `EP01`、`E01`、绝对集数 | 发布方的集数写法       | 动画、综艺常见，可能需要先转换为元数据源的季集编号 |

不要只根据文件排序批量填 `S01E01`。合并播出、上下集、特别篇，以及电视播出顺序与光盘顺序不同，都可能让后面的集数整体错位。

## 片源与制作方式

| 标记                        | 常见含义                                                        | 不能直接推断的事                                     |
| --------------------------- | --------------------------------------------------------------- | ---------------------------------------------------- |
| `BDMV`、`BDISO`             | 蓝光目录结构或光盘镜像                                          | 原盘里的视频本身已经编码压缩，并非未压缩视频         |
| `BluRay`、`BDRip`           | 蓝光来源；结合其他字段判断是否压制                              | 单独写 `BluRay` 不等于完整原盘                       |
| `REMUX`                     | 提取所需轨道后重新封装，通常不重编码这些流                      | 不等于保留菜单、花絮、全部音轨，也不是恢复成拍摄母版 |
| `WEB-DL`                    | 通常指保留网络平台分发的音视频流                                | 平台提供的流本身已编码，也不保证一定没有水印         |
| `WEBRip`                    | 通常指对网络来源内容进行录制或重编码                            | 各发布方用法不完全一致，需结合发布说明               |
| `HDTV`、`HDTVRip`           | 电视广播来源及其后续处理版本                                    | 可能有台标、广告、隔行或帧率处理问题                 |
| `DVD`、`VIDEO_TS`、`DVDRip` | DVD 结构或由 DVD 制作的压制版本                                 | 画面规格受源材料限制，但可能保留独有版本             |
| `CAM`、`TS`、`TC`           | CAM 常指影院摄录；TS 常指 Telesync；TC 通常指 Telecine 胶片转录 | 三者不是同一种制作方式；实际品质需另看               |

`TS` 还可能出现在 `.ts` 扩展名中，此时通常表示 MPEG 传输流容器，**不能只凭 `.ts` 判断它是影院摄录资源**。

REMUX 主要描述处理方式，BluRay、WEB、HDTV 则描述来源。对同一版光盘，规范的 REMUX 可以保留所选视频流而避免额外编码损失；但不同发行版可能使用不同母版、调色或剪辑，不能把所有资源排成固定的画质等级。

选择时先确认是不是自己要看的版本，再比较实际画面、字幕、兼容性和体积。发布页说明与对比截图往往比单个标签更有用。

## 分辨率、编码与 HDR

### 分辨率是像素规格，不是画质评分

| 标记              | 常见规格或含义                                          |
| ----------------- | ------------------------------------------------------- |
| `720p`            | 常见画布为 1280 × 720，逐行                             |
| `1080p`           | 常见画布为 1920 × 1080，逐行                            |
| `1080i`           | 1080 行隔行信号，需要正确处理场序与反交错               |
| `2160p`、`4K UHD` | 家庭影音通常指 3840 × 2160；影院 DCI 4K 的宽度则为 4096 |

电影可能裁去编码画面中的黑边，例如文件实际为 `1920 × 800`，发布名仍归在 `1080p` 档位。**去掉黑边会减少存储的像素行数；添加黑边则会增加画布高度。** 是否裁掉了有效画面，要结合源片比例和截图判断。

`p` 和 `i` 描述扫描方式，`60fps` 等字段描述帧率；它们不是同一个指标。分辨率更大、帧率更高，也不能单独证明细节更多或画面更好。源材料、缩放处理、码率与编码参数都会影响结果。

### H.264 与 x264 不是同一类名称

| 标记            | 含义                                        |
| --------------- | ------------------------------------------- |
| `H.264`、`AVC`  | 同一视频编码标准的常用名称                  |
| `x264`          | 一种生成 H.264 视频的编码器                 |
| `H.265`、`HEVC` | 同一视频编码标准的常用名称                  |
| `x265`          | 一种生成 HEVC 视频的编码器                  |
| `AV1`           | 另一种视频编码格式，需要核对客户端解码能力  |
| `10bit`         | 视频位深标记，可见于 SDR，也可见于 HDR 内容 |

文件写着 `HEVC`，不能据此断定由 x265 压制。较新的编码标准通常有更好的压缩潜力，但具体画质和体积仍取决于片源、编码器、参数与目标码率。

`.mkv` 改成 `.mp4`、文件名里的 `H264` 改成 `H265`，都不会转换编码。想继续了解编码与封装，可以从本站的[压制常用软件与资料](/posts/2026-10-09-encode-software/)进入。

### HDR、杜比视界与位深分开看

`SDR`、`HDR10`、`HDR10+`、`DV` / `DoVi`（Dolby Vision）和 `HDR Vivid` 描述动态范围或相关视频技术，**不是 H.264、HEVC 那样的视频压缩编码名称**。

`2160p` 不等于 HDR，`10bit` 也不等于 HDR。文件标注了 Dolby Vision，还需要核对其具体 Profile、兼容层以及播放器、系统和显示设备的支持情况；不能假定所有杜比视界文件都能自动回退为 HDR10。

选择 HDR 文件时，先确认实际播放链路支持它。颜色异常、偏色或画面发灰，需要检查 HDR 识别、色调映射与输出设置，不能靠改文件名解决。

## 音轨、字幕与容器

### 先看编码，再看声道和语言

| 标记                   | 常见含义                                     |
| ---------------------- | -------------------------------------------- |
| `AAC`                  | 有损音频编码，常见于网络视频和压制资源       |
| `AC3`、`DD`            | Dolby Digital，有损编码                      |
| `E-AC-3`、`DDP`、`DD+` | Dolby Digital Plus，有损编码；与 DD 有区别   |
| `DTS`                  | 常指 DTS 核心有损音轨；需结合完整名称判断    |
| `TrueHD`               | Dolby TrueHD，无损音频编码                   |
| `DTS-HD MA`            | DTS-HD Master Audio，无损音频编码            |
| `FLAC`                 | 无损音频编码                                 |
| `LPCM`、`PCM`          | 常见的未压缩数字音频表示                     |
| `2.0`、`5.1`、`7.1`    | 声道布局标记，`.1` 表示低频效果声道          |
| `Atmos`、`DTS:X`       | 沉浸式音频相关标记，需要适配的解码与输出链路 |

**Atmos 不等于无损。** 消费级影视资源中的 Atmos 可以随 Dolby Digital Plus 或 Dolby TrueHD 承载；只看到 `Atmos`，还不知道它使用哪一种音轨。

同样，文件名里的 `7.1` 不代表家里会自动出现七个环绕声道，`5.1` 也不是采样率。实际输出取决于播放器解码、是否直通，以及电视、功放或回音壁的能力。

`Dual Audio`、`多音轨`、`国语` 等说明的是语言或轨道数量。要确认有没有需要的语言、是否混入解说音轨，应在媒体信息和播放器音轨菜单里实际查看。

### 字幕有内封、外挂和画面内嵌

- **内封字幕**：字幕轨道放在 MKV 等容器内，播放器通常可以选择或关闭。
- **外挂字幕**：视频旁边的 `.srt`、`.ass` 等文件，依靠命名关联。
- **硬字幕**：文字已烧录进视频画面，通常不能像独立字幕轨那样关闭。

`CHS`、`CHT`、`中字`、`双语` 等发布标记只是线索，不能保证字幕类型、语言、时间轴或翻译质量。PGS 等图形字幕、ASS 特效字幕，也可能影响客户端直接播放或触发字幕烧录。

### MKV 与 MP4 是容器

容器负责装载视频、音频、字幕等轨道。MKV 常用于多音轨、多字幕媒体文件，MP4 在许多设备和网页播放环境中也很常见；两者都不是画质等级。

能否直接播放，要同时看**容器、视频编码、音频、字幕和客户端支持**，不能笼统地说 MKV 或 MP4 一定更兼容。

## 版本与发布组标记

| 标记               | 常见含义                                         |
| ------------------ | ------------------------------------------------ |
| `Extended`         | 加长版                                           |
| `Director's Cut`   | 导演剪辑版                                       |
| `Theatrical`       | 院线剪辑版                                       |
| `Unrated`          | 未分级版，具体内容差别看发行说明                 |
| `Remastered`       | 修复或重新制作版本，不保证所有人都偏好其处理     |
| `IMAX`             | 可能涉及扩展画幅等版本特征，需核实具体片段与来源 |
| `PROPER`、`REPACK` | 通常涉及纠错、修复或重新发布，含义依发布规则而定 |

末尾的 `-Group` 可能对应压制、封装、字幕或发布团队。它有助于追溯版本和制作说明，但不是统一的质量认证。

导演剪辑版、院线版等差别可能涉及内容和时长，整理时应保留版本信息，避免把两部不同剪辑误当作同一个文件覆盖。`PROPER`、`REPACK` 则要先看修复说明，不必仅凭标签重复收藏。

## 电影入库怎么命名

以下使用 [Emby 电影命名规则][movie-naming]。先为每部电影单独建文件夹，用片名和年份定位作品：

```text
movies/
└── Example Movie (2024)/
    ├── Example Movie (2024).mkv
    ├── Example Movie (2024).zh.srt
    └── Example Movie (2024).en.srt
```

外置字幕以视频的完整基本名开头，再追加语言和字幕标记。按 [Emby 字幕命名规则][subtitles]，可用 `zh`、`en` 等语言代码，必要时加上 `forced`、`default` 标记，例如：

```text
Example Movie (2024).zh.default.srt
Example Movie (2024).en.forced.srt
```

`forced` 通常用于只翻译特定外语对白、标牌等内容的字幕，不等于完整字幕；`default` 是默认标记，实际选择还受用户播放设置影响。简繁、双语和自定义名称的显示应在所用客户端中检查。

### 同名作品可以补数据库 ID

Emby 支持在目录名中提供 ID，例如以下结构：

```text
电影名 (年份) [tmdbid=数字ID]
```

这里的 `电影名`、`年份` 和 `数字ID` 都是占位符，使用时从正确的 TMDB 电影条目填写。电影和剧集属于不同类型的条目，不能只复制一串数字而忽略类型。也可以在 Emby 的识别界面中直接填写 ID。

### 同一电影的多个版本

如果需要让 Emby 把不同规格归在同一电影下，多版本文件放在同一目录，文件名以**完整目录名加 `-`**开头，后面写区分版本的标签：

```text
movies/
└── Example Movie (2024)/
    ├── Example Movie (2024) - 1080p SDR.mkv
    ├── Example Movie (2024) - 1080p SDR.zh.srt
    ├── Example Movie (2024) - 2160p HDR.mkv
    └── Example Movie (2024) - 2160p HDR.zh.srt
```

若目录名增加了数据库 ID，视频名的对应前缀也一起调整。外置字幕要匹配具体版本的完整基本名，避免两版时长或剪辑不同造成字幕错位。

## 剧集入库怎么命名

按 [Emby 剧集命名规则][tv-naming]，每部剧一个总目录，每季一个目录，文件名明确写出季和集：

```text
tv/
└── Example Series (2024)/
    ├── Season 01/
    │   ├── Example Series (2024) - S01E01.mkv
    │   ├── Example Series (2024) - S01E01.zh.srt
    │   └── Example Series (2024) - S01E02.mkv
    ├── Season 02/
    │   └── Example Series (2024) - S02E01.mkv
    └── Season 00/
        └── Example Series (2024) - S00E01.mkv
```

`Season 00` 用于所选元数据源定义的特别篇；预告、花絮不能不看条目就随意编进这一季。动画的 OVA、OAD、剧场版有时是特别篇，有时是独立电影，应按实际条目归档。

一个视频确实包含同一季的两集时，可以按 Emby 支持的形式写成：

```text
Example Series (2024) - S01E01-E02.mkv
```

这只是告诉媒体库它对应哪些集，**不会自动把视频切成两份**。只有一个单集文件时，不要因为发布包里写了集数范围就沿用整个范围。

使用 MoviePilot 等工具自动整理时，先确认匹配结果、季集映射和整理预览，再处理整季。对于动漫绝对集数、合集或上下集拆分，先选几集核对标题和时长，能省下后面整库纠错的时间。

## 整理与做种如何兼顾

下载器中的原始目录和给媒体服务器读取的目录可以分开：

```text
data/
├── downloads/       # 保留下载器识别的原始文件名
└── library/
    ├── movies/      # 按电影规则整理
    └── tv/          # 按剧集规则整理
```

需要继续做种时，不要在文件管理器里直接批量移动或改名下载器正在使用的文件。可以让整理工具在媒体库目录创建硬链接，或按存储条件选择复制。

硬链接要求源和目标位于同一文件系统，并需要工具和容器路径支持。两个名字指向同一份文件数据，重命名媒体库里的链接不会改掉下载目录里的名字；但修改文件内容会影响所有链接，不能把硬链接当备份。跨文件系统时通常要改用复制等方式。

先用一部电影和一两集剧集验证：

1. 识别出的片名、年份、季集正确。
2. 整理后的目录和字幕名称符合预期。
3. Emby 能正确入库，切换字幕与音轨后能正常播放。
4. 下载器仍能找到原文件，校验和做种状态正常。

验证完成后，再扩大批量整理范围。

## 用 MediaInfo 核对真实参数

[MediaInfo][mediainfo] 可以查看容器、视频、音频和字幕轨道的信息。选用文本或树状视图，重点检查这些项目：

| 项目                           | 用来核对什么                              |
| ------------------------------ | ----------------------------------------- |
| 容器、时长、文件大小、总码率   | 是否有明显的截断、版本或体积差异          |
| 视频格式与 Profile             | 是 AVC、HEVC 还是其他编码，客户端能否解码 |
| 宽高、帧率、扫描方式           | 实际像素尺寸，是否隔行，帧率是否符合预期  |
| 位深、色彩信息、HDR 格式       | 是 SDR 还是带有相应 HDR 信息的视频        |
| 音频格式、声道、语言、默认轨   | 是否有需要的语言和可播放的音轨            |
| 字幕格式、语言、默认或强制标记 | 是否内封字幕，以及播放器可能如何选择      |

媒体信息能核对文件技术参数，但**不能凭空证明它来自某张光盘、是否原生 4K，或画质一定比另一版更好**。语言标签和默认标记也可能填写错误，最终还要实际试听、查看画面和字幕。

排查时可以按“发布说明 → 文件信息 → 实际播放”的顺序，把文件名、真实参数和播放结果对应起来。

## 常见问题

### 文件名很完整，为什么还是刮削错误？

先检查媒体库类型、片名、年份、季集和目录层级，再核对所选元数据源的条目。已有 NFO 中的错误 ID、不同的剧集排序方式，也可能影响识别；必要时手动指定正确条目，再刷新元数据。

### 2160p、REMUX、TrueHD 都齐了，就一定最适合自己吗？

这些字段描述规格与处理方式。还需要确认版本、字幕、设备解码、HDR 输出、网络带宽和存储空间。高规格文件触发转码或音频不兼容时，实际体验可能不如适配设备的版本。

### 只保留中文片名可以吗？

可以使用中文名，但建议同时保留年份，剧集再保留季集编号。同名作品较多或译名不稳定时，用数据库 ID 辅助识别。技术字段可以放在版本后缀中，不必全部塞进用于匹配作品的主名称。

### 批量改名会改善画质吗？

不会。改名只改变文件系统中的名称；重新封装可以改变容器或轨道组织，重新编码才会改变编码数据。三者用途不同，整理媒体库时先把识别和播放跑通，再考虑是否需要转码。
