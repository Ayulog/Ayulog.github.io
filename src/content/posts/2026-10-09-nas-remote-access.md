## 先选一条适合自己的路线

| 网络和使用需求                                     | 可以优先考虑                     | 主要条件                                       |
| -------------------------------------------------- | -------------------------------- | ---------------------------------------------- |
| 有公网 IPv4，需要用浏览器访问照片、媒体等 Web 服务 | DDNS + 端口映射 + HTTPS 反向代理 | 入站端口可用，能够配置路由器与防火墙           |
| 没有公网 IPv4，但有可用的公网 IPv6                 | IPv6 DDNS + 防火墙放行 + HTTPS   | 外部客户端也有可用 IPv6                        |
| 主要是自己和家人访问，能安装客户端                 | Tailscale 等组网 VPN             | NAS 与客户端加入同一私有网络，访问权限配置正确 |
| 没有可用公网入口，希望提供固定的公开地址           | 公网 VPS + frp 等反向隧道        | 有可达的服务器，愿意承担费用和维护             |
| 想先用起来，不想维护网络工具                       | NAS 厂商远程访问功能             | 机型与应用支持，接受其带宽和功能限制           |
| 没有公网 IPv4，愿意尝试打洞                        | Lucky STUN                       | NAT 环境适合，能接受外部端口变化               |

**私人访问可以先考虑组网 VPN，即使家里有公网 IP 也一样。** 如果希望家人直接打开一个网址，再考虑把需要的 Web 服务通过 HTTPS 提供出去。

远程访问 NAS，也不等于要把整个 NAS 后台开放到互联网。照片、媒体服务和管理后台可以使用不同的访问方式。

## 先判断有没有公网入口

### 公网 IPv4：先看实际拨号设备

进入路由器或光猫管理页面，找到实际连接运营商的那台设备，查看 WAN IPv4。再通过外部查 IP 服务，查看这条宽带的出口 IPv4。

比较时要保证查询走的是家里的这条宽带，没有经过代理或 VPN，并且两边看到的都是 IPv4。

下面这些地址不是可直接用于互联网入站的公网 IPv4：

| 地址范围                                          | 常见用途                     |
| ------------------------------------------------- | ---------------------------- |
| `10.0.0.0/8`                                      | 私有网络                     |
| `172.16.0.0/12`，即 `172.16.*.*` 至 `172.31.*.*`  | 私有网络                     |
| `192.168.0.0/16`                                  | 私有网络                     |
| `100.64.0.0/10`，即 `100.64.*.*` 至 `100.127.*.*` | 运营商共享地址，常见于 CGNAT |

如果路由器 WAN 是 `192.168.*.*`，也可能只是光猫在拨号、路由器又做了一层 NAT。要继续查看光猫，不能直接判定运营商没有分配公网地址。光猫有公网 IPv4 时，可以按自己的网络条件调整桥接与拨号，或者配置两层转发。

WAN IPv4 与外部查询地址一致，通常说明具备进一步配置直连的条件；但运营商可能限制部分入站端口，路由器和 NAS 也可能拦截连接。**最终要以外网能否连接实际服务端口为准。**

另外，公网 IP 不必固定。家庭宽带重拨后地址变化，可以用 DDNS 自动更新域名。

### 公网 IPv6：看承载服务的设备

没有公网 IPv4 时，继续检查 NAS 或运行 Lucky 的设备有没有可用的全球单播 IPv6 地址。

`fe80::/10` 是链路本地地址，`fc00::/7` 是唯一本地地址，不能拿它们作为互联网直连入口。设备显示“已启用 IPv6”，也不代表已经具备外网入站条件。

还需要同时满足：

1. 运营商向家庭网络提供可用的 IPv6 路由和前缀，入口设备拿到了可路由的地址。
2. 对外提供服务的程序监听 IPv6，路由器和设备防火墙允许对应端口入站。
3. 出门后使用的手机流量、公司或酒店网络，也能访问 IPv6。

AAAA 记录应指向**实际接收外部连接的设备地址**。服务在 NAS 上，就不能未经核对直接填路由器的 WAN IPv6；服务入口在 Lucky 上，则应指向 Lucky 所在设备的可达 IPv6。

家庭 IPv6 前缀也可能变化，设备还可能使用会轮换的临时地址。选择适合长期提供服务的地址，并让 DDNS 跟踪它，能减少重连后失效的问题。

## Lucky 与 ddns-go 怎么选

| 工具                                          | 主要作用                                                       | 适合的情况                                 |
| --------------------------------------------- | -------------------------------------------------------------- | ------------------------------------------ |
| [ddns-go](https://github.com/jeessy2/ddns-go) | 获取 IPv4 / IPv6，自动更新 DNS 记录，提供管理页面与日志        | 已经有反向代理或 NAS 自带 HTTPS，只缺 DDNS |
| [Lucky](https://lucky666.cn/)                 | 集成 DDNS、Web 反向代理、TCP/UDP 转发、ACME 证书和 STUN 等功能 | 希望集中管理域名、证书和访问入口           |

可以把它们放到连接流程里理解：

- **DDNS**：让域名始终尽量指向当前 IP。IPv4 对应 A 记录，IPv6 对应 AAAA 记录。
- **端口映射**：在常见家庭 IPv4 NAT 网络中，把路由器收到的连接转到内网服务。
- **反向代理**：接收 HTTP(S) 请求，再转给相应的照片、媒体或文件应用。
- **HTTPS 证书**：让客户端验证访问的服务名称，并加密对应的连接。

ddns-go 不负责端口转发或反向代理；Lucky 的普通反向代理也需要一个可达入口。若使用 Lucky 的 STUN 或其他隧道功能，还要分别满足那些功能的条件。

已经使用 Lucky 的 DDNS，就不必再让 ddns-go 更新同一个域名的同类记录。两者同时写入，可能把地址来回覆盖。

另外，Lucky 仓库明确说明源码公开到 `1.4.10`，后续暂无继续开源计划，因此不能仅凭 GitHub 仓库就把当前版本称为完全开源软件。不同 Lucky / 万吉发行版本的功能范围，也以[官方安装说明](https://lucky666.cn/docs/install)为准。

## 有公网 IP：域名与直连

### 方案一：公网 IPv4 + DDNS + Lucky 反向代理

这条路线需要可用的公网 IPv4 和入站端口。先给 NAS 保留内网地址，再让 DDNS 更新 A 记录，在路由器上把选定的 HTTPS 端口转发到反向代理，由反向代理连接应用。

```text
浏览器 → 家庭公网 IPv4 → 路由器端口映射 → HTTPS 反向代理 → NAS 应用
```

证书、域名解析、端口映射是三件事，分别验证。非默认 HTTPS 端口需要写在访问地址中，A / AAAA 记录不会替浏览器指定端口。完整例子见 [Lucky 的 IPv4 配置](/posts/2026-10-10-lucky-guide/#方案一公网-ipv4--ddns--lucky-反向代理)。

### 方案二：公网 IPv6 + DDNS + Lucky

IPv6 通常不需要 IPv4 那样的 NAT 端口映射，但仍要放行路由器和 NAS 的入站防火墙。AAAA 记录指向入口设备，程序也要监听 IPv6。

Lucky 可以接收 IPv6 请求，再转给内网 IPv4 应用；访问者自己仍需有 IPv6，不能靠反向代理凭空获得这条连接能力。配置见 [Lucky 的 IPv6 说明](/posts/2026-10-10-lucky-guide/#方案二公网-ipv6--ddns--lucky)。

同一域名同时有 A 和 AAAA 时，两条路径分别验证。只有一条可用时，不要留下另一条错误记录。

## 无公网 IP：组网与穿透

这里指的是：没有能够直接接收入站连接的公网 IPv4，IPv6 也不可用，或者经常使用的外部网络无法访问家中的 IPv6。

可以先向运营商询问是否能提供公网 IPv4 或可用 IPv6，但申请条件因地区、套餐和运营商而异。无法获得时，再按使用需求选择下面的方案。

### 方案一：组网 VPN，适合自己和家人

[Tailscale](https://tailscale.com/) 这类组网工具，可以让 NAS、电脑和手机加入一个私有网络。日常使用时，通过 NAS 的组网地址或网络内名称访问服务。

基本流程是：

1. 在 NAS 和远程设备上安装受支持的客户端。
2. 加入同一私有网络，按需邀请家庭成员并授权其设备。
3. 配置访问规则，只允许相应成员连接需要的 NAS 服务。
4. 从外网使用 NAS 的组网地址访问文件、照片或管理页面。

NAS 不支持直接安装时，也可以在家中常开设备上设置子网路由，但需要额外配置路由转发、授权与目标设备防火墙。仅安装一个容器，并不意味着整个家庭局域网都已经可访问。

Tailscale 会尝试建立点对点连接；网络条件不允许时，可以通过中继传输。因此，**无公网 IPv4 不代表一定走中继，安装组网工具也不保证一定直连。** 实际路径可以通过 `tailscale status` 或 `tailscale ping` 检查。

它适合私人访问，代价是访问端通常也要安装客户端。单独安装原生 WireGuard 则还需要规划可达端点和路由，不能把“装上 VPN 软件”当成自动解决所有 NAT 问题。

### 方案二：NAS 厂商远程访问，适合少折腾

如果 NAS 自带远程访问功能，可以先从厂商方案开始。通常只需绑定账号、启用对应服务，再用官方应用或厂商提供的访问地址连接。

要提前确认它支持哪些应用、哪些协议，是否会通过厂商中继，以及账号、套餐、流量和带宽限制。能打开 NAS 管理页面，不一定表示所有 Docker 服务都能一起访问。

这类方案适合日常取文件、备份照片。经常远程播放高码率视频或传输大文件时，应实际测试自己网络下的速度。

### 方案三：公网 VPS + frp，适合固定公开入口

如果没有家庭公网入口，又希望外部浏览器直接打开固定网址，可以让 NAS 主动连接一台具备公网入口的 VPS，再由 VPS 转发请求。

[frp](https://github.com/fatedier/frp) 的常见中转部署就是这种结构：

```text
NAS 上的 frpc → 主动连接 VPS 上的 frps，建立隧道
外部客户端 → VPS 公网入口 → 隧道 → NAS 指定服务
```

准备时需要考虑：

- **服务端与客户端**：VPS 运行 `frps`，NAS 运行 `frpc`，核对版本兼容性、连接认证和隧道传输加密。
- **域名与 HTTPS**：域名指向 VPS；Web 服务可以在 VPS 上处理 HTTPS，也可以将连接转给家中的 HTTPS 入口，按部署方式配置证书。
- **访问范围**：只转发需要的服务，保留应用登录认证，限制服务器的管理入口。
- **成本与性能**：这条中转路径会消耗 VPS 带宽和流量，还受家庭上行、两段线路质量和服务器性能影响。

固定的是 VPS 侧的访问入口，NAS 可以通过主动连接应对家庭地址变化。代价是多维护一台服务器，并持续支付相应费用。

### 方案四：Lucky STUN，适合愿意折腾的环境

Lucky 还提供 [STUN 内网穿透](https://lucky666.cn/docs/modules/stun)。在适合的 NAT 环境下，它可以发现并维持外部映射，让外网通过取得的公网地址和端口访问内网服务。

这与 ddns-go 更新 DNS 记录是不同的事情。Lucky 官方将适用环境描述为 NAT1，并明确提示 STUN 功能用于体验，**无法保证端口变化频率，也不能指定或固定公网端口**。这里的 NAT1 是网络工具中的分类说法，不代表任意运营商 NAT 都支持。

尝试时，可以先按官方文档添加一条穿透规则，选择 TCP 或 UDP，设置未被占用的通道端口、目标设备与目标服务端口，再结合 Lucky 所在位置配置必要的路由转发和防火墙。查看规则日志取得外部地址后，务必从外网验证。

使用前要接受这些限制：

- 能否成功取决于 NAT 行为、光猫与路由拓扑，以及运营商过滤策略。
- 外部端口可能变化；相同端口号的 TCP 与 UDP 映射也不能想当然地共用。
- DDNS 的 A / AAAA 记录只保存地址，无法让普通浏览器自动知道变化后的服务端口。
- 如果另做跳转页来跟踪新端口，跳转页本身仍需要一个可达入口。

STUN 适合当作有条件的直连尝试。需要稳定书签、长期给家人使用的入口时，组网 VPN 或固定 VPS 入口通常更容易维护。排查穿透时也应理解每条规则的作用，避免直接把整台 NAS 设为 DMZ 主机。

## 连接成功后再检查这些

远程能打开网页只是第一步，接下来确认几个实际使用问题：

- **管理入口**：NAS、路由器、Lucky 和 ddns-go 的管理页面，优先通过内网或组网 VPN 访问；SMB 的 `445` 端口也留在可信网络内。
- **账号与权限**：对外应用使用独立账号、强密码，支持时启用多因素认证。HTTPS 保护传输，不代替登录与访问控制。
- **密钥与更新**：DNS API 凭据只授予必要权限，不把真实令牌贴进截图或公开配置；及时更新 NAS、反向代理和对外应用。
- **重新连接**：路由器重拨或设备重启后，检查 DDNS 地址、服务监听和证书续期是否仍然正常。
- **速度**：远程从 NAS 下载文件，主要消耗家里的上传带宽；通过 VPS 或中继时，还要考虑中转链路。

例如家庭上行是 `50 Mbps`，理想换算约为 `6.25 MB/s`，扣除协议开销、其他设备占用后通常更低。媒体播放还要留意码率峰值和 NAS 的转码能力。

## 常见问题

### DDNS 显示成功，为什么还是连不上？

成功只说明 DNS 更新请求完成，不代表入站链路已经打通。可以沿着下面的顺序排查：

1. **解析地址**：A / AAAA 是否指向正确入口，有没有仍在缓存中的旧记录，查 IP 请求是否误走了代理。
2. **网络路径**：公网 IPv4 是否真实可用，是否漏配光猫那一层转发，外部设备是否具备 IPv6。
3. **监听与放行**：应用是否监听对应地址族和端口，路由器、NAS 防火墙是否允许连接。
4. **反向代理**：Lucky 是否收到请求，前端域名是否匹配，后端协议、地址和端口是否正确。
5. **应用设置**：是否需要外部 URL、可信代理、WebSocket 或额外的登录配置。

DNS 缓存受 TTL 影响，更新后不一定所有设备立刻看到新地址。`ping` 不通也不能单独证明 HTTPS 不可用，应测试真正使用的服务端口。

### 为什么家里能打开，出门后打不开？

内网访问成功，只能说明内网这段链路正常。出门后还需要公网入口、正确解析和入站放行；仅提供 IPv6 的服务，还要求外部网络支持 IPv6。

反过来，外网能打开、家里用公网域名打不开，可能涉及路由器不支持 NAT 回环，可以考虑配置内网 DNS，让同一个名称在家里指向内网入口。

### 证书申请成功，是不是说明公网已经通了？

不是。使用 DNS-01 时，证书颁发机构验证的是域名控制权，NAS 可以没有可用的入站连接。证书签发、DNS 解析和服务可达性需要分别验证。
