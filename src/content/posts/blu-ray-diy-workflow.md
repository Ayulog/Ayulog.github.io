这篇围绕给一部蓝光影片补字幕，依次完成原盘检查、准备校对小片、字幕定稿、混流和验收。整个 DIY 类目的流程、软件与其他任务入口放在 [蓝光与媒体工具清单](/posts/media-diy-software/)。

下面以工具能够正常读取的、未加密的普通二维蓝光 BDMV 目录为起点。只增加字幕时，最终视频和音频可以保留原码流；中间压出的小片只是校对副本。UHD、Dolby Vision、多角度和复杂 BD-J 菜单还要另外核对工具支持，不能直接套用普通蓝光的旧教程。

公开资料核查于 **2026 年 10 月 11 日**。BDFix 与 easyavs2bdnxml 放在旧工具衔接的位置说明，不把未经核实的旧版按钮和参数当作当前通用设置。本文未完成实盘制作测试。软件下载入口集中在 [蓝光与媒体工具清单](/posts/media-diy-software/)和[字幕清单](/posts/subtitle-software/)。

## 先定成品目标

同样是“加一条字幕”，输出目标不同，后半段的工作量会差很多。

| 想要的成品                       | 后续路线                  | 要处理的内容                                   |
| -------------------------------- | ------------------------- | ---------------------------------------------- |
| 保留原菜单、花絮和导航的蓝光目录 | 在原结构上重制            | 轨道、播放列表、片段引用与菜单逻辑都要复核     |
| 只保留选定正片的新蓝光结构       | 用 tsMuxer 等工具重新混流 | 正片轨道、章节和新生成的播放结构               |
| 便于媒体库播放的 MKV             | 用 MKVToolNix 等工具封装  | 轨道、语言、默认与强制标记、章节及所需字体附件 |

**tsMuxer 生成一个新的蓝光目录，不等于保留原盘菜单。** 如果目标是第一种，就不能先把原盘合成一个 M2TS，再期待混流工具自动还原花絮入口、选章按钮和多版本关系。

整条流程可以先记成：

```text
原盘副本 → 确认影片版本、MPLS、轨道和章节
                ├─ 原始音视频与原盘结构 → 留给最终混流
                └─ 完整节目 → 校对小片
                                 ↓
字幕原稿 → 校字、对轴 → ASS 排版与版本整理
                                 ↓
                    蓝光：PGS / SUP；MKV：ASS 或 PGS
                                 ↓
原始素材 + 新字幕 → 重制蓝光 / 新建蓝光 / MKV
                                 ↓
                  重新扫描、播放验收、保存工程
```

输入原盘、工作素材和最终输出分开存放，例如 `source/`、`work/`、`output/`。保留原盘副本，Build 或混流输出选择新目录；不要让输出覆盖正在做种或唯一留存的来源文件。

## 第一步：检查原盘与播放列表

先用 BDInfo 扫描原盘，确认准备处理的是哪一个发行版、哪个剪辑版本。记录正片 MPLS、时长、片段顺序、视频帧率、音轨、字幕轨和章节，保留一份报告，后面用来对照输出。

蓝光正片不一定对应一个完整的 M2TS。常说的“肉酱盘”通常是在说正片由多个片段组织、可能带无缝分支的情况；它是口头叫法，实际处理仍要看播放列表。

- **单片段节目**：确认 MPLS 引用的 M2TS、入点和出点，再判断能否直接拿这个文件作工作素材。文件最大只能提供线索。
- **多片段或无缝分支节目**：按正确 MPLS 读取片段顺序和播放范围，不按文件名排序，也不把 `STREAM` 目录里的文件全部拼起来。
- **多个相近的播放列表**：结合正片时长、语言片头、角度、章节和实际场景判断。最长的列表也不一定就是所需版本。

需要一份完整工作视频时，可以按[Remux 流程](/posts/blu-ray-remux/#第一步确认正确的播放列表)先导出所选节目。tsMuxer 可以读取 MPLS，但合并后仍要检查接缝和音画同步；不必为了“原盘有很多文件”就先重写整张碟。

如果后面要保留原菜单，合出的 MKV 或 M2TS 只是工作素材，重制仍从保留的原盘结构开始。不同 MPLS 可能共用片段，修改一个片段可能影响其他版本，这也是先记录引用关系的原因。

## 第二步：准备字幕与轨道安排

字幕可以从原盘提取，也可以从字幕库、SubHD 等公开入口寻找，具体入口见[字幕清单](/posts/subtitle-software/)。下载后先核对片名、年份、发行版、剪辑版本、语言和字幕格式，保存未经改动的原稿及来源信息。

片名相同不代表字幕可以直接使用。院线版、加长版、不同片头，以及流媒体与蓝光之间的剪辑差别，都会影响同步。只有 SUP 图形字幕且需要改字时，先走 OCR；已经有 SRT 或 ASS，就直接进入校对。

这时也把成品需要的字幕列出来，避免排完一套之后又反复返工。例如：

| 素材与需求                 | 可以安排的轨道                   | 先确认什么                                     |
| -------------------------- | -------------------------------- | ---------------------------------------------- |
| 英语原声，有可靠中英文本   | 简英、繁英，按需要另做简体、繁体 | 中英文逐句对应，双行长度和显示时间合适         |
| 非英语原声，主要供中文观看 | 简体、繁体                       | 中文译文完整，原声中的外语段落没有漏译         |
| 还需要纯英文字幕           | 保留原盘英文，缺少时另找匹配文本 | 是完整对白字幕，还是仅外语段落、评论或听障字幕 |

这些是按观看需要作出的安排，不是“英语片必须四条、其他片必须两条”的固定规则。原盘已有的字幕可以保留作对照；若要删减，先确认没有丢掉需要的强制字幕或特殊内容。

字幕文件里可能有制作署名、版本说明、重复条目或广告。先逐项判断，再清理影响阅读的内容；不要把片头片尾所有条目一并删除。保留必要的译者、字幕组和字体署名，按原有使用要求处理，另记本次做了哪些修改，不能把取得的译文标成自己的原创。

## 第三步：制作校对小片，匹配时间轴

原盘直接拖动不顺畅时，再压一份小体积工作视频。可以用 HandBrake 或 ShanaEncoder，具体设置见[字幕校对用的快速压片教程](/posts/handbrake-shanaencoder-subtitle-proxy/)。这里的要求是：

1. 来自上一步确认的完整节目，保留全片时间线，不删片头、不剪片尾、不变速。
2. 保留画面比例和黑边，不把字幕烧进视频。
3. 选字幕对应的原声，避免误用评论音轨或配音。
4. 帧率与源视频一致，不随手把 `24000/1001` 改成 `24`，也不为了小体积改变播放速度。

这份小片只用于听对白、校字和一般时间轴检查。精细定位与最终验收回到原视频；HDR 原盘做 SDR 工作副本时，也不能用副本判断最终字幕的颜色和亮度。

在 PotPlayer 中外挂字幕可以先粗查，在 Aegisub 或 Subtitle Edit 中修改并保存。至少检查开头、中间和片尾，再补查剪辑变化或分支接点：

| 表现                         | 处理方向                                     |
| ---------------------------- | -------------------------------------------- |
| 全片始终早或晚同一段时间     | 整体平移字幕时间                             |
| 开头基本同步，越往后差得越多 | 核对片源播放速度与时基，再决定是否按比例调整 |
| 某个场景以后突然失步         | 检查删减、加长片段或片头差异，按段重对       |
| 时间接近，但对白内容对不上   | 重新核对影片版本、原声和字幕来源             |

[Aegisub 的 Shift Times][aegisub-shift]可以按时间或帧数平移全部、选定或指定范围的行。播放器里的临时字幕延迟只适合判断差值，最终改动要写回字幕工程，并重新加载检查，不能只在自己的播放器里看着同步。

## 第四步：在 Aegisub 中整理样式和版本

文字和时间基本定稿后，再整理字体、字号、描边、边距与双语排版。普通对白可以建立 `MainCN`、`MainEN` 等容易识别的样式；招牌、顶部注释和歌词保留各自的位置与样式，不全选替换成同一种底部对白。

按以下顺序处理更容易回退：

1. 保存一份校对稿，再另存用于排版的 ASS。
2. 核对脚本分辨率、实际画布和所用字体，先检查长句、双行与特殊字符。
3. 做好一份基准版本，再派生简体、繁体、双语或单语稿。
4. 每个版本重新检查错字、人名、标点、换行和缺字，确认删去一行语言后没有破坏标签或布局。

“做完一条，再一拖四”只能理解为复用已经校准的时间轴和样式。简繁转换后，人名、用词和标点仍需校对；从双语稿删除英文，也要检查剩余中文的位置。不能只改文件名，就认为四条字幕已经完成。

如果小片是 720p、目标字幕画布是 1080p，要正确处理坐标缩放，不能只改 ASS 头部的分辨率数字。已有工程如何适配视频，参照 [Aegisub 的分辨率说明][aegisub-resolution]；具体排版和特效见 [Aegisub 教程](/posts/aegisub-ass-effects/)。

## 第五步：把定稿字幕转为 SUP

蓝光里的 PGS 是图形字幕。ASS 转 SUP 会把文字、字体和标签渲染成图像，再编码为带显示时间的字幕流；播放时不再需要同一套字体，后续改字则要回到 ASS 工程。目标为 MKV，且观看设备能正确显示 ASS 时，可以跳过本步，直接封装 ASS 与所需字体。

可以沿用[字幕流程篇的转换路线](/posts/subtitle-workflow/#第六步渲染并转回-sup)：

- **直接转换**：如 kidpoleon 的 [ass2sup][ass2sup]，内部调用 Spp2Pgs，使用前准备字体与 PATH 中的 ffprobe，核对自动匹配到的视频和参数。它会根据视频高度选择输出画布，不要把降分辨率的校对小片当成自动探测的目标视频；确认最终画布和帧率对应成品。Subtitle Edit 也能[导出 Blu-ray SUP][se-file]，具体 ASS 标签支持范围以其文档为准。
- **分步转换**：[ass2bdnxml][ass2bdnxml]将 ASS 渲染成 BDN XML 与 PNG，再由 [SUPer][super]编码为 SUP，适合需要查看中间图像的情况。

先试转包含双语长句、顶部注释、淡入淡出或其他复杂效果的一小段。检查字体、位置、透明度与时序正常，再处理全片；转换耗时取决于片长、效果、工具和硬件，没有固定的“每条几百秒”。

导出前尤其核对三项：

- **目标画布**：普通 1080p 蓝光按对应画布渲染。UHD 也不能直接按视频尺寸导出 2160p 蓝光字幕；ass2bdnxml 的说明要求 UHD 蓝光字幕按 1080p 渲染，由播放器放大。
- **帧率与时间**：以目标节目为准，不能让转换器默认的 23.976 fps 覆盖实际 24 fps 等其他帧率。
- **渲染结果**：PGS 可以表现部分动态效果，但不保存可执行的 ASS 标签；渲染器差异、调色板和解码带宽会限制结果。查看错误与丢弃事件日志，再回看复杂片段。

旧流程里还常见 **easyavs2bdnxml + avs2bdnxml**。如果手里已有可工作的环境，仍按“先核对配置、字体与输入，再小段试转”的顺序处理。本次没有核实到足以复现 `0.3.4.300` 全套选项的官方说明，因此不把“勾选 VSFILTERMODE、取消首尾黑屏”等组合写成通用参数；这些设置不能代替输出检查，也不要与名称相近的 easySUP 混为同一工具。

输出之后重新打开每条 SUP，确认首尾字幕完整、字幕会按时消失，文件名能够区分简繁与双语版本。保留 ASS、字体清单及转换设置；采用分步路线时，XML 和 PNG 一起保存。

## 第六步：按目标混流

到了这一步，输入应是原始音视频或原盘结构，以及已经检查过的新字幕：蓝光使用 SUP，MKV 则可用 ASS 等受支持的格式。不要把校对小片当成最终视频重新混进去。各工具的具体制作路线，包括 KITe UHD 与 Scenarist，另见[蓝光原盘 DIY](/posts/blu-ray-diy/)。

### 保留原菜单：从原盘结构重制

这里的 BDFix 是 **Defsoft 的旧蓝光重制工具**。[历史产品资料][bdfix-info]列出 M2TS / MPLS 模式、轨道替换和新 BDMV 输出等功能。这里可以用它理解重制的工作顺序，但旧资料不足以保证任意 Pro 版本、UHD 或复杂菜单都兼容。

已有可用 BDFix 环境时，按这几个检查点衔接：

1. **打开原盘副本**，确认目标节目、原轨道和输出位置与记录一致。
2. **选择处理范围**。单片段可检查对应的 M2TS；多片段节目按正确 MPLS 处理，不能在 M2TS TREE 里随便选一个文件就加入整片字幕。
3. **确认是新增还是替换**。替换原字幕会占用原轨道的位置；新增轨道则还涉及播放列表与菜单能否选择它。保留需要的原字幕，不覆盖错轨。
4. **载入对应 SUP**，检查语言、顺序及时间线。整片字幕不能直接重复塞进每一个以自身起点计时的片段；确认当前模式怎样处理片段与节目时间。
5. **核对语言标记**。选择工具提供的中文项；三字母语言码本身不能区分简体、繁体、简英和繁英，轨道顺序及说明还要另行记录。
6. **Build 到新目录**，查看处理日志，遇到不支持的轨道或结构先查清原因，再继续输出。
7. **重新打开成品**，从菜单进入正片，逐条切换新字幕，核对章节和其他受影响的节目。

“保留了菜单文件”与“菜单仍能正确控制新轨道”是两回事。原有菜单的语言按钮、轨道编号和 BD-J 导航可能仍指向旧对象；播放器快捷键能切换，也不能证明菜单按钮正确。工具无法完整处理时，应另选支持该结构的重制方案，或回到新建正片蓝光、MKV 的目标。

章节的保留与重读见[章节教程中的 BDFix 部分](/posts/media-chapters/#bdfix-pro重制现有蓝光时保留和复核章节)。

### 新建正片蓝光：tsMuxer

不需要原菜单时，可以用 [tsMuxer][tsmuxer]加载确认好的 MPLS 或完整节目素材，保留所需视频、音频与原字幕，再加入新 SUP，检查各轨语言和章节，输出到新的 Blu-ray 目录。

章节应来自同一影片版本，检查是否正确带入；需要手动填写时见[tsMuxer 章节设置](/posts/media-chapters/#tsmuxer生成蓝光结构时写入章节)。混流结束重新用 BDInfo 扫描，并播放检查片段接缝、音画和字幕。

tsMuxer 的官方仓库在本次核查时已明确标为**停止开发**。它支持多种输入与蓝光输出，但仍要按实际版本检查轨道支持和已知问题，不能把“能加入列表”当成目标设备兼容的保证。

### 输出 MKV：接 Remux 流程

用 MKVToolNix 加入所选节目的原始轨道、新字幕与章节，设置语言、轨道名、默认和强制标记，输出新文件。普通完整中文字幕不应因为想让它默认出现，就一律标成强制字幕。

设备支持 ASS 时，也可以直接封装 ASS 与所需字体，不必先转 SUP；只有目标需要 PGS 时才走图形字幕转换。完整设置接[蓝光原盘 Remux](/posts/blu-ray-remux/#第四步用-mkvtoolnix-整理成品)。

## 第七步：检查目录和实际播放

旧流程有时会在 Build 后运行 **BDFolderNormalizer** 补齐目录。本次没有找到足以核实其当前版本和处理范围的可靠公开说明，因此不把它列为必做步骤。空目录处理不能修复错误的 MPLS、CLPI、丢失的媒体片段或失效菜单，也不能据此判定整张碟合规。

先检查输出日志和目录，再用 BDInfo / MediaInfo 读取成品，与原记录对照。视频、音频、字幕、时长与章节都确认后，还要实际播放：

| 检查点                     | 具体检查什么                                       |
| -------------------------- | -------------------------------------------------- |
| 开头、中间、片尾           | 字幕完整，音画与字幕同步，没有持续漂移             |
| 分支接缝和剪辑变化处       | 没有漏片段、重复画面、声音中断或突然失步           |
| 每一条新增字幕             | 语言与顺序正确，简繁、双语内容没有放错轨           |
| 双行、长句、顶部注释、歌词 | 没有缺字、出界、重叠、闪烁或错误遮挡               |
| 暂停、快进、章节跳转       | 恢复播放后字幕正常显示和清除，不残留上一条         |
| 菜单与导航                 | 正片、选章、音轨和字幕按钮都指向预期内容           |
| 最终观看设备               | 画面、声音和字幕实际可用，HDR 场景下亮度与颜色合适 |

PotPlayer 可以辅助检查媒体和字幕；保留原菜单的成品还要使用能够处理该盘导航的播放器，从蓝光目录或 ISO 入口检查。PowerDVD 等软件是否适用，要看版本、授权功能和目标盘规格，不能把“PowerDVD 20 能打开”当作所有蓝光、尤其是 UHD 的统一验收条件。

如果最终要在实体播放机上使用，还要在那台设备和实际交付形式上检查。只打开 `STREAM` 里的一个 M2TS，验证不到播放列表、选章或菜单逻辑。

## 第八步：整理成品与工程

确认成品可用后再固定目录名和文件名，记录影片版本、来源技术信息、保留与新增的轨道、字幕来源、本次改动，以及测试过的播放器。命名可以参考[影视资源命名](/posts/media-resource-naming/)；名称里写了 DIY，不代表经过重新压制，也不能替代具体的改动说明。

工程至少保留原始字幕、校对稿、最终 ASS / SUP、所用字体清单、对应播放列表与章节记录。输出目录只放成品需要的文件，工作小片、临时 PNG、日志和工程另存，避免混进最终交付。

如果准备通过 BT 分享，先固定成品目录，再制种；发布说明中的片名、轨道信息、截图和字幕署名都与这份成品核对。之后重新下载发布页的种子，指向同一份数据，完成校验再做种。校验通过说明数据与种子一致，影片能否正常播放仍以前面的验收为准；制种后再改文件内容或目录结构，需要重新处理种子。
