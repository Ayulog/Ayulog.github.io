初次配置 OpenWrt 时，可以先将其作为二级路由接入现有网络：保留原主路由正常工作，只在实验路由下接一台测试设备。这样即使配错网关或 DNS，也不会影响家里其他设备上网。

以下配网步骤建立在固件已正常启动、且设备具备独立 WAN 与 LAN 接口的前提下。不同机型的刷机方法差异较大，刷写前需对照具体设备的文档操作。系统与插件汇总见 [软路由系统与插件清单](/posts/soft-router-software/)；iStoreOS 的网络向导、iStore 插件与绿联 NAS 虚拟机部署见 [iStoreOS：安装、配网与插件笔记](/posts/istoreos-guide/)。

## 基础概念与网络角色

### 常见组件名称

- **OpenWrt**：面向嵌入式与路由设备的 Linux 发行版，提供路由、防火墙、无线和软件包管理功能。
- **LuCI**：OpenWrt 默认的 Web 管理界面，日常的接口配置、防火墙与无线设置都在这里完成。
- **iStoreOS**：基于 OpenWrt 定制的系统，内置网络向导与软件中心，详见 [iStoreOS 篇](/posts/istoreos-guide/)。
- **iStore**：适用于部分 OpenWrt 分支的软件中心，安装插件时仍需核对底层固件版本与 CPU 架构。

### 路由器的四种接入角色

| 角色     | 主要工作                                   | 适用场景与特点                        |
| -------- | ------------------------------------------ | ------------------------------------- |
| 主路由   | 连接光猫或上游宽带，负责拨号、NAT 与 DHCP  | 全屋网络入口，改动配置会影响所有设备  |
| 二级路由 | WAN 口接主路由 LAN 口，下挂独立的测试网段  | 适合新系统测试，IPv4 下会形成双重 NAT |
| 无线 AP  | 关闭自身路由与 DHCP，仅扩展现有局域网无线  | 适合补充全屋 Wi-Fi 覆盖，设备同处一网 |
| 旁路由   | 作为局域网内的普通节点，接管指定设备的网关 | 适合单网口小主机或虚拟机按需分流      |

使用 x86 小主机或 ARM 开发板运行路由系统时，是否具备无线 AP 能力取决于无线网卡硬件与驱动支持；多网口软路由搭配独立硬路由 AP 是常见方案。本文以双网口或多网口设备的**二级路由**模式为主；单网口设备可参考 [iStoreOS 篇](/posts/istoreos-guide/)配置为旁路由。

## 固件选择与备份恢复

### 资料查询与硬件核对

同一个商品型号可能存在不同芯片方案、闪存容量或硬件修订版（如 v1、v2）。下载固件前，先从机身铭牌和原厂后台确认完整型号与硬件版本：

| 资料入口                                                 | 适合查询的内容                         | 核对要点                               |
| -------------------------------------------------------- | -------------------------------------- | -------------------------------------- |
| [OpenWrt 设备表](https://openwrt.org/toh/start)          | 官方支持状态、硬件规格与安装恢复方法   | 精确匹配到硬件修订版（Hardware Ver.）  |
| [恩山无线论坛](https://www.right.com.cn/forum/index.php) | 机型讨论、第三方固件发布与刷机排错经验 | 对照闪存布局、分区表与原帖后续反馈     |
| [acwifi](https://www.acwifi.net/)                        | 路由器拆机、功放芯片与无线吞吐测试     | 关注测试环境、频段、距离与具体硬件版本 |

除型号外，还需确认设备的内存与闪存大小、网口数量以及目标固件对无线驱动的支持情况。小闪存硬路由适合承担基础路由与轻量插件，下载、媒体服务和容器建议放在 NAS 或独立主机上。

### 常见固件文件类型

| 常见命名标记       | 典型用途                               | 刷写前核对项                           |
| ------------------ | -------------------------------------- | -------------------------------------- |
| `factory`          | 从原厂固件首次刷入 OpenWrt             | 原厂升级页面是否直接接受、是否需过渡包 |
| `sysupgrade`       | 已运行 OpenWrt 的设备升级或重刷        | 型号、分区布局（如 UBI）是否与当前一致 |
| `initramfs`        | 临时加载到内存运行的引导或救援系统     | 启动后需再刷入对应的 `sysupgrade` 镜像 |
| `.img` / `.img.gz` | x86 主机、开发板或虚拟机的整盘磁盘镜像 | 启动方式（UEFI / Legacy）与目标写入盘  |

从发布页下载固件后，建议在本地核对 SHA-256 校验值：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath ".\firmware.bin"
```

若刷写界面提示机型不匹配或校验失败，应立即中止并重新核对分区表与固件版本，切勿勾选强制刷写，也不要混刷其他设备的编程器固件（会覆盖无线校准数据 ART/EEPROM 与 MAC 地址）。

### 备份配置与准备恢复方案

刷机或大版本升级前，先在电脑上留存以下信息：

- 原系统的管理地址、WAN 接入方式、宽带账号密码，以及 IPTV / VLAN 绑定配置。
- 局域网网段、静态 DHCP 租约、端口转发规则与 Wi-Fi 名称密码。
- 目标机型的离线救砖文档（如 U-Boot Web 恢复页、TFTP 刷机方法、网卡固定 IP 地址及对应的恢复镜像）。

如果设备当前已运行 OpenWrt，可在 LuCI 的 **系统 → 备份 / 升级 → 生成备份** 中下载配置压缩包，或通过 SSH 导出：

```sh
sysupgrade -l
sysupgrade -b /tmp/router-config-backup.tar.gz
```

生成后用 SCP/SFTP 将 `/tmp/router-config-backup.tar.gz` 复制到电脑保存。该备份仅包含 `/etc/config/` 等系统配置文件，不包含已安装的软件包、容器或外接磁盘数据。跨大版本升级、切换固件分支或从原厂固件迁移时，建议在刷入后手动重新配置，将旧备份留作参数参考。

## 二级路由配网（LAN / WAN / Wi-Fi）

以下假设家里现有主路由的 LAN 网段为 `192.168.1.1/24`，实验路由规划使用独立的 `192.168.50.0/24` 网段（管理地址 `ROUTER_IP` 设为 `192.168.50.1`）。若上游网络或 VPN 已占用该网段，请替换为其他未使用的私有网段。

```text
互联网 / 光猫
      │
现有主路由：192.168.1.1/24
      ├── 家中原有设备（手机、电脑、NAS）
      │
      └── LAN 口 ──→ 实验路由 WAN 口（DHCP 获取 192.168.1.x）
                           │
                     实验路由 LAN 口：192.168.50.1/24
                           │
                     测试电脑 / 测试 Wi-Fi（192.168.50.x）
```

### 1. 独立连接并修改 LAN 网段

1. 先不要连接主路由，仅用网线将测试电脑接到实验路由的 LAN 口，并临时断开电脑的 Wi-Fi。
2. 电脑网卡设为自动获取 IP，按固件文档打开初始管理地址，完成管理员密码设置，并在 **系统 → 系统** 中核对时区与系统时间。
3. 打开 **网络 → 接口 → LAN → 编辑**，将 LAN 口改到规划的测试网段：

| 配置项    | 示例设置                                      |
| --------- | --------------------------------------------- |
| 协议      | 静态地址                                      |
| IPv4 地址 | `ROUTER_IP`（如 `192.168.50.1`）              |
| 子网掩码  | `255.255.255.0`（`/24`）                      |
| IPv4 网关 | 留空（默认路由由 WAN 口自动获取）             |
| DHCP 服务 | 启用，起始值 `100`、数量 `100`（`.100–.199`） |

4. 点击“保存并应用”。重新插拔网线让电脑获取新网段 IP，再用浏览器访问新的管理地址 `http://ROUTER_IP` 完成应用确认。

### 2. 接入主路由并配置 WAN

确认新管理后台可正常访问后，用网线将**主路由的 LAN 口**连接到**实验路由的 WAN 口**。

在 **网络 → 接口 → WAN** 中，将协议设为 **DHCP 客户端**。由于上游主路由已完成宽带拨号，实验路由无需再配置 PPPoE。保存后查看接口状态：

- **WAN 口**：已获取 `192.168.1.x` 地址，网关与上游 DNS 指向主路由。
- **LAN 口**：保持 `192.168.50.1/24`，与 WAN 口处于不同网段。
- **防火墙**：保持默认的 `lan → wan` 转发、WAN 区域 IPv4 动态伪装（Masquerade）以及 WAN 入站拒绝规则。

### 3. 配置 Wi-Fi 与客户端验证

若设备带有受支持的无线网卡，可在 **网络 → 无线** 中启用测试 Wi-Fi：

1. 将国家/地区设为实际所在地（影响可用信道与合规功率）。
2. 设置独立的测试 SSID（如 `Router-Lab`），模式选 `Access Point（接入点）`，网络绑定到 `lan`。
3. 加密方式选择 `WPA2-PSK`（AES/CCMP）或 `WPA2/WPA3` 混合模式。
4. 2.4 GHz 频段建议先用 `20 MHz` 频宽，5 GHz 频段避开雷达信道或按周围干扰情况选择固定信道。

配置完成后，用测试电脑或关闭了蜂窝数据的手机连接实验路由，在终端验证网络连通性：

```powershell
ipconfig /all
ping ROUTER_IP
nslookup example.com
```

确认客户端已拿到 `192.168.50.x` 地址、能正常解析域名并访问 HTTPS 网站，且重启实验路由后各项连接依然正常，即可在 LuCI 中导出一份“基础联网正常”的配置备份。

## 软件包与插件安装

### 确认系统与软件包架构

安装插件前，可先在管理首页查看固件版本，或通过 SSH 查看系统与存储详情：

```sh
ubus call system board
cat /etc/openwrt_release
uname -r
df -h
```

对于使用 `opkg` 的版本，可执行以下命令查看支持的软件包架构：

```sh
opkg print-architecture
```

除 CPU 架构外，软件包还受固件分支、C 标准库、内核版本（`kmod-*` 包要求严格匹配）以及包管理器类型（旧版与 23.05 使用 `opkg`，新版逐步转向 `apk`）限制。

### 通过 LuCI 安装软件包

在 **系统 → 软件包** 中点击“更新列表”，检索所需软件并安装。带 Web 界面的服务通常包含核心包与对应的 `luci-app-*` 界面包（以及 `luci-i18n-*-zh-cn` 中文语言包）。

- 每次只安装并测试一个功能模块（如 DNS 分流、远程访问或流量控制），验证正常后再进行下一步。
- 若更新软件源或下载依赖失败，先在路由器 SSH 内测试路由器自身的 DNS 解析、默认路由和系统时间。

### 插件冲突与注意事项

- **避免多套 DNS 抢占端口**：同时启用 AdGuard Home、SmartDNS 或代理插件内置 DNS 时，需按文档错开监听端口并理清上下游转发关系，避免争抢 53 端口或形成回环。
- **避免混用多套透明代理**：不同代理插件会同时改写 `iptables` / `nftables` 防火墙规则，同一时间只启用一套。
- **不混用跨分支软件源，不批量升级所有包**：强行忽略依赖（`--force-depends`）或执行全量 `opkg upgrade` 容易导致核心组件损坏，系统更新应通过固件升级（`sysupgrade`）完成。

## 常用进阶功能

### 静态 DHCP 租约

为局域网内的 NAS、打印机或服务器分配固定内网 IP，可在 **网络 → DHCP/DNS → 静态租约** 中绑定设备的 MAC 地址与 IPv4 地址。手机与平板默认可能开启“私有/随机 WLAN 地址”，绑定前需先在手机端将该 Wi-Fi 的随机 MAC 关闭。

### DNS 过滤与分流

部署本地 DNS 过滤或分流服务时，需先规划好查询链路（例如客户端 → 路由器 53 端口 → 过滤组件 → 上游加密 DNS），通常保留 `dnsmasq` 负责局域网 DHCP 与本地域名解析，再将上游转发或特定端口交由过滤插件处理。测试时注意关闭浏览器自带的“安全 DNS（DoH）”，确保客户端查询确实经过路由器。

### SQM 流量整形

当带宽跑满导致游戏、语音延迟飙升（Bufferbloat）时，可安装 `luci-app-sqm` 进行流量整形。先测出日常稳定的上下行带宽，将整形阈值设为实测带宽的 85%–90% 并对比满载延迟。由于 SQM 消耗 CPU 资源且与部分硬件流量卸载（Flow Offloading）互斥，高带宽环境下需留意 CPU 占用。

### DDNS 与远程访问

需要从外网连回路由或家中 NAS 时，先确认宽带具备公网 IPv4 或公网 IPv6，再结合 DDNS、端口映射或 VPN 组网配置（详见 [NAS 远程访问](/posts/nas-remote-access/)）。路由器自身的 LuCI 管理页与 SSH 建议仅限内网或组网 VPN 访问，不要直接暴露在公网。

### 改为无线 AP 或旁路由

- **无线 AP 模式**：将旧路由 LAN 口改为与主路由同网段且不冲突的空闲 IP，关闭旧路由的 IPv4 DHCP、DHCPv6 与 IPv6 RA 服务，再用网线连接主路由 LAN 口与旧路由 LAN 口（或使用固件内置的 AP 模式向导）。
- **旁路由模式**：与主路由处于同一局域网，关闭自身 DHCP 服务，将默认网关指向主路由；仅将需要分流的客户端网关与 DNS 手动指向旁路由地址。具体配置见 [iStoreOS 篇的旁路由配置](/posts/istoreos-guide/#配置为旁路由并指定客户端网关)。

## 故障排查与日常维护

### 常见故障排查

| 现象                           | 优先检查项                                  | 处理方向                             |
| ------------------------------ | ------------------------------------------- | ------------------------------------ |
| 修改 LAN 地址后进不了后台      | 电脑是否仍保留旧网段 IP、是否误连原有 Wi-Fi | 重新插拔网线刷新 DHCP，访问新管理 IP |
| 电脑获取到 `169.254.x.x`       | 网线是否插在 LAN 口、LAN 口 DHCP 是否启用   | 检查物理接线，或给电脑手动设同网段IP |
| WAN 口获取不到地址             | 主路由 LAN 到实验路由 WAN 的网线及接口协议  | 确认物理网口映射与 WAN 口 DHCP 协议  |
| WAN 与 LAN 网段冲突            | 上游主路由是否同样使用当前 LAN 网段         | 断开 WAN 口，将实验路由改为其他网段  |
| 已获取地址但无法上网           | WAN 默认路由、`lan → wan` 转发与 NAT 伪装   | 核对防火墙区域设置与路由表           |
| 能连 IP 但域名无法解析         | 路由器上游 DNS、系统时间及新装的 DNS 插件   | 停用新增 DNS 插件，恢复默认解析链路  |
| 测试网段无法直接发现主路由 NAS | 二级路由跨网段隔离了二层广播发现            | 直接用主路由网段 IP 访问，或改用 AP  |

排查网络与服务报错时，可在 LuCI 系统日志页面查看，或通过 SSH 检查地址、路由表与最新日志：

```sh
ip addr
ip route
logread | tail -n 80
```

### 配置恢复与固件升级

- **插件配置导致断网**：先在后台停用最近修改的插件，或回滚对应的配置文件。
- **配置混乱但系统仍能启动**：导入此前保存的“基础联网正常”备份，或在备份/升级页面执行恢复出厂设置（清空当前 OpenWrt 配置）。
- **系统无法启动（变砖）**：按照该机型的救砖文档进入 Failsafe 安全模式、Bootloader 恢复网页或使用 TFTP 重刷固件。

日常升级固件前，先查阅新版本的 Release Notes，核对分区格式、配置兼容性及所需插件版本，并在升级前后各留存一份配置备份与安装的插件清单。
