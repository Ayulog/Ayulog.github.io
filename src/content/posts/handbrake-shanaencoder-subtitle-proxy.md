原盘或高码率视频体积大，在字幕编辑器里反复拖动也可能不够顺畅。校字、听对白、调普通时间轴时，先压一份体积小的工作视频，再把 SRT、ASS 外挂上去。这份副本保留完整片长，下面叫它“小片”。

先按 **MP4 + H.264 + 720p + AAC** 跑通一遍。小片要和原片保持相同的剪辑版本、播放速度与画面比例；字幕不烧进画面，改完才能立刻重新加载。精细定位、逐帧特效和最终验收仍回原视频做。

操作以 Windows 为主，默认输入是**逐行、恒定帧率的 SDR 视频**。公开资料核查于 **2026 年 10 月 11 日**，HandBrake 对照 1.11.2 发布记录与官方文档，ShanaEncoder 对照官网列出的 7.4 及帮助条目；不同语言包的选项名称可能略有差异。参数是试压起点，实际耗时和体积取决于片源与硬件。通用转码概念见[一键压制篇](/posts/encode-one-click/)，这里只讲校对小片需要的设置。

## 先准备对应的片源

用 [MediaInfo][mediainfo] 看一下时长、帧率、分辨率、扫描方式、HDR 信息和音轨。字幕对应哪个剪辑版本，就从哪个版本压小片；手上另一份下载的小体积版本，片名相同也不能拿来代替。

蓝光原盘先确认正片播放列表、角度、片长与音轨，必要时先无损 Remux 成一份 MKV，再交给转码工具。**最大 M2TS 只能作为线索**：无缝分支或多片段电影的正片可能由多个文件组成，直接压其中最大的一个，会丢失部分内容。具体核对方法见[蓝光原盘 Remux](/posts/blu-ray-remux/)。

正式小片保留全片，不删片头、不剪片尾、不拼接、不变速。输出另存为 `movie-proof.mp4` 之类的名称，保留原片及字幕工程。试听并选中字幕对应的原声，避免误选评论音轨、配音或口述影像。

## 一组可以先试的参数

下面这组适合先压一分钟，确认清晰度和操作是否正确。只选其中一款软件完成转码即可。

| 项目       | 建议起点                                 | 用途与限制                                                    |
| ---------- | ---------------------------------------- | ------------------------------------------------------------- |
| 封装       | MP4                                      | 便于在常见播放器和字幕编辑器中打开                            |
| 视频       | H.264 软件编码，8 bit、4:2:0             | HandBrake 选 H.264 (x264)，ShanaEncoder 选 H264 (SW: x264)    |
| 尺寸       | 以 1280×720 为上限，等比缩小，不放大小源 | 保留完整画布；非 16:9 视频不要强拉成 1280×720                 |
| 裁剪与滤镜 | 四边裁剪为 0；逐行源关闭不必要滤镜       | 保留黑边和字幕定位参照，不默认降噪、锐化或补帧                |
| 质量       | x264 的 RF / CRF 23                      | 恒定质量不保证文件大小；画面文字看不清时试 21–22 或提高分辨率 |
| 速度       | x264 `veryfast`                          | 适合作为速度优先的起点；有余力再比较 `fast`                   |
| 帧率       | 保持源视频的帧率与时间关系               | 不把 23.976 改成 24，也不把 50 / 59.94 / 60 fps 降成 30       |
| 音频       | 一条原声，AAC、Stereo、128–160 kbps      | 足够作为普通对白校对起点；下混后要试听对白                    |
| 字幕       | 不烧录，校对稿另存为 SRT / ASS           | 后续在编辑器或播放器中外挂加载                                |

HandBrake 的 x264 720p 常规建议范围是 RF 19–23，23 在其中偏向节省体积的一端。这里的 RF / CRF 数字只用于这组 x264 设置，不要原样套到硬件编码、x265 或 AV1 上。

如果只是对对白和普通时间轴，先试 720p；需要读画面上的小字、检查双语排版，可以保留 1080p。降低分辨率会丢失细节，调低 CRF 也不能把已经缩掉的文字恢复出来。

## HandBrake 操作

### 1. 打开源文件，选择起始预设

从 [HandBrake 官网][hb-download]安装，打开确认好的 MKV 或 MP4。检查扫描得到的标题、时长和范围，输出位置指向新文件。

可以从 General 分类里的 **Very Fast 720p30** 开始，再按下面各页修改。这个预设带 **30 fps 上限**，选完预设还要回帧率页改，高帧率源尤其要检查。以后保存自己的校对预设，也要逐个检查新片源的音轨和字幕选择。

### 2. 尺寸：保留黑边，等比缩小

在 **Dimensions / 尺寸** 页：

1. 关闭自动裁剪，选择不裁剪；若界面使用 Custom / 自定义裁剪，把上、下、左、右都设为 `0`。
2. 分辨率限制设为 `720p`，保持宽高比，不允许放大。检查最终输出尺寸，而不是只看输入框里的数字。
3. 普通方形像素的 1920×1080 片源，可以输出 1280×720。已裁成宽银幕的文件按原比例缩小，不必补成或拉伸成 16:9。
4. 查看预览，确认黑边仍在、人脸没有变形、画面没有被截掉。变画幅影片还应查看画幅切换处。

这里保留黑边，是为了让校对画布与原片对应。尤其已有 ASS 定位或字幕落在黑边区域时，不宜在制作工作副本时再裁一次画面。

### 3. 滤镜：只保留确实需要的处理

在 **Filters / 滤镜** 页，这份逐行源关闭反交错、反梳齿、反胶卷，以及降噪、锐化等额外处理。不要为了“更流畅”启用补帧或改变播放速度。

真正的隔行源、胶转磁素材不能照这一步一律关闭处理，相关边界见后面的说明。

### 4. 视频：x264、RF 23、veryfast

在 **Video / 视频** 页设置：

- **Video Encoder**：`H.264 (x264)`，不要选成 10 bit 版本。
- **Framerate (FPS)**：`Same as source`；配合 **Variable Framerate / VFR**，按源时间戳保留时间关系。选 VFR 不会主动把恒定帧率素材变成忽快忽慢。
- **Quality**：`Constant Quality`，RF 先设为 `23`。
- **Encoder Preset**：`veryfast`；Tune 留空或 `None`，Profile / Level 改为 `Auto`，不要沿用起始预设的 Level 3.1 来限制高帧率输出。

已经确认是 CFR 的片源，在目标编辑器明确需要 CFR 时，也可使用 `Same as source + Constant Framerate`。VFR 素材强制 CFR 可能补帧或丢帧，不能把这种转换当成逐帧一一对应。

这套流程使用恒定质量，无需为了旧教程里的固定码率切换到平均码率或两遍编码。文件太大时，先确认没有误留高清无损音轨，再判断是否调整分辨率与质量。

### 5. 音频与字幕：选对原声，清空字幕列表

在 **Audio / 音频** 页只保留需要的原声，编码选 AAC，混音选 Stereo，码率先用 128 或 160 kbps。把多声道音轨下混为立体声后，抽查对白是否清楚；校对片不需要附带所有配音和高清无损音轨。

在 **Subtitles / 字幕** 页，**清空所有条目，包括 Foreign Audio Scan / 外语音频扫描**。只取消某条字幕的 Burn In 不够：预设的自动扫描与轨道选择仍可能带入字幕。保存校对预设时，在字幕选择规则中设为不自动添加轨道，并关闭外语扫描和自动加入 Closed Captions；每次入队前再看一眼列表。

清空字幕列表只影响这次输出，不会删除源文件里的字幕。需要对照原文字幕时，将其单独保留，在校对软件中加载；Burn In 会把字写进画面，之后无法关闭或替换。

### 6. 先试一分钟，再压全片

把编码范围临时设为从片头开始的约 60 秒，另存 `movie-proof-test.mp4`。如果片头只有标志或黑场，可另试一段有对白的片段，但从中途截出的样片不能直接套用全片字幕时间码。

在实际使用的 Subtitle Edit、Aegisub 或播放器里打开样片，检查解码、跳转、画面文字与声音。确认后，**把范围恢复为全部章节或完整时长**，输出正式小片，再保存预设并按需加入队列。预设不会替你确认每个文件的正片版本、音轨和编码范围。

## ShanaEncoder 操作

从 [ShanaEncoder 上游下载页][shana-download]获取程序；本次下载页列出的是 [7.4][shana-release]。它适合 Windows 下批量生成工作副本，基本目标与上面的 HandBrake 设置相同。部分官方帮助沿用旧版截图，第三方汉化包的文字也可能不同，下面按功能名称对应。

### 1. 添加文件并打开快速设置

先添加一个源文件，查看输入信息，核对片长、尺寸和实际帧率。按 **F6** 打开快速设置，在编码设置中选择 `MP4` 输出、软件 `H264 (SW: x264)` 编码；不要误选 `Stream Copy`，也不要在第一次试压时混用硬件编码质量参数。

### 2. 设置视频、尺寸与音频

按设置中的功能名称逐项确认：

1. **视频质量**：在 H264 编码设置中使用 CRF 质量模式，先设 `23`；编码器预设选 `veryfast`，Tune 设 `None`，Level 设 `Auto`。如果仍在按视频码率编码，先切换质量模式，不要把 CRF 数字填进 kbps 输入框。
2. **画面尺寸**：启用尺寸变更，16:9 或更宽的高清源可填宽 `1280`、高 `-1`，将比例变更设为不使用，按原比例计算高度。4:3 高清源可用 960×720；竖屏源按高 `720`、宽 `-1` 等比缩小。尺寸已经低于目标的源关闭缩放，避免放大。关闭裁剪、画面拉伸与不必要滤镜。
3. **帧率与速度**：CFR 片源不勾选更改帧率，播放速度保持 `1.0`，关闭补帧。不要照搬预设里的 24、25 或 30 fps。
4. **音频**：在文件列表右键的“视频／音频流选择”中核对原声，再设置 AAC、Stereo、128–160 kbps，并试听下混结果。多音轨文件里，“第一条音轨”未必是原声。

软件界面里的编码格式、质量模式和编码器速度预设是不同设置。选了 `H264`，还要把 CRF 与 `veryfast` 设上。

### 3. 关闭字幕叠加与自动加载

在 **F6 → 视频／字幕** 页，取消“将字幕叠加到视频”（韩文界面为 `영상에 자막 입히기`）。在“其他”页也关闭不需要的 Closed Caption 字幕封装；字幕轨封装和画面烧录是两件事。

ShanaEncoder 能自动识别同名外挂字幕，也能读取内封字幕。检查文件列表右键的“字幕选择”，不要让同目录的校对稿被意外加载并烧录。界面译名不同时，认“是否把字幕写入视频画面”这项功能，再用下面的样片确认。

先压一份样片，在播放器关闭所有字幕后播放。如果仍能看到字，先确认原视频是否本来就有硬字幕，再检查转码时的字幕设置。已经写进画面的字，转码工具不能将其作为独立字幕关闭。

### 4. 检查日志，再批量处理

通过分段编码或截取范围试压约一分钟，检查编码日志中实际使用的视频编码器、CRF、preset、尺寸、音轨及字幕处理。若查看 FFmpeg 命令，软件 x264 通常对应 `libx264`，质量与速度分别对应 `-crf` 和 `-preset`；这些用于核对，不要求把整条命令粘进 GUI 的扩展参数框。

样片合格后，关闭分段编码、恢复完整片长，再保存设置并处理全片。最后检查输出的帧率、时长、声音与字幕。批量任务中只要片源比例、帧率或音轨顺序不同，设置就要逐项重设，不能整批照搬。

## 压好以后怎么校对

把小片与当前修改的字幕一起加载到 Subtitle Edit 或 Aegisub；需要听声打轴时，确认音频也来自同一版本，并保留原有音视频时间关系。不要把另行提取的音频强行归零后，直接认定它与小片同步。

例如，可以保留下面几份文件：

```text
movie-original.mkv    原片，用于复核
movie-proof.mp4       完整片长的工作副本
movie-working.ass     持续修改的字幕工程
```

用播放器复核时可手动加载字幕，或按播放器规则使用同名文件；避免同时显示一条内封字幕和一条外挂字幕。校对不需要每改一个字就重新压片。

**加载低分辨率小片时，保留 ASS 原有的 PlayRes 脚本分辨率，不要因为视频变成 720p 就自动重采样已有工程。** 等比缩小完整画布通常便于继续校字和粗看位置，但不能代替原分辨率下的字号、描边、遮罩、特效与 SUP 图像检查。原 MKV 中的字体附件也不会自动随视频进入这份 MP4，校对时仍需准备对应字体。关于脚本坐标与排版，接 [ASS 特效字幕教程](/posts/aegisub-ass-effects/)。

需要对照原 PGS 图形字幕时，另用支持它的工具打开原 SUP 或原片，不要为了适应 720p 小片反复缩放正式字幕。提取与校对方法见 [SUP 字幕处理教程](/posts/sup-subtitle-editing/)。

全片压好后，至少在**开头、中段、片尾**找有对白的位置，与原片同一段交叉核对：

| 看到的问题                 | 优先排查                                                     |
| -------------------------- | ------------------------------------------------------------ |
| 从头到尾都差不多提前或延后 | 起始时间、音轨延迟、试压范围，是否加载了另一版本的音频       |
| 开头对得上，越到后面越偏   | 先查变速、误改帧率或字幕来自另一版本；单做整体平移会掩盖问题 |
| 某一处以后突然错位         | 删片头、分支拼接、缺片段、不同剪辑版本                       |
| 时间对，位置或比例不对     | 裁边、拉伸、像素宽高比，以及 ASS 是否被重采样                |

帧率数字相同、总时长接近，时间轴仍可能不一致。小片校对完成后，把字幕加载回原片，复查对白、场景切换、长句、注释与片尾，再进入[字幕整理与封装流程](/posts/subtitle-workflow/)。

## 几种需要另行处理的情况

- **HDR / Dolby Vision**：把 HDR 片源直接压成 8 bit H.264，画面并没有真正转成 SDR。优先用确认过的 SDR 片源；只有 HDR 源时，需另外配置色调映射和颜色转换，检查是否发灰、过暗或偏色。小片不用于判断最终 HDR 颜色，背景见[认识 HDR](/posts/understanding-hdr/)。
- **VFR 录屏或手机视频**：HandBrake 的 `Same as source + VFR` 用于保留源时间关系，但编辑器也要正确读取时间戳。ShanaEncoder 的“关闭帧率转换”对 VFR 文件是否保留时间戳，仍要看编辑器导入结果；需要逐帧对轴时，不用一个平均 fps 推算全片帧号。
- **隔行与胶转磁片源**：反交错、场率与逆胶转磁会影响帧数和时间对应，先确认素材类型再处理；不能直接套用逐行源设置。
- **想用显卡加速**：可以试 H.264 的 NVENC、QSV 或 AMF，选项是否可用取决于硬件、驱动和程序版本。改用硬件编码后重新试压，按该编码器的质量模式设置，不能照搬 x264 的 CRF 与速度预设。编码快也不保证拖动最顺畅，仍需在校对软件中实测。
