给原盘加上音轨、字幕之后，还要让菜单能选中它们。这涉及三件事：菜单上显示什么、按钮执行什么动作，以及目标播放列表实际开放了哪条轨道。只改图片时按钮可能仍指向旧字幕，只改轨道时菜单也不会自动多出选项。

两种菜单要分开处理：**IG 菜单**改图形流、按钮命令和播放列表关联；**BD-J 菜单**则要沿 Java 应用的入口，查资源、按钮数据和动作逻辑。混流本身见[蓝光原盘 DIY](/posts/blu-ray-diy/)，目录关系见[认识蓝光碟片](/posts/understanding-blu-ray/)。

公开工具资料核对日期为 **2026 年 10 月 11 日**。下面涉及的菜单框架来自不同年代，没有逐一完成实盘修改和硬件播放测试；具体类名、按钮编号、PID、时长与编译环境都要从目标盘读取。

## 先判断菜单类型，再记下轨道关系

### 从实际播放入口判断

| 要看什么     | IG 菜单                                                          | BD-J 菜单                                       |
| ------------ | ---------------------------------------------------------------- | ----------------------------------------------- |
| 菜单内容     | Interactive Graphics 流中的页面、按钮、图形对象和命令            | Java Xlet 使用的类、图片、字体和配置数据        |
| 主要入口     | HDMV 导航、MPLS 中的 IG 流关联；独立 IG Clip 常通过 SubPath 引用 | 标题对应的 BDJO 应用表、入口类与应用 classpath  |
| 常见文件     | `MovieObject.bdmv`、MPLS、CLPI、承载 IG 的 M2TS                  | BDJO、JAR，以及 JAR 内外的 XML、PNG、二进制资源 |
| 新增选项要改 | 按钮状态、方向导航、动作、流关联                                 | 按钮列表、资源引用、轨道映射、动作及可能的分页  |

**不能只凭盘里有没有 `JAR` 目录分类。** 同一张盘可以有不同类型的标题；正片菜单、花絮和其他应用也可能走不同入口。应先确认从主菜单进入正片时调用了哪个标题、哪个 MPLS，以及呼出的菜单属于哪条路径。

IG 与字幕常见的 PG / PGS 是不同用途的图形流。字幕 SUP 可以参与混流，但不能靠改扩展名变成带按钮和导航命令的 IG 菜单。

### 做一张菜单与轨道对应表

至少记录这些内容：

- 实际进入正片的 MPLS，以及是否存在多版本、多语言或无缝分支的其他入口。
- MPLS 引用的 M2TS、CLPI、主菜单和 Pop-up Menu（弹出菜单）。
- 菜单按钮 ID、显示文字、按钮动作、目标轨道在当前 MPLS 中的位置，以及实际 PID。
- 新增或删除轨道以后，这些对应关系是否发生变化。

例如，一个字幕按钮原先选择“当前列表中的第 8 条字幕”。混流时把原本未开放的轨道也全部加入列表，新中文字幕可能变成第 12 条；按钮仍选择第 8 条，就会出现“文字是中文，实际切到另一条字幕”的情况。这里的数字仅作说明，程序和工具中的编号还可能分别从 0 或 1 开始。

**轨道序号、PID、按钮 ID 和 SubPath ID 要分别记录。** 它们不是同一套编号。所谓“隐藏轨道”也可能只是某个 MPLS 的 STN（Stream Number Table）未列入该流，数据仍在 M2TS 中；从 STN 去掉一项只是在列表里撤掉，M2TS 内的轨道还在。

动手前保留完整原盘副本，另建工作目录、拆分资源目录和输出目录。后续按“改一组关联文件、保存一个版本、测试一次”的顺序进行，避免最后同时排查图像、Java 和播放列表三个问题。

## 一、IG 菜单

### 工具怎么分工

[BDEdit][bdedit] 可以查看 BDMV 导航结构，并提供 IG 菜单、对象和调色板的编辑、导出与复用功能；[IG Editor][ig-editor]侧重页面、按钮、导航命令和图形资产，也支持 PSD 工作流。菜单完成后可进入对应的编著工具，例如 [EasyBD UHD][easybd] 或 Scenarist 的制作流程。

截至核查日，BDEdit 官网说明、更新记录与第三方下载目录列出的版本号并不完全一致，这里不指定一个“最新版”。涉及 UHD 时，应确认手上的构建能够正确读取该盘字段，保存前后对照文件变化。IG Editor、EasyBD 的公开 Demo 与当前商用版本也可能不同，安装前核对版本和功能。

[justdan96/tsMuxer][tsmuxer] 已停止开发，最终版为 **2.7.0**。其使用说明列有 PGS、SRT 等输入，不能据此把它当作 IG 菜单编辑器。尤其是从 MPLS 重新混流以后，不能假定输出继承了原盘全部菜单关联。

### 1. 找到主菜单和弹出菜单

在 BDEdit 中打开原盘，从实际播放的 MPLS 检查 PlayItem、STN 和 SubPath。对于独立承载 IG 的 Clip，SubPath 通常能看到 `IG menu` 一类的条目，再由 SubPlayItem 查到具体 Clip。

切到对应 Clip，进入 Menu 视图，核对页面内容、按钮文字和对象。主菜单与弹出菜单可能是不同 Clip；多语言盘还可能有英语、法语等不同主菜单，以及同一正片下的多组弹出菜单。不要找到第一个看得懂的菜单就停止检查。

有些 IG 与其他流复用在同一个 Clip 中，并不采用独立 SubPath 的形式。下面恢复 SubPath 的流程针对**原盘本来使用独立 IG Clip**的情况，不能给所有盘都机械增加一条 SubPath。

### 2. 分清页面、按钮和图形对象

IG 编辑器里的 Page、Button、Object、Palette 各自承担不同作用。通常要核对：

| 部分                               | 修改时要保持的关系                                                     |
| ---------------------------------- | ---------------------------------------------------------------------- |
| Page / BOG（Button Overlap Group） | 按钮所属页面、按钮重叠组，以及组内哪些按钮允许显示                     |
| Button                             | 按钮 ID、坐标、默认焦点、上/下/左/右邻接按钮                           |
| 状态对象                           | Normal、Selected、Activated 等状态所引用的对象；有动画时还包括对象范围 |
| Object / Palette                   | 位图内容、尺寸、透明度、调色板以及引用编号                             |
| Command                            | 确认按钮后切换的流、跳转目标或导航动作                                 |

**替换已有文字**时，可以沿用原按钮 ID 和动作，替换相关状态图并检查尺寸、位置与透明度。普通状态改成中文后，还要查看选中、按下时是否重新露出旧文字。

**新增按钮**时，先复制功能接近的按钮，再分配可用 ID，补图形对象、方向导航和动作。还要检查默认焦点、返回路径和按钮组规则，避免出现“按钮可见但方向键永远到不了”或“按下后跳回错误页面”。

音轨、字幕按钮的动作必须与目标 MPLS 的 STN 对应。某些盘还会通过 MovieObject 或寄存器保存选择状态，不能把看到的一条切换命令当作完整逻辑。

### 3. 输出修改后的 IG

可以沿用 BDEdit 的菜单导出、编辑和复用流程，也可以在 IG Editor 中整理图形与命令后，交给支持该输出的编著工具。各工具的项目格式、菜单资产格式和成品 M2TS 不可互换使用。

BDEdit 官方说明列有 `.mnu` 菜单导入导出、PNG 对象处理和将菜单复用至 M2TS 的功能。输出后应检查它生成或更新了哪些文件：**承载 IG 的 M2TS 与描述该 Clip 的 CLPI 必须配套**，播放列表中的引用也要与它们对应。

如果 IG 本来与音视频共同复用，处理范围会比独立菜单 Clip 大；不要直接用一段只有菜单数据的 M2TS 覆盖原有音视频 Clip。保留原流的组成、时间关系和关联文件，再用工具允许的方式重建。

### 4. tsMuxeR 混流后恢复弹出菜单

常见现象是：正片正常播放，遥控器却呼不出原有 IG 弹出菜单。此时先检查原盘 MPLS 的 IG 关联是否在新输出中丢失。

用两个 BDEdit 窗口分别打开原盘与工作盘，对照同一个实际播放入口：

1. **确认菜单资产存在。** 工作盘内应有被引用的 IG M2TS 和对应 CLPI，文件编号按实际输出确认。
2. **恢复 SubPath。** 对原来独立挂接的 IG，核对 SubPath 类型和数量；多语言或多组 Pop-up 要分别处理。
3. **恢复 SubPlayItem。** 填写正确 Clip、In/Out 时间，以及与主 PlayItem 的同步关系。正片经过裁切、合并或时间轴变化时，不能把原盘时间原样照搬。
4. **恢复 STN 中的 IG 项。** 将 IG 流登记到对应 PlayItem 的流表，核对工具显示的 SubPath 引用、SubClip 引用、PID 和语言等字段。
5. **检查其他 SubPath。** UHD 盘可能还有其他用途的子路径；增加 IG 后重新核对编号，不能覆盖原有条目。
6. **检查所有实际入口。** 多版本、多语言或多段播放的 MPLS，要逐个确认相关 PlayItem；同时保留音频、PG 字幕与原菜单期望的顺序。

旧案例中的固定 Clip 编号、`1400` / `1401` 或某个结尾固定的 Out Time，都只是那张盘的参数。**PID 要从实际 Clip 和流表读取，不能按“1080p 用一个、4K 用另一个”推断。**

修改已有导航文件后，检查工具是否同步了相应 `BACKUP` 副本，并保持存在的备份项与主文件一致。不要把编辑器生成的临时备份文件当成盘片规范要求的 `BACKUP` 目录。

### 5. 文字已经烘焙进菜单视频时

有的菜单把文字画在背景视频里，IG 只负责覆盖高亮或响应按键。这种情况下，改 IG 对象不会改变背景上的文字，要同时处理视频层。

先检查源 Clip 的分辨率、帧率、帧数或时长、像素格式、色彩信息和时间戳。可以用 MediaInfo，或使用 [ffprobe][ffprobe]：

```powershell
ffprobe -v error -select_streams v:0 -show_streams -show_format -of json "menu-source.m2ts"
```

确认素材确实是静止背景后，才适合按“提取画面 → 修改文字 → 按原时间线重新编码 → 复用并生成配套 CLPI”的路线处理。动态背景只改第一帧并循环播放，会丢掉原来的动画。

UHD 盘上的菜单 Clip 也可能是 SDR，色彩信息按实际 Clip 确认。HDR 画面转 8-bit PNG 时，改色彩标签不会执行色调映射，重编码时写上 BT.709 也不完成转换。输出应采用明确的色彩管理和目标盘允许的编码参数，再检查高亮层是否仍然对齐。FFmpeg 能输出 AVC / HEVC 文件，编码参数仍要符合蓝光编著要求。

## 二、BD-J 菜单

### 1. 从 BDJO 找到真正的应用入口

BDJO 包含应用的启动和类路径等信息，播放器据此找到 Java Xlet。先查看目标标题对应的 BDJO，记录应用入口、Organization ID、Application ID、相关 classpath 和 JAR，随后再分析代码。[HD Cookbook 的 BDJO 工具说明][hdc-bdjo]可用于理解这层关系。

不要假定 `00000.jar` 就是全部菜单。有的 JAR 保存逻辑，有的保存语言资源、字体或通用组件；文件间还可能存在依赖。`CERTIFICATE` 目录与相关盘片标识也应一起保留。

用反编译器查找入口类后，沿初始化、语言分支、主菜单对象往下找。像 `MenuXlet`、`initXlet`、`Sublist`、`audiolist`、`setup` 等名称或字符串可以提供线索，但类名可能被混淆，菜单也可能完全由数据文件描述。

BD-J 使用 Java TV、DVB、HAVi 等平台 API，不能用普通桌面 Java 项目的依赖替代。反编译结果主要用来阅读和定位，不应默认等同于可以重新构建的源码。

### 2. 先认框架，再找修改点

下面这些是不同菜单案例中出现过的结构，适合用来判断查找方向：

| 结构线索                                                                                     | 通常要一起检查                                                    |
| -------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| 部分迪士尼 UHD 菜单：入口、语言菜单、主菜单与 Pop-up 子菜单分开                              | 按钮列表、图像定义、动作类、播放列表/轨道数据，以及各状态图       |
| Radius60 菜单：PNG 图集、XML、Java 列表/显示/动作类                                          | 资源名、图集坐标、按钮与轨道映射；有的还使用 `bluray_project.bin` |
| 部分 Sony 菜单：`common.properties`、`onQClient.cfg`、`playlists.xml`、HCF / QCT             | 默认语言与资源目录、音频/字幕/强制字幕数据、字形尺寸和按钮表      |
| 《天堂公路》对应的另一套菜单结构：`com.dbp.MenuXlet`、`menu.xml`、`disc.xml`、`chapters.xml` | 菜单配置、盘片与章节映射，以及 PNG / CSV / TXT 等字体和资源索引   |

**片商名称不等于菜单框架。** 例如狮门的不同影片就可能分别采用 Radius60 和另一套结构；同一框架的不同影片也可能改过类名、数据组织和分页方式。不要把某片的混淆类名、菜单总类或固定文件编号当作检索模板。

### 3. 新增音轨或字幕按钮

新增一个选项时，把下面几层连起来：

1. **物理轨道与 MPLS。** 新流已经混入，目标 MPLS 的 STN 能选到它，PID 与 CLPI 一致。
2. **应用内轨道数据。** 程序使用的播放列表描述、轨道变量或二进制索引也要包含新轨道，MPLS 里的流表只是其中一层。
3. **按钮列表。** 插入新按钮，检查数组长度、条目数、排序与按钮 ID。
4. **显示资源。** 按钮引用的资源名、图片位置、宽高和状态图都有定义。
5. **点击动作。** 将按钮关联到正确轨道，同时检查音轨选择、字幕开关和“关闭字幕”条目的区别。
6. **选择反馈。** 当前选项的勾选标记、滑块、下次打开菜单时的焦点，以及主菜单与 Pop-up 的显示要同步。

调试时可以先借用已有按钮图，做出一个能正确切轨的新条目。动作确认后，再换成最终文字和状态图。这样能区分“轨道/按钮映射错误”和“图片资源没有定义”两类问题。

有些框架的切轨动作读取统一列表，不需要为每个新按钮增加一个动作类；另一些则必须修改动作分派。应沿现有按钮看它如何工作，不能固定认为“只改五个 class”就完成。

对于有多条实际播放 MPLS、且开放轨道不同的盘，还要逐个核对。不要因为 BD-J 菜单来自 JAR，就认为新混流生成的 MPLS 总能直接替换原盘。

### 4. 图片图集与翻页

BD-J 按钮常从一张较大的 PNG 图集中裁切出来。修改时记录每张图的资源名、X/Y、宽/高、透明度，以及 Normal / Selected / Activated 等状态的引用。

如果是字形图集，新增汉字还涉及字符索引、字宽与间距；光把“中文字幕”画进 PNG 空白处，程序不会自动知道这些字在哪里。Sony 案例中的 HCF、Radius60 的 XML，以及其他框架的 CSV / TXT，都可能承担不同的索引工作。

画布也不宜无条件扩大。要考虑原框架对图片尺寸、内存、坐标和加载方式的处理，再决定复用空位、增大图集还是添加独立资源。

**新增条目超过一页时，分页要单独处理。** 《蚁人 3》的 Radius60 案例中，新增音轨或字幕后不会自动分页，需要参考已有的章节分页组，把菜单组改为相应的分页结构，并补齐上一页、下一页和箭头显示逻辑。这是该框架的修改思路，不能直接复制类名到其他影片。

翻页后至少检查：首尾页箭头是否正确、方向键能否跨页、当前选项是否仍有标记，以及返回菜单时是否保留合理的页码和焦点。

### 5. 重编译与打包

反编译前保留原 JAR，再建立独立源码和编译输出目录。用多个反编译器对照有助于发现错误还原，但遇到控制流、内部类、重载或异常处理问题时，仍需要核对原字节码。

先尝试**不改业务逻辑的回编译**。如果原样都不能生成可用 class，先解决依赖和反编译错误，不要在这个基础上继续加按钮。

编译时重点检查：

- BD-J 平台 API、原包依赖和字节码目标版本是否匹配。
- 包名、类名、方法签名和资源路径是否保持原有关系。
- 内部类、匿名类以及其他伴随生成的 class 是否完整。
- 平台 API 只用于编译依赖，没有被误打进应用 JAR。
- 替换后 JAR 的目录层级正确，没有多套一层工作目录。

旧版 Scenarist BD-J 工具的记录使用过 JRE / JDK **1.5.0_07** 和当时的 Safeguard 组件。这说明的是那套历史环境，不能写成今天所有菜单修改都必须安装的 Java 版本，也不能默认换成最新 JDK 后就兼容。

[Scenarist 当前官网][scenarist]分别列出 BD、UHD 与 Designer 产品；Designer 是制作菜单图形资产的 Photoshop 插件。产品支持菜单制作，任意发行盘的 JAR 仍需自行反编译与重建。现有工具链需要哪些 API、编译器和签名组件，按对应版本文档与实际工程确认。

### 6. BD-J 重签名

改动原先已经签名的 JAR 内容后，原摘要与签名不再匹配。即使只换了一张包内 PNG，也可能遇到这个问题。

**普通 Java SE 的 `keytool` 加 `jarsigner`，不能直接当作完整的 BD-J 重签流程。** [HD Cookbook 安全工具说明][hdc-security]明确指出，BD-J 的签名清单还需要 `BDJ-Signature-Version: 1.0` 等要求，并提供 `BDCertGenerator`、`BDSigner` 等专用工具。这是旧 java.net 项目的公开档案，应按历史实现阅读，不能当作当前 Oracle 支持的即装即用工具；签名后再用压缩工具手工加入一行属性，也会破坏原有签名关系。

签名时需要连同盘片一起考虑：

- **密钥、证书链与 JAR。** 签名使用私钥；`app.discroot.crt` 是供验证使用的应用根证书，复制原证书不能代替原私钥。
- **Organization ID 等应用身份。** 从本盘 BDJO 和相关盘片信息核对，保持与证书和应用配置一致。不要按片商套用固定值，也不要为了解决报错随意改身份字段；应用存储和权限可能依赖它们。
- **涉及哪些 JAR。** 保留现有根证书与密钥关系时，处理范围和更换整套根密钥不同。若采用新的根证书，所有仍需要由该信任链验证的已签名 JAR 都必须纳入一致性检查，其余仍用旧链的包也要一起重签。
- **其他关联数据。** 权限请求文件、持久化访问凭据，以及用到在线功能时的签名资料，可能还有独立要求。

旧版 Scenarist 流程中“新建密钥、统一重签 JAR、生成新的 `app.discroot.crt`”是在建立新的签名关系，不能恢复发行方的原签名。具体操作应使用对应工具链的完整流程，并核对生成的证书及其备份位置。

删掉整个 `META-INF` 目录不是一个通用修复步骤。这个目录可能包含清单和其他有效元数据；旧签名条目应按所用签名工具的要求处理。未签名应用与已签名应用的权限也不同。

下面的命令仅用于辅助查看 Java JAR 的签名和证书情况：

```powershell
jarsigner -verify -verbose -certs "work-app.jar"
```

它不能验证完整的 BD-J 盘片合规性。新版 JDK 还会依据安全策略处理已禁用的算法，某些旧签名可能被视作未签名；阅读输出时要记录 JDK 版本并查看具体原因，见 [Oracle 文档][jarsigner]。没有必要为通过一次检查去修改系统全局安全策略。

## 改完后的菜单与播放测试

测试时从**整个蓝光目录或 ISO 的菜单入口**打开。双击正片 M2TS 只能证明音视频可以解码。

| 测试项目         | 要确认的内容                                                     |
| ---------------- | ---------------------------------------------------------------- |
| 冷启动           | 完整退出播放器后重新打开，能正常经过入口到达菜单                 |
| 主菜单与弹出菜单 | 播放前、播放中、暂停后都能按预期进入和退出                       |
| 按钮导航         | 上下左右、确认、返回、首尾页和默认焦点没有断路                   |
| 音频与字幕       | 每个新选项都切到实际目标流，关闭字幕、强制字幕和导评选择没有混淆 |
| 显示反馈         | 普通/选中/按下图像、勾选标记、滑块和分页状态对应实际选择         |
| 播放路径         | 章节跳转、返回主菜单、多语言、多版本和无缝分支都按实际入口检查   |
| 文件一致性       | 修改的 JAR、证书、MPLS、CLPI、M2TS 及相应备份没有新旧混用        |

软件端需要使用实际启用了蓝光菜单和 BD-J 支持的播放器环境。[libbluray][libbluray]包含导航、播放列表、菜单和 BD-J 支持，但仅安装这个库并不足以播放所有商业受保护盘片；播放器前端、Java 环境和目标设备也会影响结果。最后仍应在准备使用的硬件上测试，记录播放器版本和固件。

遇到问题时，可以按现象缩小范围：

- **正片能播，IG 呼不出：** 查菜单 Clip 是否存在、MPLS 的 SubPath / STN，以及 IG PID 和调用路径。
- **中文按钮切到错误字幕：** 查当前 MPLS 的流表顺序，再查按钮或 Java 数据里的轨道映射。
- **按钮不可见或无法聚焦：** 查状态资源、按钮组、坐标、邻接 ID 和分页边界。
- **BD-J 黑屏或卡在加载：** 查日志里的类加载、资源、编译版本与签名错误，按日志指出的那一类问题往下查。
- **换片或重开后状态异常：** 查应用身份、选择状态及播放器对该盘的持久化数据；只按播放器提供的方法处理对应盘的测试缓存。
