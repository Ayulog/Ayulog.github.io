一张蓝光原盘里常有多条播放列表，先确认要保留哪个版本，再把其中的音视频、字幕和章节整理成便于播放的 MKV。播放列表、HDR 与章节的基础分别在[蓝光目录与播放列表](/posts/understanding-blu-ray/)、[HDR 与杜比视界](/posts/understanding-hdr/)和[章节的处理](/posts/media-chapters/)，这里的流程从它们接下去。

这里以 **Blu-ray / UHD Blu-ray → MKV** 为主，软件入口集中在[蓝光与媒体工具清单](/posts/media-diy-software/)，音频工具见[音频清单](/posts/audio-software/)。公开资料核对到 **2026 年 10 月 10 日**。

## Remux 要保留原样还是转兼容副本

**Remux 是重新封装，不是重新压制。** 视频从 M2TS 换到 MKV，通常复制已有的压缩码流，不经过解码再编码；但容器、时间戳、轨道排列和部分封装信息会改变，不能期待输出文件与原盘文件的哈希相同。

开始前先区分想留下什么：

| 目标                               | 处理方式                            | 需要知道的边界                    |
| ---------------------------------- | ----------------------------------- | --------------------------------- |
| 保存整张碟的菜单、花絮和多版本结构 | 保存原盘目录或 ISO                  | 单个正片 MKV 不能替代完整原盘     |
| 保存选定版本的原始音视频           | 提取该 MPLS 对应的节目，再封装 MKV  | 检查轨道、章节、HDR/DV 数据与同步 |
| 给设备制作更容易播放的副本         | 按需增加兼容音轨，或转换 DV Profile | 记录具体改动，保留原始版本        |

裁黑边、缩放、降噪、烧录字幕和 HDR 转 SDR 都需要改变画面，已进入压制流程。把 TrueHD 解码成 FLAC 虽可保留相应的 PCM 声音，也不是原始 TrueHD 码流的复制；如果原轨带 Atmos，还涉及对象信息的丢失。

分流步骤以**工具能够正常读取的原盘文件**为前提。实体碟能否读取取决于光驱、固件、读取软件及当前支持情况，MKVToolNix、eac3to、DGDemux 都不负责受保护实体碟的读取，见[蓝光基础说明](/posts/understanding-blu-ray/#光驱能读不等于电影能播)。

## 第一步：确认正确的播放列表

先用 BDInfo 查看 `BDMV/PLAYLIST/*.mpls`，记录准备处理的影片版本。至少核对以下几项：

1. **时长与版本**：正片、导演剪辑版、加长版、不同语言片头或片尾，是否符合预期。
2. **片段顺序**：MPLS 引用哪些 M2TS，是否有多片段、无缝分支或重复片段。
3. **视频**：编码、分辨率、帧率、HDR 格式；DV 盘还要注意 BL 与 EL。
4. **音轨与字幕**：语言、编码、声道、正片音轨、评论音轨及 PGS 字幕。
5. **章节**：数量与时间点是否对应这个版本。

最大的 M2TS、最长的 MPLS、章节最多的列表，都只能提供线索。面对大量时长相近的列表、播放列表混淆或不同剪辑，应结合菜单实际选择的版本与画面顺序确认；拿不准时不要直接批量输出。

**视频、音频、字幕和章节尽量从同一个 MPLS、同一次处理结果取得。** 分别从两个版本取视频和音轨，再靠整体延迟拼起来，可能片头同步、到分支点就失步。

给这次处理保留 BDInfo 报告、工具版本和日志。分流会增加磁盘占用：原盘、临时轨道和最终 MKV 可能同时存在，输出目录应与原盘分开。

## 第二步：选择提取路线

三种路线都可以完成 Remux，不需要让同一份音视频依次经过所有工具。

| 路线                     | 适合什么情况                                 | 后续操作                          |
| ------------------------ | -------------------------------------------- | --------------------------------- |
| MakeMKV 直接输出 MKV     | 希望先完整保留选定节目，减少手工组织文件     | 再用 MKVToolNix 整理轨道和章节    |
| MPLS 直接交给 MKVToolNix | 原盘已能读取，只需选择轨道并封装             | 输出后重点检查时间线与分支点      |
| DGDemux / eac3to 先分流  | 要单独检查音轨、处理字幕，或明确控制 DV 数据 | 把同一时间线的轨道交给 MKVToolNix |

### MakeMKV：先得到一份完整节目

1. 用 MakeMKV 打开来源：可读取的碟片、ISO，或原盘目录中的 `BDMV/index.bdmv`。
2. 展开节目，核对来源播放列表、时长、片段信息和章节数；标题编号只作参考。
3. 勾选要保存的视频、音轨、字幕；检查正片音轨与评论音轨，留意完整无损轨和兼容轨的区别。
4. 使用不做音频转码的设置，选择新的输出目录，生成 MKV。
5. 保存日志，用 MediaInfo 和 MKVToolNix 再读一遍输出；需要改章节名称或轨道信息时，在下一步统一整理。

MakeMKV 的作用是选出节目并保留其内容，不涉及整张碟的交互菜单。它可以保存 UHD 蓝光的 Dolby Vision 数据，输出后仍要检查数据和实际播放结果。

### MKVToolNix：直接读取 MPLS

在 MKVToolNix GUI 的混流器中，按下面的顺序操作：

1. 点击**添加源文件**，或拖入已经确认的 `BDMV/PLAYLIST/00800.mpls`。添加的是播放列表，不是同名或最大的 M2TS。
2. 如果弹出扫描其他播放列表的提示，已确认列表时可以选**不扫描，仅添加此文件**；还需比较候选列表时再扫描。扫描结果只提供候选，剪辑仍需按菜单中的实际选择确认。
3. 在**轨道、章节及标签**列表中，勾选需要的视频、音轨、字幕和章节。逐条核对语言、声道与用途，尤其是配音、评论音轨和不同中文字幕。
4. 选中一条轨道后，在右侧填写语言、轨道名称、默认及强制标记。默认字幕按自己的播放需要选择；语言显示为 `und` 时应核实内容再填写。
5. 在**输出**中检查文件标题、章节与切割设置，选择原盘目录之外的新输出文件。单部电影通常保持不切割，然后点击**开始混流**。

进度到 100% 后还要读任务的警告和错误。分支接缝、字幕同步与章节跳转留到成品检查时逐项确认。

命令行先检查识别结果，再输出：

```sh
mkvmerge -J "disc/BDMV/PLAYLIST/00800.mpls"
mkvmerge -o "movie.remux.mkv" "disc/BDMV/PLAYLIST/00800.mpls"
```

`00800.mpls` 是示例名称，必须换成实际确认的列表。第二条命令是保留默认读入内容的最小示例，实际需要哪些音轨、字幕和章节，仍应在 GUI 或参数中明确选择。

当前版本能处理受支持来源中的蓝光双轨 DV；GUI 只显示一条视频轨时，工具已经把相应 BL/EL 合到同一轨道中，具体检查方法见后面的 DV 部分。

不要把数个 M2TS 随意拖入后按文件名追加，替代 MPLS 的片段顺序与入出点。某张盘出现连接处不同步或工具警告时，保留日志，改用下面的分流路线交叉检查。

### DGDemux：按播放列表分流

[DGDemux][dgdemux]针对 Blu-ray / UHD 的轨道提取，无缝分支处理是它的主要用途之一。Windows 提供 DGDemuxGUI，当前 Linux 发行包也包含 GUI 与命令行程序；操作前确认下载包对应平台，并读随包的使用说明。

以下选项按 Windows 1.0.0.86 随包的 `DGDemux.txt` 核对。在 DGDemuxGUI 中，按以下顺序处理：

1. 在 **Disk / Browse** 中选择原盘根目录或 `BDMV`，从扫描结果选择正确 MPLS；不要把目录选到更深的 `STREAM`。核对节目时长、片段和轨道。
2. 先用 **Analyze** 查看各片段入出点、视频时间戳与连接关系，留意节目窗口之外的额外内容或疑似截断。多版本、多角度也先明确时间线。
3. 选择要导出的视频、音频、PGS 与 **Chapters**，设置 **Output folder** 与 **Output name**。要保留完整 DTS-HD，就不要选择只提取 DTS core。
4. DV 输入若需要合并输出，BL 与 EL 都要选中；当前 Windows 版提供 P7 合并及 P8.1 合并选项，具体数据取舍见下文。
5. 点击 **Demux**，保存日志，检查读盘错误、帧数与音频处理结果；正常流程保留默认的间隙修正，不启用供研究或调试使用的 `-nogaps`。

**DGDemux 的默认输出不按 MPLS 入出点裁剪。** 它默认提取所引用 M2TS 的完整内容；需要严格遵守 MPLS 节目窗口时，使用对应的 `-strictpl` 选项，并按 Analyze 结果和目标版本判断是否启用，输出后再核对时长、章节与接缝。

命令行先列轨，再按实际 PID 分流。例如，只有在列轨结果确认 `4113`、`4352` 是所需视频和音频 PID 时，才可使用第二条：

```sh
DGDemux -i "disc/BDMV/PLAYLIST/00800.mpls"
DGDemux -i "disc/BDMV/PLAYLIST/00800.mpls" -o "work/movie" -demux 4113,4352,Chapters
```

先建立 `work` 目录；`-o` 后是**不含扩展名的输出前缀**，不是仅指定文件夹。PID 也不是 eac3to 或 mkvmerge 的轨道编号。这个最小示例未选择 DV 的 EL；需要 DV 时应同时选择实际 BL/EL，再按下面的合并选项处理。

DGDemux 的使用说明将同次提取的音轨描述为已与分流视频同步。因此，**不要把源盘显示的延迟值再机械地应用到这批输出**；若实播仍有问题，先回查列表、日志和具体接缝。

TrueHD 的默认输出可以同时包含 `.thd`、伴随 `.ac3` 与组合形式；只需独立 TrueHD 时，当前命令行支持 `-thd 2`。封装 MKV 时选需要的 `.thd`，再按设备需求决定是否保留单独 AC-3，不要把几种表示同一节目音频的输出全当成不同音轨重复加入。

当前 Windows 1.0.0.86 的 DV 选项对应命令行 `-mergedv`（合并并保留 P7）与 `-mergedv81`（转为 P8.1）。两者都需要同时选择 BL/EL，并在工具目录准备 `dovi_tool`。Linux 与不同版本的选项应以对应包内文档为准。

如果来源同时含 HDR10+，还应留意 `-dvstrip` 会移除 HDR10+ 数据，不要把它当作保留 DV 的必选参数。确认成品前也先保留分流中间文件。

分流结束后，音视频、章节和日志一起保留，音频的处理记录和章节来源也留在同一目录。DV 输入要确认输出是已经合并的 BL+EL 码流，还是分开的两份文件；两种情况分别处理。

### eac3to 与 UsEac3To：分析与音轨分流

eac3to 既能分析来源，也能分流和转换音频。**输出扩展名与参数决定它是在复制、解码还是重新编码**，使用前先看识别结果，确认当前这一步属于哪一种。

下面假设已下载 eac3to，并能在终端中调用它。加入 PATH 是一种方式；也可以在工具目录打开 PowerShell，把命令开头写成 `.\eac3to.exe`。`disc` 和 `work` 是示例目录，分别代表可读取的原盘和预先建立的输出目录。

#### 扫描原盘，再查看选定列表

还不知道列表编号时，先扫描原盘目录：

```sh
eac3to "disc"
```

输出可能列出 `1)`、`2)` 等节目序号，以及对应 MPLS、时长和章节数。这个序号只属于本次扫描结果；它既不是 MPLS 文件名，也不是音轨编号。按前面的选片方法确认版本，不要直接选第一个或最长的一项。

假设本次确认需要的是 `1)`，可以继续查看：

```sh
eac3to "disc" "1)"
```

把 `1)` 放进引号，可避免 PowerShell 将右括号当作语法解析。已经知道正确 MPLS 时，也可以直接列出它的内容：

```sh
eac3to "disc/BDMV/PLAYLIST/00800.mpls"
```

**原盘目录加节目序号、直接指定 MPLS，是两种输入方式。** 直接写 MPLS 时无需再附加 `1)`。随后列出的 `1:`、`2:`、`3:` 等才是本次可选择的章节或轨道编号，不能照抄 MediaInfo 的流编号，也不能直接当作 mkvmerge 的 Track ID。

#### 批量分流所选节目

需要把所选节目拆成独立素材时，可使用带 `.*` 的输出名称：

```sh
eac3to "disc/BDMV/PLAYLIST/00800.mpls" "work/movie.*" -keepDialnorm
```

`movie` 是输出文件名前缀，`.*` 让 eac3to 按轨道格式生成独立文件；不要把这里的星号改成一个固定的音频扩展名。4.00 随包说明指出，批量分流默认跳过隐藏轨道，通配输出只覆盖非隐藏轨道。章节若存在，也应检查是否一并输出。运行结束后逐项核对文件、格式和日志。

这一步是 Demux，不会生成最终 MKV，也不需要先压制视频。分流结果中若有 LPCM，按下文改用工具支持的 WAV/W64 等表示。DV 来源则继续核对 BL、EL 与 RPU 的去向，导出全部文件后仍要确认成品里有完整的 DV 视频轨。

#### 只提取需要的素材

例如，**仅当本次列表确认 3 号是需要的 TrueHD 音轨**时，先建立 `work` 输出目录，再提取：

```sh
eac3to "disc/BDMV/PLAYLIST/00800.mpls" 3: "work/audio.thd" -keepDialnorm
```

如果确认 4 号才是需要的完整 DTS-HD 音轨，则可以用：

```sh
eac3to "disc/BDMV/PLAYLIST/00800.mpls" 4: "work/audio.dtshd" -keepDialnorm
```

两条命令是不同来源条件下的例子，不是要求每部片都执行两遍。`-keepDialnorm` 用于保留原有的 dialogue normalization 信息；需要完整 DTS-HD 时不加 `-core`。换成 `.wav`、`.flac` 等输出就进入解码或转换流程，不能期待 Atmos、DTS:X 对象信息自动跟着 PCM 保存。

如果本次编号 `8` 对应需要的 PGS 字幕，则单独提取为 SUP：

```sh
eac3to "disc/BDMV/PLAYLIST/00800.mpls" 8: "work/eng.sup"
```

只有要另做兼容音轨、且本次编号 `4` 确实是含 DTS core 的 DTS-HD 音轨时，才加 `-core`：

```sh
eac3to "disc/BDMV/PLAYLIST/00800.mpls" 4: "work/eng.core.dts" -core -keepDialnorm
```

这得到的是有损 DTS 核心，不是完整 DTS-HD MA / DTS:X。它应作为明确选择的兼容副本，不能悄悄替换前面的完整音轨。

#### 用 UsEac3To 操作

[UsEac3To][useac3to]是 eac3to 的图形前端。先核对它调用的 eac3to 位置，再打开或拖入原盘目录、MPLS；用原盘目录输入时，还要在 **Feature** 中确认节目。轨道区显示的播放列表、时长和语言都核对后，再设置 **Settings → Output Folder**，使用 **User defined** 输出到独立目录。

根据需要选择一种运行方式，按钮名称可能随前端版本略有变化：

| 需要做什么          | 操作                                                                                                                     | 输出后接着做什么                              |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------- |
| 批量分流所选节目    | 在 **Global parameters** 选择 `demux`，点击旁边的 **RUN**                                                                | 核对导出的轨道、章节与日志，再交给 MKVToolNix |
| 只提取若干素材      | 在 **Track Input** 选轨，在 **Output format** 选格式，逐项点击 **Add**；检查下方命令后点击 **RUN CL / RUN Command Line** | 核对每条输出及仍需处理的延迟                  |
| 分流后调用 mkvmerge | 先在 **Settings → Path to MkvMerge** 指向 `mkvmerge.exe`，逐项 **Add** 后点击 **Run and MkvMux**                         | 回读生成的 MKV，继续检查语言、默认标记与章节  |

**TrueHD 输入要把输出手工改成 `thd`，前端默认的 `ac3` 不适用于这类轨道。** 同样，选 FLAC/WAV 就是解码转换；在常用参数中加入 `core` 就是在提取核心。下方生成的命令是复核这些选择的地方，运行前检查轨道编号、输出扩展名和参数作用的对象。

`Run and MkvMux` 调用的是另行配置的 mkvmerge。最终封装使用 MKVToolNix，不采用依赖旧 Haali 组件的 eac3to 直接写 MKV 路线；没有必要为了这套流程再安装 Haali。

UsEac3To 1.4.0 的更新针对 eac3to 4.01，使用测试版或其他配套版本时按作者说明核对兼容性。

当前 eac3to 的能力已经和十多年前不同。[发布记录][eac3to-release]显示，3.60 已加入使用 DGDemux 算法的 TrueHD gaps correction；3.66 又增加 `-strictpl` 和 `-auditpl`。前者让提取严格遵守 MPLS 各片段入出点，后者只分析播放列表、不做分流。两者解决的问题不同，按需要逐个启用并查看日志。

4.00 对 E-AC-3 7.1 / JOC 的解码支持也有更新；解码得到的是声道声音，Atmos 对象元数据需要原样保留。

遇到版本不匹配、某种音频解码器不可用或运行警告，应先核对 eac3to 与前端的当前说明。原样分流与解码转换所需组件不同，不必为了复制轨道就安装旧教程列出的所有外部解码器。

## 音轨、字幕和延迟怎么处理

### 音频先保留来源编码

通常先保存需要的原始音轨，再考虑是否增加兼容副本：

| 来源音轨                    | 以保留为目标时                                                   | 不应混淆的处理                                                   |
| --------------------------- | ---------------------------------------------------------------- | ---------------------------------------------------------------- |
| Dolby TrueHD / TrueHD Atmos | 保存完整 TrueHD 码流                                             | 转 PCM、FLAC 或普通 AC-3 不会保留原有 Atmos 对象信息             |
| DTS-HD MA / DTS:X           | 保存完整 DTS-HD 码流                                             | 只抽 DTS core 会丢高清扩展，不能当作完整 DTS:X 保留              |
| LPCM                        | 保留 PCM 音频，手工分流可使用工具支持的 WAV/W64；也可按需转 FLAC | 无头 `.pcm` 不能假定可直接导入；转 FLAC 需核对位深、声道与采样率 |
| AC-3、DTS、E-AC-3           | 有需求就保留原轨                                                 | 有损转有损不会提升原始音质                                       |

TrueHD 在蓝光中可伴随 AC-3 兼容音频，但它不是 DTS-HD 那种同一意义上的 DTS core。是否另留 AC-3 取决于播放设备与使用需要，不存在 Remux 必须统一删除兼容音轨的规则。

同样，不需要按声道数给音轨排质量名次。原始单声道、立体声、后来重混的多声道可能各有保留价值，`7.1` 只是声道数更大。

### 延迟只按实际时间线处理一次

工具日志中的 `delay`、`gap`、音频补齐或裁切要先分清属于哪一种，再决定是否手工输入：

- **容器中的起始时间差**：工具可能在重新封装时已经按时间戳处理。
- **分流后仍需补偿的固定延迟**：根据输出和日志，在混流时设置一次。
- **无缝分支连接处的音频帧处理**：它可能发生在多个接缝，不能用全片一个毫秒数解决。

在 MKVToolNix 中，正延迟让该轨更晚播放，负延迟让它提前。只有核实仍需要调整时才填写，已经修正过的内容不再重复填写。

如果片头对得上，越到后面偏差越大，先核对帧率、播放速度和版本；如果到某一片段突然偏移，先检查分支接缝。不要靠不断试延迟掩盖来源不一致。

### PGS、完整字幕与强制字幕

PGS 是图形字幕，提取为 `.sup` 后可直接封装进 MKV，不需要为了 Remux 先 OCR 成 SRT。若设备不能直接显示 PGS，那是播放兼容性需求，可另外准备文本字幕。

完整字幕、只翻译外语对白或画面文字的字幕、听障字幕、评论字幕，应按内容区分。**PGS 内部部分字幕事件的 forced 标记，与 MKV 整条轨道的“强制显示”标记不同。** 给一整条完整字幕设为强制，并不会自动筛出其中需要强制显示的几句。

设语言、默认轨和强制标记前，实际查看字幕内容。默认标记只是播放器选轨的依据之一，播放器的语言偏好和用户设置也会参与选择。

## 第三步：处理 Dolby Vision

### BL、EL、RPU 与三种保存目标

UHD 蓝光常见的 Dolby Vision Profile 7 包含 **BL（基础层）、EL（增强层）和 RPU（动态元数据）**。BL 通常提供 HDR10 兼容基础；FEL 与 MEL 的差别、Profile 的含义见[HDR 说明](/posts/understanding-hdr/#杜比视界的-profileblel-与-rpu)。

这里最容易混淆的是“轨道数”和“层数”：原盘中的 BL、EL 可以来自两个流，封装后可以合在 MKV 的**同一条视频轨**里。因此一条轨道也可能保存 BL+EL+RPU，判断 Profile 要看轨内实际数据而不是轨道数量。

| 目标                    | 预期保留的数据               | 对原盘数据的影响                         |
| ----------------------- | ---------------------------- | ---------------------------------------- |
| 保留 Profile 7          | BL + EL + RPU                | 保留增强层，仍需播放器支持对应的数据处理 |
| 转 Profile 8.1 兼容副本 | HDR10 兼容 BL + 转换后的 RPU | 丢弃 EL；FEL 的增强图像信息不再保留      |
| 只留 HDR10              | HDR10 兼容 BL 及其 HDR 信息  | 去掉 DV 数据，不再是 DV 成品             |

保留 Profile 7 与“电视亮 DV 标志”不是一回事。部分播放链路只使用 BL+RPU，或回退到 HDR10；有 DV 标志时还要确认 FEL 的实际去向。

### 路线一：保留原盘 Profile 7

如果 MakeMKV 已输出包含 BL+EL+RPU 的 MKV，或者 MKVToolNix 已从原盘正确合并 DV，直接保留该视频轨继续封装即可。不必为了使用 dovi_tool 而额外提取、转换再注入一遍。

对于 DGDemux 等工具的分流结果，先看文件组织：已合并的 P7 HEVC 可以直接交给当前 MKVToolNix；若是分离的 BL 与 EL，需要先正确合并，不能在混流器里简单添加成两条可切换的视频轨。

用 [dovi_tool 2.3.4][dovi]合并分离文件的示例：

```sh
dovi_tool mux --bl "BL.hevc" --el "EL.hevc" -o "BL_EL_RPU.hevc"
```

这里的 `EL.hevc` 应包含原盘 EL 与 RPU；两份文件必须来自同一播放列表、同一剪辑和时间线。保留 P7 时不加转换模式 `-m`，也不加丢弃增强层的 `--discard`。如果工具报告两层帧数不匹配，先查源文件和分流过程，不要强行跳过后就宣称完整。

### 路线二：制作 Profile 8.1 兼容副本

只有当目标播放链路需要这种形式时，再做 P7 → P8.1。它可以不重新编码 BL，但**丢弃 EL 属于数据删减**，FEL 的增强图像信息不再保留。

如果手里已有合并后的 `BL_EL_RPU.hevc`，直接进入转换。若来源是 P7 MKV，则先确定视频 Track ID，再提取完整视频流：

```sh
mkvmerge -J "movie.p7.mkv"
mkvextract "movie.p7.mkv" tracks 0:"BL_EL_RPU.hevc"
```

第二条假设刚才确认的视频 ID 为 `0`；实际不同就替换该编号。这一步要提取完整视频流，只取 RPU 不够。

制作另一个 P8.1 文件：

```sh
dovi_tool -m 2 convert --discard "BL_EL_RPU.hevc" -o "BL_RPU_P81.hevc"
```

在当前版本中，`-m 2` 将 RPU 转为 P8.1 兼容形式，并移除 P7 FEL 的 luma/chroma mapping；`--discard` 丢弃 EL 视频数据。不要机械套用旧教程里的 `-m 5`，当前文档将它定义为保留 mapping 的旧 mode 2，含义不同。

如果是从原 P7 MKV 转换，可把新视频与原文件中的音轨、字幕和章节重新组合。下面的示例用于**未经裁切、视频起点正常的恒定帧率蓝光来源**；裸 HEVC 不携带原 MKV 的逐帧时间戳和轨道设置，存在起点偏移或特殊时间线的输入不能直接套用。

```sh
mkvmerge -o "movie.p81.mkv" "BL_RPU_P81.hevc" --no-video "movie.p7.mkv"
```

`--no-video` 只排除随后这个原 MKV 的旧视频，避免一份文件里同时出现新旧两条视频轨。回读输出时，还要检查新视频的帧率、时长与轨道信息；音视频时间线必须与转换前一致。

这里使用先提取 HEVC 再转换的流程。[2.3.4 更新记录][dovi-release]新增了 `convert` 等命令直接读 MKV 的实验支持，不必为了减少中间文件就忽略其当前边界。

FEL 的作用也不只是“多几个位深数字”。[Dolby 的 UHD 蓝光制作指南][dolby-authoring]说明，它可以参与残差重建与亮度信号的恢复；因此“电视只有 10bit，所以 FEL 可以无条件丢掉”不是可靠的判断依据。

### 不把不同片源的 RPU 直接套用

RPU 与对应视频帧关联。片名相同、分辨率相同或时长接近，都不足以证明帧序、剪辑、画幅和调色一致。不同发行版、流媒体版本与蓝光之间的 RPU 移植属于单独一项工作，不在普通 Remux 流程里。

同样，Profile 5 不是 HDR10 兼容基础层，P7 → P8.1 的处理方法不适用于它；把 SDR、HDR10 或 HDR10+ 自动“做成 DV”属于另行生成一份 DV，发行方原始的 Dolby Vision 并未因此恢复。

## 第四步：用 MKVToolNix 整理成品

无论前面选哪条路线，最后都回到同一条影片时间线：视频、音轨、字幕、章节相互对应。

### 整理轨道与输出设置

在 MKVToolNix GUI 的混流器中：

1. 添加中间 MKV，或同一次分流得到的轨道。独立视频、音频和字幕使用“添加”；“追加”是把内容接到前一段后面，不是加入另一条音轨。
2. 勾选要保留的轨道，检查语言与名称。轨道名写明原音、配音、评论或字幕用途，比只写编码名更容易选择。
3. 按实际需要设置默认音轨、默认字幕与强制字幕，不把所有轨道都设为默认或强制。
4. 原样保留原章节时，使用对应来源的章节；导入编辑后的 XML/TXT 时，禁用旧章节，避免出现重复 Edition。具体操作见[章节教程](/posts/media-chapters/#第四步写入-mkv-或蓝光结构)。
5. 裸视频通常没有容器时间戳，应核对工具识别出的帧率；不要不看来源就强制填 `23.976` 或 `24`。只在确有依据时修正。
6. 输出到新文件，查看混流日志，再进行回读和播放检查。

### 从 MPLS 单独导出章节

直接读取 MPLS 时，MKVToolNix 可以带入其中的章节；只想保留这些时间点，无需再导出一份 XML 重复添加。需要备份、改名或检查章节时，再单独处理：

1. 打开 MKVToolNix GUI 的**章节编辑器**，载入与当前音视频对应的 `.mpls`。
2. 核对章节数量、时间点与影片版本。如需统一编号名称，可以使用 `Chapter <NUM:2>` 这类模板，生成 `Chapter 01`、`Chapter 02`；这是命名偏好，不需要把整个软件界面改成英文，也不要因此覆盖已有的正式章节名。
3. 检查或编辑完成后，选择**保存为 XML 文件**。这一步只输出章节信息，不会提取音视频。
4. 回到混流器，在**输出 → 章节 → 章节文件**中载入保存的 XML。同时取消复制输入文件原有的章节，避免两套章节一起进入成品。

如果章节来自另一个剪辑版本，不能靠改名使它匹配当前影片。章节编辑与时间调整的完整过程见[章节教程](/posts/media-chapters/)；这里保留与 Remux 衔接所需的步骤。

### 用命令行封装与设置延迟

用独立轨道封装时，最小示例可以是：

```sh
mkvmerge -o "movie.remux.mkv" "video.hevc" "audio.thd" "subtitle.sup" --chapters "chapters.xml"
```

这条命令只演示文件如何组合，语言、默认轨和延迟仍要另外设置。`video.hevc` 应是已经整理好的完整视频流；DV 双层来源需要连同 EL/RPU 一起处理。

检查输入中的 Track ID：

```sh
mkvmerge -J "audio.thd"
```

只有当结果确认需要调整的音轨 ID 是 `0`，且仍需要向后延迟 80 ms 时，才可写成：

```sh
mkvmerge -o "movie.remux.mkv" "video.hevc" --language 0:en --sync 0:80 "audio.thd" "subtitle.sup" --chapters "chapters.xml"
```

`--language`、`--sync` 放在它们作用的输入文件前；这里的 `0` 属于随后那个输入文件。不同工具、不同输入文件的编号不能互换，见 [mkvmerge 的选项与 Track ID 说明][mkvmerge]。

修改轨道名称、默认标记和章节不需要重新压制。需要补字幕、字体附件或不同来源音轨时，也要先确认来源与时间线；重新封装不会自动完成同步。

### 文件名与导入问题

MKVToolNix 支持 Unicode 文件名，中文、空格和连字符本身不是禁止项，不必把成品改成单个英文单词。命令行里的文件路径用引号括起来；旧版 eac3to、前端或外部组件若遇到路径问题，可以临时用短的英文工作目录排查，但不要把这种排错办法当作格式要求。

拖放没有反应时，先用**添加源文件 / 打开文件**按钮选择同一个文件，确认路径可读、工具版本与程序权限。混流报错则先读日志：缺少 MPLS 引用的片段、来源不能读取、格式不受支持或时间戳异常，需要分别处理；切换到 eac3to / DGDemux 分流可以交叉检查，但不能保证修复损坏来源。

## 单个 MPLS 包含多集时怎么切分

有些剧集把多集连续放在同一播放列表里。如果原盘已有各集独立且完整的 MPLS，优先按集选择；只有确认多集共用一个列表时，再考虑按章节切分。

先播放并记录每集真正的起点，按实际起点分章。假设核对后得到以下四集与章节的对应关系：

| 集数    | 在完整列表中的章节范围 | 对应起始章节 |
| ------- | ---------------------- | ------------ |
| 第 1 集 | 1–4                    | 1            |
| 第 2 集 | 5–8                    | 5            |
| 第 3 集 | 9–12                   | 9            |
| 第 4 集 | 13–16                  | 13           |

在 MKVToolNix GUI 中添加这个 MPLS，并完成轨道选择；进入**输出 → 切割**，模式选**在章节之前**，章节编号填写：

```text
5,9,13
```

这里填的是第二集及以后各集的起始章节，用英文逗号分隔；第一集已经从文件开头开始，不需要再填 `1`。保持**最大文件数**不限制，不勾选**链接文件**，选择新的输出文件名后开始混流，预期得到四个独立 MKV。

命令行对应写法如下；轨道选择仍需按实际需要补充：

```sh
mkvmerge -o "episode.mkv" --split chapters:5,9,13 "disc/BDMV/PLAYLIST/00800.mpls"
```

未自定义编号模板时，输出会命名为 `episode-001.mkv`、`episode-002.mkv` 等。也可以先完整封装并检查，再把命令末尾的 MPLS 换成那份 MKV，使用同样的章节切分方式。

这一功能有两个会影响结果的边界，见 [mkvmerge 的切割说明][mkv-split]：

- **切点受关键帧限制。** 实际会在章节起始时间或其后的第一个关键帧前切开，不保证任意章节时间都能逐帧精确切割。片头片尾可能落到相邻文件里，应连续播放每个切点前后检查；需要任意位置的精确切割时，单纯 Remux 未必能满足。
- **编号按所有 Edition 的顶层章节计算。** 它不是显示名称里的数字，也不包含任意嵌套的子章节。普通单 Edition、单层章节可以照上例理解；复杂章节结构应先核对、整理实际参与计数的列表。

输出后逐集检查开头、结尾、字幕、音画同步和章节跳转，并按每个文件的新起点核对章节时间。不要把整季原有的 XML 不经调整重复写入每一集；也不要假设所有盘都恰好每集四章。

## 第五步：检查文件与实际播放

先回读成品，再用实际设备播放。MediaInfo 的标签、工具日志和实际播放各能证明一部分，不能互相替代。

| 检查项       | 看什么                                                                   |
| ------------ | ------------------------------------------------------------------------ |
| 版本与时间线 | 时长、片段顺序、片头片尾，是否是预期剪辑                                 |
| 视频         | 编码、分辨率、帧率、位深、色彩信息，HDR10 / HDR10+ / DV 是否符合保存目标 |
| 音频         | 编码、语言、声道、采样率；需要保留的 Atmos / DTS:X 是否仍在              |
| 字幕         | 语言、内容、默认与强制行为，开头中段结尾是否同步                         |
| 章节         | 数量、名称、时间与跳转；是否重复或来自另一版本                           |
| 分支接缝     | 在连接前后连续播放，检查音频中断、重复、缺字或突发不同步                 |
| 播放设备     | 实际容器、DV Profile、音频直通与字幕组合是否支持                         |

DV 成品先查看 MediaInfo 中报告的 Profile 和 `BL+EL+RPU` / `BL+RPU` 等信息，再按需要提取码流检查 RPU。Profile 7 保存目标若只剩 BL 或 BL+RPU，就需要回查提取与混流步骤；Profile 8.1 则不能期待还保留 EL。

dovi_tool 可以直接从成品 MKV 提取 RPU，再查看汇总：

```sh
dovi_tool extract-rpu "movie.remux.mkv" -o "RPU.bin"
dovi_tool info -i "RPU.bin" --summary
```

汇总中的 Profile、FEL/MEL 与 RPU 帧数可以辅助核对。例如 P7 来源可能显示 `Profile: 7 (FEL)`，P8.1 转换后的 RPU 汇总显示 Profile 8；`.1` 的 HDR10 兼容关系还要结合视频与封装信息判断。**RPU 汇总只描述 RPU 自身**，EL 是否存在、帧数是否对得上，要与 MediaInfo、视频帧数和完整处理日志一起看。

数据层面通过后，仍需在目标设备上看实际 HDR/DV 模式、画面、章节跳转和音频输出。电视触发 DV、功放显示 Atmos、文件时长相同，各自只说明对应的一项，完整性按前面的检查一起看。

如果怀疑视频被重新编码，可在受控流程中比较对应的压缩视频数据；不同工具会重排或重写部分码流封装，整文件或提取流的哈希不同也可能只是封装差异。对普通整理，保留来源记录、参数和日志，再核对格式与实际播放更有用。

确认成品之前，保留原盘、分流日志和必要的中间文件。若制作了 P8.1、兼容音轨或字幕转换版，在自己的记录中标明改动，便于以后重新处理。

字幕的获取与制作见[字幕的处理](/posts/subtitle-workflow/)，从原盘或公网获取字幕，串起 OCR、校对、翻译、ASS 特效制作，以及重新生成 SUP 的流程。
