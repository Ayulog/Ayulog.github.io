第一次配置 OpenWrt，可以先把它接成二级路由：保留原主路由，只接一台测试设备。改错网关或 DNS 时，影响也只在测试网络内。

系统、插件和资料入口见 [软路由总篇](/posts/2026-10-10-soft-router-software/)。iStoreOS 的网络向导、iStore 插件和绿联 NAS 虚拟机部署另见 [iStoreOS：安装、配网与插件笔记](/posts/2026-10-10-istoreos-guide/)。

下面从固件和备份讲起，再配置 LAN、WAN、Wi-Fi 和插件。刷机步骤因型号而异，必须按设备文档操作；这里的配网示例要求固件已运行，并有独立的 WAN、LAN 接口。未针对具体机型做刷机测试。

## 第一步：弄清楚要折腾什么

### OpenWrt、LuCI、iStoreOS、iStore 分别是什么

- **OpenWrt**：面向路由器等设备的 Linux 系统，可以配置路由、防火墙、无线和软件包。
- **LuCI**：OpenWrt 常见的网页管理界面；教程里的“网络 → 接口”等操作通常在这里完成。
- **iStoreOS**：基于 OpenWrt 的系统，提供网络向导等功能，具体设置见 [iStoreOS 篇](/posts/2026-10-10-istoreos-guide/)。
- **iStore**：软件中心。安装了它不代表底层固件变成 iStoreOS，插件仍要核对适用版本。

原厂固件如果已经满足需求，也可以先做地址规划、调整无线、增加 AP。刷机主要是为了获得需要的功能，实际无线表现还取决于驱动、硬件和环境。

### 主路由、二级路由、AP 和旁路由

| 角色     | 主要工作                                   | 初学时需要理解的地方                  |
| -------- | ------------------------------------------ | ------------------------------------- |
| 主路由   | 连接上游网络，为家中设备提供路由和地址分配 | 修改它会影响使用它上网的设备          |
| 二级路由 | WAN 接已有主路由，LAN 建立另一个网段       | 容易单独测试，IPv4 通常会形成双重 NAT |
| AP       | 扩展无线接入，让设备进入原有局域网         | 通常不再单独承担 NAT 和地址分配       |
| 旁路由   | 按设计为部分设备处理路由、DNS 等服务       | 接上网线不会自动接管全家流量          |

“软路由”通常是使用通用硬件运行路由系统的设备；它是否带有可用的无线 AP 功能，要看网卡和驱动。多网口小主机配独立 AP，也是常见组合。

本文先走二级路由这条路。单网口设备不直接套用下面的接线流程，可以先按对应文档配置为普通主机或旁路由；VLAN 单线复用留到熟悉网络之后再研究。

## 第二步：确认设备与固件

### 先记下这几项

1. 完整型号与硬件版本，查看机身标签和管理页面，不只看商品名称。
2. 当前固件名称、版本，以及准备安装的目标系统。
3. 内存、闪存或磁盘容量，网口数量，以及无线是否受目标系统支持。
4. 设备文档要求的安装入口和恢复方式。

选择设备时，先看是否有清楚的安装与恢复文档，再看性能。小闪存路由器可以做基础网络功能，下载、媒体服务和容器则会增加存储与内存需求，通常更适合放在 NAS 或独立主机上。

### 固件名称相似，用途可能完全不同

| 常见标记           | 通常用途                               | 需要核对                               |
| ------------------ | -------------------------------------- | -------------------------------------- |
| `factory`          | 某些设备从原厂系统首次安装             | 原厂升级页面是否接受、是否有前置步骤   |
| `sysupgrade`       | 某些已运行 OpenWrt 的设备升级          | 目标型号、分区布局及升级兼容性         |
| `initramfs`        | 某些设备临时启动或安装过程中的中间步骤 | 是否仅在内存运行、后续如何正式安装     |
| `.img` / `.img.gz` | 某些 x86、开发板的磁盘或存储介质镜像   | 目标磁盘、启动方式、写入工具与分区影响 |

这些只是常见命名。**最终以设备文档为准，不能靠文件后缀判断刷法。** x86 还要核对 UEFI / Legacy 启动方式；写入整盘镜像会影响目标盘原有数据，操作前确认磁盘身份。

从官方或可信维护者的发布页取得镜像，并对照同一发布渠道提供的校验值。Windows 可以使用：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath ".\firmware.bin"
```

把 `firmware.bin` 换成实际文件名，对比计算结果与发布值。哈希一致可以帮助确认文件完整性，下载来源本身仍然需要可信。

如果页面明确提示设备不匹配、镜像不支持或校验失败，就停下来重新核对。不要用强制刷写选项绕过提示，也不要把别人的整套闪存备份写进自己的设备。

## 第三步：备份并准备恢复方案

刷机前，至少把下面这些资料留在电脑上：

- 当前管理地址、WAN 接入方式，以及有需要时的宽带拨号信息。
- Wi-Fi 名称、地址规划、静态租约、端口转发等设置。
- IPTV、电话或运营商专用 VLAN 的配置记录。
- 当前可用固件、目标固件、对应安装说明和恢复说明。
- 系统提供的配置备份，以及插件单独导出的配置或数据。

备份可能包含 Wi-Fi 密码、拨号密码和密钥，保存在自己的备份位置，排错发帖时也先检查截图和日志。

### 已经使用 OpenWrt，可以导出配置备份

LuCI 通常提供 **系统 → 备份 / 升级 → 生成备份**。下载后，在电脑上确认压缩包能打开，里面包含预期的配置文件。

熟悉 SSH 的话，也可以在路由器上先查看备份清单，再生成备份：

```sh
sysupgrade -l
sysupgrade -b /tmp/router-config-backup.tar.gz
```

这里的 `-b` 是创建配置备份，不会刷写固件。随后用文件传输工具将备份复制到电脑；`/tmp` 通常是临时存储，重启后文件会消失。

**配置备份不是整机镜像**，通常不能完整保存固件、已安装软件及所有插件数据。设备校准分区、引导程序、容器数据和外接磁盘也不等于已经备份；是否需要单独处理，按机型和应用文档确认。

从原厂系统迁移、跨分支或跨大版本升级时，不要默认旧配置可以直接恢复。设备文档要求全新配置时，保留旧设置作为手工重建的参考。

### 先知道如何回去，再开始写入

把恢复文档离线保存，确认需要哪个网口、电脑如何设静态 IP、使用什么镜像。有些设备支持恢复网页，有些需要 TFTP 或其他方式，Reset 按多久也不是通用规则。

首次写入固件时使用稳定供电和有线连接，按对应文档等待安装完成。完成后先确认可以登录和联网，再安装额外插件。

## 第四步：搭建二级路由测试环境

下面假设家里的主路由已经正常联网，它的 LAN 地址是 `192.168.1.1/24`。实验路由使用另一个 LAN 网段 `192.168.50.0/24`。

这些地址都是示例。如果上游或现有 VPN 已经使用这个网段，请选一个不重叠的私有网段，并同步调整文中的地址。

```text
互联网 / 光猫
      │
现有主路由：192.168.1.1
      ├── 原来的手机、电脑、NAS
      │
      └── LAN → 实验路由 WAN：自动获取 192.168.1.x
                     │
                实验路由 LAN：ROUTER_IP
                     │
                测试电脑 / 测试 Wi-Fi
                地址：192.168.50.x
```

先让主路由保持原来的工作方式。实验路由 WAN 获取上游地址，LAN 为测试设备分配地址；这是两个不同网段，各自运行 DHCP 服务是正常的。

这个结构便于撤回改动，但不是严格的安全隔离：测试设备通常仍能主动访问上游局域网。两层 IPv4 NAT 也可能影响入站连接、端口转发和部分游戏。上图只描述 IPv4，IPv6 的前缀、RA 和防火墙要另外核对。

### 1. 先单独连接实验路由

先不连接上游，只将电脑接到实验路由的 LAN 口，电脑使用自动获取 IP。暂时断开电脑连接主路由的 Wi-Fi，减少多条连接造成的判断混乱。

按设备文档找到初始管理地址。不要默认所有固件都是 `192.168.1.1`，也不要默认所有软路由的第一个物理口都是 WAN。

首次登录后设置自己的管理员密码，并检查时区、系统时间。时间明显错误会影响 HTTPS 和软件下载。

### 2. 修改实验路由的 LAN

LuCI 通常在 **网络 → 接口 → LAN → 编辑** 中设置：

| 项目                 | 本例设置                      |
| -------------------- | ----------------------------- |
| 协议                 | 静态地址                      |
| IPv4 地址            | `ROUTER_IP`                   |
| 子网掩码             | `255.255.255.0`，即 `/24`     |
| LAN 的 IPv4 网关     | 本例留空，默认路由由 WAN 获取 |
| LAN DHCP 服务        | 启用                          |
| DHCP 起始值          | `100`                         |
| DHCP 地址数量 / 限制 | `100`                         |

在常见 LuCI 界面中，起始值 `100`、数量 `100` 对应 `192.168.50.100` 到 `192.168.50.199`。如果界面显示的是“结束地址”，则直接按地址填写，别把数量当成结束值。

保存应用后，电脑仍可能保留旧租约。重新连接网线，让电脑获取新地址，再打开 `http://ROUTER_IP`；若固件启用了 HTTPS，则按实际协议访问。页面带有应用确认或回滚倒计时时，按提示完成确认。

### 3. 接入主路由并设置 WAN

确认新管理地址可访问后，再接：

```text
现有主路由 LAN → 实验路由 WAN
```

在 **网络 → 接口 → WAN** 中选择 **DHCP 客户端 / 自动获取地址**。本例的主路由已经联网，实验路由不需要再填 PPPoE 账号。

基础测试时，先让 WAN 自动获取上游网关和 DNS。检查状态页：

- WAN 获得 `192.168.1.x` 地址，默认网关为 `192.168.1.1`。
- LAN 仍为 `ROUTER_IP`，两个网段没有重叠。
- 防火墙保留路由模式常见的 LAN 到 WAN 转发、WAN 区域 IPv4 地址伪装，以及对 WAN 入站的限制。

如果安装的是面向开发板或主机的特殊镜像，不一定已经分配好 WAN/LAN；先按它的设备文档完成端口对应关系。

## 第五步：设置 Wi-Fi 并检查联网

### 无线先用容易判断的设置

设备确实有受支持的无线网卡时，再到 **网络 → 无线** 配置：

1. 设置与实际所在地一致的国家或地区。
2. 为测试网络使用单独的 SSID，例如 `Router-Lab`，避免与家中现有 Wi-Fi 混淆。
3. 选择设备与客户端共同支持的 WPA2-PSK（AES）或 WPA2/WPA3 过渡模式，设置独立密码。
4. 无线模式选择 **接入点 / Access Point**，确认无线接口接入 LAN 网络，启用并保存。
5. 先使用保守的信道宽度，例如 2.4 GHz 的 20 MHz；其他频段结合当地允许的信道、设备能力和实际干扰调整。

增加发射功率、拉宽信道不一定能改善使用体验。覆盖差先检查摆放位置和回程，有布线条件时增加有线 AP 通常更容易定位问题。

### 用一台客户端逐项验收

手机测试时临时关闭蜂窝数据，电脑测试时确认连接的是实验网络，避免实际流量走了另一条出口。

| 检查项       | 本例预期结果                             |
| ------------ | ---------------------------------------- |
| 客户端 IPv4  | `192.168.50.x`，掩码 `255.255.255.0`     |
| 默认网关     | `ROUTER_IP`                              |
| DNS          | 基础配置下通常由 DHCP 下发为实验路由地址 |
| 管理页面     | 能打开实验路由后台                       |
| 实验路由 WAN | 有上游分配的地址、默认路由和 DNS         |
| 实际上网     | 能解析域名并打开正常的 HTTPS 页面        |
| 原来的网络   | 接主路由的设备仍正常上网                 |
| 重启验证     | 实验路由重启后仍能分配地址并联网         |

Windows 上可以用这些命令辅助检查：

```powershell
ipconfig /all
ping ROUTER_IP
nslookup example.com
```

看 `ipconfig` 时，注意选择实际连接实验路由的网卡。Ping 没有回应只能作为线索，不能单独证明目标不可达；最终还要检查管理页和实际网页访问。

完成这一步，导出一份“基础联网正常”的配置备份。以后插件装坏了，就有一个明确的恢复起点。

## 第六步：安装插件

先检查内置功能是否已经满足需求，例如静态 DHCP 租约通常不需要额外插件。确实需要安装时，一次只装一个，验证后再继续；DNS 接管、透明代理、远程访问等功能分别测试。

### 安装前确认系统与软件包架构

管理页面通常能看到型号和固件版本。需要进一步确认时，在路由器的 SSH 终端执行：

```sh
ubus call system board
cat /etc/openwrt_release
uname -r
df -h
```

这些命令分别帮助查看设备与系统信息、发行信息、内核版本和存储空间。命令输出不需要原样公开，分享前检查设备标识等信息。

对使用 `opkg` 的系统，还可以查看支持的软件包架构：

```sh
opkg print-architecture
```

不要只凭 `uname -m` 显示 ARM 或 x86 就选包。固件分支、软件包管理器、依赖库和内核模块版本也会影响兼容性；如果系统使用的是 `apk`，应查它对应的文档，不能继续照抄 `opkg` 安装教程。

### 通过 LuCI 安装软件包

使用带 LuCI 的固件时，在 **系统 → 软件包** 中更新软件包列表，再查找需要的软件；菜单名称以当前版本为准。更新列表只是获取可用软件信息，不等于升级所有已安装软件。

1. 导出当前配置，记录准备安装的软件名称和来源。
2. 使用当前固件对应的软件源，先查看软件说明、依赖和剩余空间。
3. 安装后检查日志，再按插件文档配置。需要网页界面的插件，确认是否还需要对应的 LuCI 界面包。
4. 测试插件功能、普通上网和 DNS，必要时重启验证。

遇到依赖下载失败，检查**路由器自身**的默认路由、DNS、系统时间和软件源。旁路由场景可能出现电脑能上网、路由器自己却下载不了的情况。

iStore 和 Are-u-ok 的适配范围、手动安装步骤见 [iStoreOS 篇](/posts/2026-10-10-istoreos-guide/#第六步安装插件)。这些插件包不能直接当作通用 OpenWrt 软件包安装。

### 几种容易出问题的组合

- 同时启用多套 DNS 服务，抢占同一个监听地址的 53 端口，或相互转发形成循环。
- 同时安装多套会修改路由和防火墙的插件，却没有明确流量经过谁。
- 将别的系统版本或第三方仓库的软件源直接混入当前系统。
- 为通过安装而强制忽略依赖、架构或内核模块检查。
- 用“升级所有软件包”代替按发行版说明升级固件。

遇到插件冲突，先核对各自的兼容说明和日志，再决定保留哪一套服务。

## 基础稳定以后，再加这些功能

### 静态 DHCP 租约

给 NAS、打印机等设备固定地址，后续访问和排错更方便。在 DHCP 设置中按设备 MAC 建立静态租约，然后让客户端重新获取地址。

注意手机可能为不同 Wi-Fi 使用随机 MAC。自己在设备端手工设置静态 IP 时，也要避开 DHCP 动态地址池及其他设备已用的地址。

### DNS 过滤与分流

先画清楚实际查询路径，例如：

```text
客户端 → 路由器 DNS 入口 → 过滤服务 → 上游 DNS
```

如果保留 dnsmasq 负责 DHCP，同时增加其他 DNS 服务，就要按插件文档分配监听地址和端口，并确认上下游不会绕回自身。

客户端启用了加密 DNS、浏览器自带安全 DNS，或通过 IPv6 获得其他 DNS 时，可能不经过这条路径。不能只看插件“已启动”就认定所有设备都生效。

### SQM 与满载延迟

如果下载或上传跑满时，语音、游戏延迟明显升高，可以研究 SQM。先测日常可稳定达到的上下行速率，再按所用算法和文档设置整形速率并对比效果。

它会消耗处理器资源，也可能与某些流量卸载或硬件加速路径冲突。开启后检查延迟、吞吐和 CPU 占用，别只看测速数字。

### DDNS 与远程访问

DDNS 用来跟踪地址变化，本身不会解决运营商 NAT、端口限制或防火墙规则。需要从外部访问家中设备时，先确认公网 IPv4 / IPv6 条件，再选对应方案。

管理页面和 SSH 尽量只在内网开放；远程管理可使用合适的 VPN 方案，另行验证身份认证和访问范围。

### 想把旧路由改成 AP

AP 的目标是扩展原来的局域网。典型做法是使用固件提供的 AP 模式，或按文档将管理地址设为主路由网段内的不冲突地址，关闭多余的 DHCP 服务，再按指定方式连接或桥接端口。

还要检查设备是否继续发送 DHCPv6 或 IPv6 RA。不要只关掉 IPv4 DHCP，就默认所有地址分配都交给了主路由。

旁路由则需要另外设计客户端网关、DNS 和回程路径。只修改 DNS 只会改变相应的解析路径；只修改 IPv4 网关也不代表 IPv6 流量会走同一路径。入门时先对一台测试设备生效，再考虑扩大范围。

## 常见问题怎么排查

按“电脑连接 → LAN 地址 → WAN 状态 → DNS → 应用服务”的顺序检查，每次只改一处。

| 现象                            | 优先检查                                     | 处理方向                             |
| ------------------------------- | -------------------------------------------- | ------------------------------------ |
| 改完 LAN 后进不了后台           | 电脑是否仍拿着旧地址，是否连错 Wi-Fi         | 重新获取地址，用新管理地址访问       |
| 电脑得到 `169.254.x.x`          | 是否拿不到 DHCP 租约、网线是否插到 LAN       | 检查物理连接和 LAN DHCP 服务         |
| WAN 没有地址                    | 主路由 LAN 到实验路由 WAN 的接线、上游 DHCP  | 先确认物理口对应和 WAN 协议          |
| WAN 和 LAN 在同一网段           | 地址规划是否冲突                             | 单独连接实验路由，改成不重叠网段     |
| 有地址但不能上网                | WAN 默认路由、转发规则、IPv4 NAT             | 对照基础路由模式配置                 |
| 域名解析失败                    | DNS 地址、监听端口、上游及系统时间           | 暂停新增 DNS 插件，恢复基础 DNS 路径 |
| 插件安装失败                    | 固件版本、架构、依赖、存储和路由器自身联网   | 阅读首个有效报错，不要强制忽略依赖   |
| 有线正常、无线异常              | 无线接口是否接入 LAN，认证、信道和客户端兼容 | 先用基础无线配置测试                 |
| 测试网络的 NAS 不易被主网络发现 | 二级路由分网段、广播发现与防火墙             | 按实际需求设计访问或调整为 AP 拓扑   |

需要查日志时，可以在 LuCI 的系统日志页面查看，也可以在路由器上执行：

```sh
ip addr
ip route
logread | tail -n 80
```

`ip route` 主要查看这里讨论的 IPv4 路由；IPv6 问题需要单独检查 IPv6 路由和地址。日志是定位线索，里面可能有域名、地址或凭据，分享前先脱敏。

### 什么时候需要恢复

- **只是找不到管理地址**：检查客户端默认网关、上游 DHCP 租约及之前记录的管理地址。
- **装插件后出问题**：先停用最近启用的插件，回退对应配置。
- **配置混乱但系统还能启动**：使用此前验证过的配置备份，或按设备说明清配置后重新设置。
- **系统不能正常启动**：按精确机型的 Failsafe、Recovery、TFTP 等恢复说明处理。

恢复出厂设置通常只是清除当前系统的配置，不会自动刷回厂商原装固件。引导程序损坏又是另一类问题，不能用通用 Reset 步骤概括。

## 升级、备份与日常维护

每次较大调整前，留一份简短记录：

```text
设备型号 / 硬件版本：
固件名称 / 版本：
管理地址：
WAN 接入方式：
LAN 网段 / DHCP 范围：
已安装插件及版本：
本次修改：
配置备份位置：
恢复说明来源：
```

升级先看发行说明，确认设备支持、是否允许保留配置，以及插件是否有对应版本。升级后检查地址分配、DNS、Wi-Fi、IPv6 和实际要用的服务；正常后再保存新的备份。

保留一份基础联网正常的配置。后续调整 DNS、远程访问或网络结构时，每完成一项就验证一次，出问题时按记录回退。
