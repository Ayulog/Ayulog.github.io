qiandao 用 HTTP 请求模板执行签到等定时任务。以下使用 `a76yyyy/qiandao` 镜像，命令在 Linux Shell 中运行。

[QD 官方文档](https://qd-today.github.io/qd/zh_CN/guide/deployment.html)使用的是 `qdtoday/qd`。两者的版本和参数需要分别核对；更换镜像时先备份，不要让两个容器同时写同一份数据库。

## 准备工作

开始前准备一台能长期运行 Docker 的服务器或家用设备，并确认以下端口没有被其他服务占用：

- Docker Engine 或 Docker Desktop；
- 主机上的 `8923` 端口（也可以在运行容器时改成其他端口）；
- 一个用于保存 qiandao 配置和数据库的目录；
- 如果需要从公网访问，准备域名、HTTPS 证书和反向代理。

qiandao 的数据需要放在容器外部。这样容器重建或升级时，任务、账号和执行记录仍然可以保留。

> 操作前先备份数据库。配置目录通常同时包含数据库和任务凭据，丢失或泄露都会影响已保存的任务。

## 使用 Docker 部署

先创建数据目录，并从 [a76yyyy/qiandao 标签页](https://hub.docker.com/r/a76yyyy/qiandao/tags)选择一个仍然存在的稳定标签。下面以该页面当前可见的日期标签 `20250803` 为例；如果标签页已经更新，替换为页面中的目标标签：

```bash
mkdir -p ./qiandao-config
docker pull a76yyyy/qiandao:20250803
```

`latest` 适合快速试用，但它会随着镜像维护者推送新版本而变化。长期运行时固定日期标签，并记录当前使用的标签和镜像摘要，升级前先做备份。

启动容器：

```bash
docker run -d \
  --name qiandao \
  --restart unless-stopped \
  -p 8923:80 \
  -v "$(pwd)/qiandao-config:/usr/src/app/config" \
  a76yyyy/qiandao:20250803
```

命令中各参数的作用如下：

- `--name qiandao`：给容器设置固定名称，便于查看日志和升级；
- `--restart unless-stopped`：主机重启后自动恢复服务；
- `-p 8923:80`：把主机的 8923 端口映射到容器的 HTTP 端口 80；
- `-v ...:/usr/src/app/config`：把配置和数据持久化到主机目录。

如果 8923 已被占用，可以改成其他主机端口，例如 `-p 18080:80`，之后访问 `http://服务器地址:18080`。启动后先查看日志确认服务状态：

```bash
docker ps
docker logs -f qiandao
```

在浏览器打开 `http://服务器地址:8923`。如果 Docker 运行在本机，也可以使用 `http://127.0.0.1:8923`。

## 初始化与登录

第一次打开页面时注册账号。官方文档说明首位注册用户默认为管理员；注册后先退出再登录，确认管理菜单已经出现。建议：

1. 使用随机生成的长密码，不要复用其他站点的密码；
2. 完成登录后立即确认站点地址、时区和通知设置；
3. 如果服务只供自己使用，在防火墙中只放行内网或 VPN 网段；
4. 需要公网访问时，在 qiandao 前面配置 HTTPS，并在反向代理层增加访问控制。

官方 QD 文档还列出了 `DOMAIN`、`AES_KEY` 和 `COOKIE_SECRET` 等环境变量。`a76yyyy/qiandao` 的具体标签是否保留这些变量，应以该标签的 README 和配置说明为准；如果支持，请把 `DOMAIN` 改成实际访问地址，并把默认的加密密钥和 Cookie 密钥替换成随机值。

不要把管理页面直接暴露在公网而不设置 HTTPS。签到任务通常包含 Cookie、Token 或其他账号凭据，泄露后可能导致第三方账号被接管。

## 制作 HAR 模板与创建第一个签到任务

qiandao 的任务一般由两部分组成：用于描述请求和提取结果的**模板**，以及填写账号信息的**任务实例**。不同站点的登录方式和返回数据不同，不能直接套用同一个模板。

### 1. 在浏览器中抓取 HAR

HAR（HTTP Archive）是浏览器保存的一组网络请求记录。制作模板前，只抓取自己有权操作的站点，并尽量使用一个专门的浏览器配置文件：

1. 打开目标站点并登录，进入需要执行签到或领取操作的页面；
2. 按 `F12` 打开开发者工具，切换到 **Network（网络）**，清空已有记录；
3. 重新执行一次目标操作，等待成功提示和相关请求完成；
4. 在请求列表中找到真正提交签到的请求，右键选择 **Save all as HAR with content（将所有内容另存为 HAR）**，保存到本地。

Chrome 和 Edge 的菜单名称基本一致。Firefox 可以在 Network 面板中重现操作，再右键已加载的结果并选择 **Save All As HAR**。如果一次操作包含多个连续请求，保留完成任务所需的请求，删除无关的统计、图片和其他站点请求。

HAR 可能包含 Cookie、`Authorization`、密码和完整响应正文。不要把原始 HAR 上传到网盘、提交 Git 或直接发给他人；分享前先删除敏感字段，实际模板中的凭据也应使用任务变量保存。

### 2. 上传 HAR 并打开编辑器

登录 qiandao 后进入 **我的模板**，点击右侧的 `+`，选择刚才保存的 HAR 文件并上传。也可以在 **社区模板** 中更新模板列表，订阅一个接近目标站点的模板，再按下面的步骤修改。

### 3. 把固定凭据改成模板变量

在请求编辑器中检查 URL、请求方法、请求头、Cookie 和请求体。把每个账号都不同的值替换为 Jinja2 变量，例如：

```text
{{ username }}
{{ password }}
{{ cookie }}
```

变量名要在模板和任务实例中保持一致，实际字段名称以当前 HAR 编辑器提供的变量列表为准。除了用户名、密码和 Cookie，也要检查请求头里的 `Authorization`、请求体中的账号字段，以及 URL 查询参数。不要把一次性 CSRF Token 当成固定值；如果它来自上一个请求，就使用变量提取保存，再供后续请求使用。

### 4. 测试请求、断言和变量提取

在请求编辑器的测试面板中，先用正确的账号测试，再用错误的账号测试，确认模板确实能区分成功和失败。为每个关键请求填写成功/失败断言，例如状态码、响应文本或 JSON 字段，这样任务失败时可以留下明确结果。

如果后续请求依赖前一个请求返回的数据，使用变量提取功能按正则表达式提取并保存为环境变量。正则表达式可以用组选择器只保留需要的部分，例如 `ab(\w+)cd` 只取括号中的内容。需要把调试信息写入任务日志时，可以使用 `__log__` 提取。

所有请求编辑完成后，点击下载按钮旁边的 **测试**，执行一次完整模板测试；确认结果后点击 **保存**。编辑中的模板会自动保存在浏览器缓存中，也可以点击 **下载** 导出一份脱敏后的模板备份。

### 5. 从模板创建定时任务

进入 **我的任务**，点击 `+`，选择刚创建的模板，填写任务变量、任务间隔、任务组和执行时间。先点击 **测试** 手动执行，确认日志和返回结果正确后再保存并启用定时任务。

也可以按下面的顺序快速检查任务：

- 模板测试能在没有定时任务的情况下完成；
- 任务测试使用真实任务变量，确认每个账号的值都已填写；
- 日志中只保留必要的成功或失败信息，不要输出完整 Cookie、Token 或响应正文。

模板中的敏感值应使用变量或账号字段保存，避免把真实 Cookie、Token 和密码直接写进公开分享的模板。导入他人模板前，先检查它实际请求的域名、请求头和脚本内容。

## 设置定时执行和通知

在任务实例中设置执行时间时，先确认容器和宿主机的时区一致。建议把任务安排在目标站点允许签到的时间窗口内，并给同一站点的多个账号错开几分钟，减少短时间内大量请求。

首次使用时可以只启用一个任务，观察几天日志再逐步增加任务数量。通知渠道应只发送执行结果和必要的错误信息，不要把完整 Cookie、Token 或响应正文发送到群聊。

## 备份、升级与回滚

### 备份配置目录

停止容器后，把挂载目录打包保存到另一块磁盘或可信的私有存储：

```bash
docker stop qiandao
tar -czf qiandao-config-$(date +%F).tar.gz ./qiandao-config
docker start qiandao
```

备份文件可能包含账号凭据，保存时应限制文件权限，并避免上传到公开仓库。

### 升级镜像

先确认 Docker Hub 标签页中的目标版本，再执行。下面把 `20250803` 替换为你要升级到的标签：

```bash
docker pull a76yyyy/qiandao:目标版本
docker stop qiandao
docker rm qiandao
docker run -d \
  --name qiandao \
  --restart unless-stopped \
  -p 8923:80 \
  -v "$(pwd)/qiandao-config:/usr/src/app/config" \
  a76yyyy/qiandao:目标版本
```

升级前后都要使用同一个挂载目录，并且不要让新旧容器同时写入同一份数据库。启动后检查日志并手动执行一个低风险任务，确认模板和历史记录可以正常读取。升级出现问题时，先停止新容器，恢复备份目录，再使用原来的镜像标签启动。

## 常见问题

### 页面无法打开

先检查容器是否正在运行：

```bash
docker ps -a --filter name=qiandao
docker logs --tail 100 qiandao
```

如果容器已退出，通常需要从日志判断端口冲突、挂载目录权限或配置文件错误。若容器运行正常，再检查主机防火墙、安全组和端口映射是否允许访问。

### 重建容器后数据消失

检查 `-v` 参数左侧是否仍然指向原来的主机目录。没有挂载配置目录时，数据只保存在容器可写层，删除容器后就会丢失。

### 任务返回登录失效

Cookie、Token 和验证码状态都有有效期。重新登录目标站点并更新任务变量，随后手动执行任务确认请求头和请求体仍符合站点接口要求。不要为了绕过风控而无限提高重试次数。

### HAR 回放失败或显示成功但没有签到

先确认导出时选择了 **with content**，否则 POST 或 JSON 请求体可能没有保存。再检查请求顺序、`Content-Type`、重定向和变量替换是否完整。HTTP 200 只代表请求被服务器接收，成功断言还应检查响应正文中的状态字段或成功关键词。

验证码、二次验证、动态签名、时间戳和 nonce 等流程通常无法只靠一份 HAR 长期回放，需要按站点规则增加变量提取或其他处理。先用测试账号回放，确认站点允许自动化，并遵守站点条款和频率限制。

### 定时任务没有执行

检查任务是否被暂停、执行时间是否已经过去，以及容器时区是否与页面显示时区一致。再查看对应时间段的容器日志；如果只有浏览器访问正常而后台执行失败，重点检查模板请求的域名解析、证书和网络出口。
