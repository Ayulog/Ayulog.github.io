iStoreOS 基于 OpenWrt 定制，内置了图形化的网络向导和 iStore 软件中心，降低了初次配网和安装插件的门槛。本文整理从镜像选择、二级路由与旁路由向导配置、绿联 NAS 虚拟机导入，到 iStore 第三方插件安装的完整流程。

软路由系统与插件汇总见 [软路由系统与插件清单](/posts/soft-router-software/)；LuCI 通用接口配置、Wi-Fi、AP 与 SQM 等内容见 [OpenWrt：路由器配网与插件笔记](/posts/openwrt-guide/)。

## 镜像准备与安装前检查

从 [iStoreOS 官网](https://www.istoreos.com/)或 [官方快速上手文档](https://doc.istoreos.com/zh/guide/istoreos/)下载对应设备的固件镜像。下载与刷写前先核对以下硬件信息：

| 检查项     | 核对内容                                                  |
| ---------- | --------------------------------------------------------- |
| 设备与架构 | 确认设备在官方支持列表中，区分 x86_64 与具体 ARM 平台镜像 |
| 启动方式   | x86 主机或虚拟机使用 UEFI 还是 Legacy BIOS 引导           |
| 存储介质   | 确认目标写入磁盘，整盘写入会覆盖目标盘原有分区与数据      |
| 网口映射   | 默认 WAN、LAN 物理网口对应关系，以及无线网卡驱动支持情况  |
| 恢复方式   | 设备失联或无法启动时的控制台接入方式与救砖流程            |

`.img` / `.img.gz` 属于磁盘镜像：实体机使用写盘工具写入存储介质，虚拟机则解压出 `.img` 后作为虚拟磁盘导入。下载后可在 PowerShell 中核对文件的 SHA-256 校验值：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath ".\istoreos.img.gz"
```

重装或更换系统前，先记录原有的管理地址、宽带账号、静态租约、端口转发及 VLAN 设置。若当前已运行 iStoreOS，可在系统备份页面导出配置文件，并将容器或插件的独立数据目录备份到其他设备。

## 网络向导配网：二级路由与旁路由

### 用网络向导配置二级路由

双网口或多网口设备可先接在现有主路由后方作为二级路由测试。以下示例假设主路由网段为 `192.168.1.1/24`，iStoreOS 的 LAN 网段规划为 `192.168.50.0/24`（管理地址 `ROUTER_IP` 为 `192.168.50.1`）：

```text
现有主路由：192.168.1.1/24
      │ LAN 口
      ▼
   iStoreOS（WAN 口：DHCP 获取 192.168.1.x）
      │ LAN 口：192.168.50.1/24
      ▼
   测试电脑：192.168.50.x
```

1. **单独连接修改 LAN 网段**：先不接上游主路由，仅用网线将电脑接到 iStoreOS 的 LAN 口。登录初始后台，设置管理员密码并检查系统时间与时区。
2. **设置 LAN 地址与 DHCP**：将 LAN 口 IPv4 地址改为 `ROUTER_IP/24`（如 `192.168.50.1/24`），启用 DHCP 服务（如地址池 `192.168.50.100`–`192.168.50.199`），LAN 网关留空。保存后重新插拔网线，使用新管理地址 `http://ROUTER_IP` 登录后台。
3. **连接 WAN 口并运行向导**：用网线连接“主路由 LAN 口 → iStoreOS WAN 口”，打开 **网络向导 → 连接现有路由器 → DHCP**（详见 [官方网络向导文档](https://doc.istoreos.com/zh/guide/istoreos/basic/network_guide.html)）。
4. **验证连通性**：确认 WAN 口已获取 `192.168.1.x` 地址与上游网关，测试电脑已拿到 `192.168.50.x` 地址并能正常解析域名、打开 HTTPS 网页：

```powershell
ipconfig /all
ping ROUTER_IP
nslookup example.com
```

确认重启后地址分配与联网正常，即可导出一份基础配置备份。二级路由在 IPv4 下会形成双重 NAT，若需端口映射或与主路由设备同网段互通，可改用下方的旁路由模式。

### 配置为旁路由并指定客户端网关

单网口小主机或 NAS 虚拟机通常配置为旁路由，与主路由处于同一局域网，由需要使用旁路由服务的客户端主动将网关或 DNS 指向它。

以下假设主路由为 `192.168.1.1/24`，旁路由规划使用空闲地址 `192.168.1.30/24`（提前在主路由 DHCP 地址池外保留该 IP）：

1. **接入前关闭 DHCP**：通过单独连接或虚拟机控制台登录 iStoreOS，提前关闭其 LAN 口的 IPv4 DHCP、DHCPv6 和 IPv6 RA 服务，避免接入后与主路由争夺地址分配。
2. **运行旁路由向导**：接入家庭局域网，打开 [网络向导](https://doc.istoreos.com/zh/guide/istoreos/basic/network_guide.html) 选择“配置为旁路由”。将管理地址设为 `192.168.1.30/24`，默认网关指向主路由 `192.168.1.1`，DNS 填写主路由或可用的上游 DNS。
3. **验证旁路由自身联网**：在 iStoreOS 后台或终端确认路由器自身可以正常解析域名并访问外网。
4. **指定测试客户端网关**：将一台测试电脑或手机的 IPv4 网关手动改为 `192.168.1.30`（如需使用旁路由上的 DNS 服务，同时将 DNS 改为 `192.168.1.30`），测试网页访问、域名解析与局域网 NAS 访问。

主路由仍负责全屋设备的 DHCP 分配。当旁路由关机或维护时，只需将客户端恢复为 DHCP 自动获取（或指回主路由网关）即可恢复正常上网。

## 在绿联 NAS 虚拟机中安装

以下流程参考 [磕巴白菜的绿联虚拟机部署文章](https://hi.keba.host/archives/istores) 整理，适用于支持虚拟机与磁盘镜像导入的绿联 NAS 系统。

### 1. 导入镜像与配置网络

1. **检查 NAS 网络模式**：记录 NAS 当前管理地址与网口连接状态。若启用了双网口聚合（Bond），按实际虚拟交换机规划决定是否使用独立物理网口承载虚拟机桥接网络。
2. **准备解压后的磁盘镜像**：下载与 NAS 处理器架构（如 x86_64）及引导方式匹配的 iStoreOS 镜像，将 `.img.gz` 解压为 `.img` 文件并上传至 NAS 存储空间。
3. **创建虚拟机**：在虚拟机管理器中选择“从磁盘镜像导入”，指定 `.img` 镜像与持久化存储池，操作系统类型选 Linux，按 NAS 硬件余量分配 CPU 核心与内存。
4. **控制台初始化与防冲突设置**：首次开机可先使用隔离网络，通过 VNC 控制台进入终端，查看或修改 LAN 口地址，并在接入家庭局域网前关闭多余的 DHCP、DHCPv6 与 IPv6 RA。
5. **切换桥接并完成向导**：将虚拟网卡切换到家庭局域网对应的桥接网络，从局域网电脑访问刚才设置的管理地址，按上一节的“配置为旁路由”步骤完成向导并指定一台客户端验证。

> [!NOTE]
> 宿主机（NAS 本体）与桥接虚拟机之间能否直接互通，取决于虚拟交换机与网卡桥接模式。若单网口桥接下 NAS 本体无法直接将网关指向内部虚拟机，可让局域网其他客户端使用该虚拟旁路由，NAS 自身保持主路由网关。

### 2. 验证持久化与快照备份

完成基础设置后，在虚拟机管理器中正常关机再重新启动，确认管理地址、网络向导设置及已安装插件均正常保留。若重启后配置还原，需检查虚拟机启动顺序是否仍挂载在只读引导盘或启用了还原模式。

验证网络稳定后，再按需开启虚拟机的“随 NAS 自动启动”，并在大改动前导出 iStoreOS 配置备份或创建虚拟机快照。

## iStore 与第三方插件安装

### 核对版本、架构与来源

iStore 软件中心支持在线安装与手动上传 `.run` 插件包。安装第三方插件前，先在后台首页或通过 SSH 确认固件版本与软件包架构：

```sh
ubus call system board
cat /etc/openwrt_release
uname -r
df -h
opkg print-architecture
```

[Are-u-ok 仓库](https://github.com/AUK9527/Are-u-ok) 汇总了面向 iStoreOS 各版本的第三方插件包。例如其 [apps 目录说明](https://github.com/AUK9527/Are-u-ok/blob/6dbb3c14b3426dce23ccdf8e8507252b98e2f0ac/apps/README.md) 针对 **KoolCenter iStoreOS 22.03.X**，对应架构为 `aarch64_cortex-a53`（及兼容的 `aarch64_generic`）与 `x86_64`。下载前务必进入与当前系统版本和 CPU 架构一致的目录。

### 手动安装 `.run` 插件包

`.run` 文件是自解压安装脚本，安装过程中通常仍需联网从软件源下载依赖包：

1. 先导出当前系统配置备份，确认剩余存储空间充足。
2. 从对应版本与架构目录下载 `.run` 文件。
3. 打开 **iStore → 手动安装**，上传或拖入 `.run` 文件，在弹出终端中观察安装日志（也可按仓库 README 说明通过 SSH 直接执行 `.run` 脚本）。
4. 显示安装成功后刷新后台页面，按插件文档配置并启动服务。
5. 逐个验证插件功能、局域网 DNS 解析与普通网页访问，正常后再安装下一个插件。

若安装日志提示依赖拉取失败，优先检查 iStoreOS 自身的网关、DNS、系统时间与软件源连通性；避免同时启用多套争抢 53 端口的 DNS 插件或多套透明代理插件。

## 故障排查与系统升级

| 现象                        | 优先检查项                                                              |
| --------------------------- | ----------------------------------------------------------------------- |
| 修改 LAN 地址后进不了后台   | 刷新电脑网卡 DHCP 租约，确认未误连其他 Wi-Fi，改用新管理 IP 访问        |
| 二级路由模式下无法上网      | 检查 WAN 口是否获取到主路由分配的 IP，确认 WAN 与 LAN 网段未重叠        |
| 旁路由无法更新软件源或插件  | 检查旁路由自身的默认网关（需指向主路由）、DNS 配置与系统时间            |
| 旁路由接入后全屋网络异常    | 检查旁路由是否未关闭 IPv4 DHCP、DHCPv6 或 IPv6 RA，或管理 IP 发生冲突   |
| 电脑能连虚拟机但 NAS 连不上 | 检查 NAS 虚拟交换机的桥接模式与单网口限制，分开测试客户端与宿主机连通性 |
| 插件安装报错或 DNS 失效     | 查看安装终端首个报错信息；停用最近新增的 DNS 或代理插件并检查 53 端口   |
| 虚拟机重启后配置丢失        | 检查虚拟机磁盘挂载顺序、存储池读写权限及是否启用了磁盘还原模式          |

日常升级系统前，先查阅目标版本的发行说明并导出配置备份。升级完成后依次复查管理地址、DHCP/旁路由网关、DNS 解析及核心插件状态，确认无误后留存新的配置备份。
