iStoreOS 基于 OpenWrt，提供网络向导和 iStore 软件中心。把它装到软路由或 NAS 虚拟机之前，要先找到对应设备的镜像，再决定让它接在主路由后面做二级路由，还是留在同一网段做旁路由。设备、镜像和虚拟机界面会随版本变化，安装时对照对应设备的文档。

系统与插件入口见 [软路由系统与插件清单](/posts/soft-router-software/)；LuCI 基础设置、Wi-Fi、AP、SQM 等通用内容见 [OpenWrt 配网与插件笔记](/posts/openwrt-guide/)。

## 设备、镜像与安装前准备

从 [iStoreOS 官网](https://www.istoreos.com/) 和 [官方快速上手文档](https://doc.istoreos.com/zh/guide/istoreos/) 查找设备对应的安装说明与镜像。先确认完整型号、硬件版本、处理器架构、网口数量和启动方式，再下载文件。支持 OpenWrt 的设备，不一定有对应的 iStoreOS 镜像。

| 检查项     | 要确认的内容                                              |
| ---------- | --------------------------------------------------------- |
| 设备与架构 | 镜像支持列表中有当前型号或平台，ARM、x86 字样对应架构大类 |
| 启动方式   | x86 或虚拟机使用 UEFI 还是 Legacy，是否符合镜像说明       |
| 存储       | 写入的是哪块磁盘，原有数据是否需要保留                    |
| 网络       | 物理口与 WAN、LAN 的对应关系，无线网卡是否受支持          |
| 恢复方式   | 管理入口失联或系统无法启动时，如何进入控制台或恢复环境    |

`.img` / `.img.gz` 通常是磁盘镜像，安装方法按官方说明选择：实体设备写入介质，虚拟机按平台说明导入磁盘。写入整盘镜像前核对目标磁盘，避免覆盖其他数据。

下载渠道提供校验值时，计算文件哈希并对照同一渠道的发布值。例如在 Windows 上：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath ".\istoreos.img.gz"
```

文件名换成实际下载的名称；校验压缩包还是解压后的镜像，按发布说明选择。

安装或换系统前，保存现有管理地址、WAN 接入方式、Wi-Fi、静态租约、端口转发，以及需要保留的 IPTV / VLAN 设置。已有 iStoreOS 时，可从系统的备份页面导出配置，并将插件数据单独备份到其他设备。配置备份通常不包含整个系统、所有软件包和外接磁盘数据。

## 用网络向导配置二级路由

双网口设备可以先接在现有主路由后面，只给一台测试设备使用。下面使用两个不同的 IPv4 网段：

```text
现有主路由：192.168.1.1/24
      │ LAN
      │
      │ WAN：自动获取 192.168.1.x
   iStoreOS
      │ LAN：ROUTER_IP/24
      │
   测试电脑：192.168.50.x
```

这些是示例地址。如果上游或 VPN 已经使用其中的网段，需要换成不重叠的私有网段。单网口设备不要直接套用这套接线，可以按下一节配置旁路由。

1. 暂时不接上游，只把电脑连接到 iStoreOS 的 LAN 口，让电脑自动获取地址。按设备文档查初始管理地址和网口分配，不默认第一个物理口就是 WAN。
2. 进入管理页面，设置管理员密码，检查系统时间与时区。时间错误会影响 HTTPS 和软件下载。
3. 将 LAN 地址改为 `ROUTER_IP/24`，启用该网段的 DHCP 服务。例如地址池使用 `192.168.50.100` 至 `192.168.50.199`。LAN 网关留空，本例默认路由由 WAN 获取。
4. 应用后让电脑重新获取地址，再打开 `http://ROUTER_IP`；使用 HTTPS 的系统按实际协议访问。出现确认或回滚倒计时时，按页面提示完成确认。
5. 连接“主路由 LAN → iStoreOS WAN”，打开 **网络向导 → 连接现有路由器 → DHCP**。入口见 [当前网络向导文档](https://doc.istoreos.com/zh/guide/istoreos/basic/network_guide.html)。主路由已经负责拨号时，这里不重复设置 PPPoE。
6. 检查 WAN 是否取得 `192.168.1.x`、上游网关和 DNS，LAN 是否仍为 `ROUTER_IP`。保留路由模式需要的 LAN 到 WAN 转发、WAN 区域 IPv4 地址伪装及 WAN 入站限制。

测试电脑应获得 `192.168.50.x`，默认网关为 `ROUTER_IP`，能够访问后台、解析域名并打开 HTTPS 网页。Windows 可辅助检查：

```powershell
ipconfig /all
ping ROUTER_IP
nslookup example.com
```

电脑有多个网络连接时，先确认实际使用的是测试网卡。完成后重启 iStoreOS，再检查地址分配和联网，导出一份基础配置备份。

这套接法通常会形成双重 IPv4 NAT，可能影响入站连接、端口转发和部分游戏；测试设备也通常仍能访问上游局域网。IPv6 的前缀、RA 和防火墙按上游的分配设置。

## 配置为旁路由并指定客户端网关

旁路由与主路由在同一局域网内，需要明确哪些设备使用它的网关或 DNS。接上网线本身不会让所有流量经过它。

以下假设主路由为 `192.168.1.1/24`，旁路由使用 `192.168.1.30/24`。先确认 `.30` 未被占用，并从主路由动态地址池中排除，或按主路由的规则保留该地址。

1. 在接入现有 LAN 前，通过单独连接或虚拟机控制台设置管理地址，关闭旁路由上多余的 DHCP、DHCPv6 和 IPv6 RA，避免与主路由同时给客户端分配网络参数。
2. 连接现有 LAN，按 [网络向导](https://doc.istoreos.com/zh/guide/istoreos/basic/network_guide.html) 选择“配置为旁路由”。管理地址设为 `192.168.1.30/24`，自身默认网关指向 `192.168.1.1`，DNS 先使用主路由或其他可用的上游解析服务。转发和防火墙设置依向导及当前版本说明核对。
3. 先确认 iStoreOS 自己能联网，再将一台测试设备的 IPv4 网关改为 `192.168.1.30`。需要使用旁路由提供的 DNS 服务时，单独调整 DNS。
4. 检查网页访问、域名解析和局域网 NAS 访问。改 DNS 只影响域名解析，流量路由仍由网关决定；改 IPv4 网关不影响 IPv6 路径。
5. 记录测试设备原来的网络设置。停止旁路由后，验证恢复自动获取或原网关、DNS 即可恢复使用，再考虑扩大使用范围。

主路由继续负责 DHCP。旁路由关机或服务停止时，依赖它提供网关或 DNS 的设备可能断网。

## 在绿联 NAS 虚拟机中安装

绿联 NAS 这一节按 [磕巴白菜的部署文章](https://hi.keba.host/archives/istores) 整理，原文记录了导入 `.img`、进入控制台、修改管理地址和配置旁路由的过程，可配合截图查看；这部分没有实机验证。开始前先确认当前绿联系统与机型支持虚拟机和磁盘镜像导入。

### 导入镜像与连接网络

1. **记录 NAS 现有网络。** 原教程先检查双网口的 Bond（链路聚合）状态，再按其方案解绑、使用独立网口。是否需要解绑取决于实际虚拟网络方案；改动前保存 NAS 管理地址、接线和恢复方法。
2. **取得对应镜像。** 从 iStoreOS 官方入口下载符合 NAS 处理器架构和虚拟机启动方式的镜像。`.img.gz` 先解压成 `.img`，再交给虚拟机的磁盘镜像导入功能。
3. **创建虚拟机。** 选择“从磁盘镜像导入”，指定镜像和数据存储位置，系统类型选 Linux。CPU、内存、磁盘及虚拟网卡按 NAS 余量与当前平台说明设置。首次开机先使用隔离虚拟网络，或让分配给它的独立物理口暂时断开上游。
4. **从控制台确认启动。** 检查管理地址，按系统提供的入口修改 LAN 地址。接入家庭 LAN 前，关闭多余的 DHCP、DHCPv6 和 IPv6 RA。原教程的 `192.168.1.26`、`192.168.1.30` 是示例，换到不同网段时要改成实际地址。
5. **接入对应的桥接网络。** 确认不会发生地址或 DHCP 冲突后，将虚拟网卡接入现有 LAN 的桥接网络。用同一局域网内的电脑访问实际管理地址，按当前镜像说明首次登录并设置密码。
6. 按前一节的旁路由步骤完成向导，先让一台客户端使用，确认网关、DNS 与局域网访问正常。

原教程提示其单网口接法对 NAS 本体使用虚拟旁路由存在限制。宿主机与虚拟机能否互通，取决于虚拟交换机、桥接和网卡模式。分别验证电脑到旁路由、NAS 到旁路由的连通性，再决定是否调整 NAS 默认网关。

### 检查配置是否保存

导入的系统磁盘应保存在 NAS 的持久化存储中。完成基础配置后，正常关闭再启动虚拟机，检查管理地址、网络向导结果和插件配置是否仍在。重启丢失配置时，先核对是否从正确的系统盘启动、磁盘是否可写，以及平台是否启用了会还原磁盘的模式，不要反复重装插件。

保存 iStoreOS 配置备份；平台支持时，也可在较大调整前保留虚拟磁盘备份或快照。快照依赖原存储，不能替代存放在其他位置的备份。NAS 重启和虚拟机停止也会影响依赖旁路由的客户端，自动启动选项需在验证网络后再设置。

## iStore 与第三方插件

iStore 是软件中心，安装 iStore 不会把其他 OpenWrt 固件变成 iStoreOS。手动安装页面能接收文件，包是否适配当前系统要看插件说明。

### 核对版本、架构与来源

先从管理页面查看型号和固件版本。需要详细信息时，在路由器 SSH 终端运行：

```sh
ubus call system board
cat /etc/openwrt_release
uname -r
df -h
```

对使用 `opkg` 的系统，可再运行 `opkg print-architecture` 查看软件包架构；使用其他包管理器的版本按对应文档核对。`uname -m` 只列出部分架构信息，固件分支、依赖库和内核模块兼容性还要看软件包清单。

[Are-u-ok 仓库](https://github.com/AUK9527/Are-u-ok) 提供不同系统版本和架构的入口。原笔记核对的 [apps README 固定版本](https://github.com/AUK9527/Are-u-ok/blob/6dbb3c14b3426dce23ccdf8e8507252b98e2f0ac/apps/README.md) 面向 **KoolCenter iStoreOS 22.03.X**，主要架构为 **`aarch64_cortex-a53`**，同时列出 **`aarch64_generic`** 兼容说明。换到其他版本时，安装前查仓库最新的对应入口。

部分依赖要通过软件源在线下载，取得 `.run` 文件不等于能够离线安装。`.run` 是安装程序，不能放进固件升级页面。安装器会以系统管理权限修改软件和服务，只使用已核对来源、适配说明的文件。

### 手动安装与验证

1. 导出当前配置，记录插件名称、版本和来源。
2. 从维护者的对应目录取得 `.run` 文件，确认系统、架构和依赖匹配。
3. 打开 **iStore → 手动安装**，上传或拖入文件，查看安装日志。
4. 安装成功后刷新页面，按插件说明配置并启用服务。
5. 检查插件功能、普通上网和 DNS，必要时重启验证，再继续安装下一个插件。

依赖下载失败时，检查路由器自身的默认路由、DNS、系统时间、存储空间和软件源。电脑能上网时，旁路由自己的出网仍可能不通。

仓库 README 也提供直接执行 `.run` 的方式；执行方式不同，版本和架构仍要匹配。遇到冲突先看首个有效报错和插件说明，不强制跳过依赖检查。多套 DNS 服务可能争用 53 端口或形成转发循环，多套网络插件也可能同时修改路由和防火墙。

原绿联教程提到过旧版 iStore 软件源域名变更的修复命令。那是特定版本的故障处理，不作为每次安装的固定步骤；遇到软件源报错时按当前版本查维护者说明。

## 排错、升级与恢复

| 现象                       | 优先检查                                                               |
| -------------------------- | ---------------------------------------------------------------------- |
| 修改 LAN 后进不了后台      | 电脑是否保留旧租约、是否连错网络，改用新的管理地址                     |
| 二级路由不能上网           | WAN 是否取得上游地址，WAN 与 LAN 是否重叠，转发与 NAT 是否符合路由模式 |
| 旁路由自己不能下载         | 自身默认网关、DNS、时间和软件源，先测路由器自己的出网                  |
| 接入后家庭网络异常         | 是否有第二个 DHCP、DHCPv6 或 IPv6 RA 服务，是否管理地址冲突            |
| 电脑能访问虚拟机，NAS 不能 | 宿主机与虚拟机的桥接、虚拟交换机和网卡模式                             |
| 插件安装失败               | 固件版本、软件包架构、空间、依赖和首个安装报错                         |
| 装插件后 DNS 异常          | 停用最近添加的服务，检查监听端口与上下游是否循环                       |
| 虚拟机重启后配置消失       | 启动磁盘、磁盘写入状态及平台还原设置                                   |

系统日志可从管理页面查看；SSH 中可以用 `ip addr`、`ip route` 和 `logread | tail -n 80` 辅助检查。分享日志前删去凭据和设备标识。

升级前阅读对应版本发行说明，确认设备支持、是否允许保留配置及插件兼容性，不用“升级所有软件包”代替系统升级。跨分支或大版本迁移时，按新版本重新核对配置。

升级后重新检查管理地址、地址分配、DNS、IPv6 和常用服务，正常后保存新备份。只在安装插件后出问题时，先停用该插件并回退配置；配置混乱但系统能启动时，再使用验证过的备份或重新配置。系统无法启动则按设备恢复文档处理，虚拟机先查看控制台与系统盘。
