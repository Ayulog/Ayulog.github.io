从外网访问家里的 NAS，采用哪套方案取决于家庭宽带的网络条件：具备公网 IPv4 或公网 IPv6 时，可以通过动态域名（DDNS）配合反向代理直接访问；处于运营商大内网（CGNAT）且无可用 IPv6 时，则可通过异地组网 VPN、公网 VPS 中转或 STUN 穿透连接。

具体工具的部署步骤见 [Lucky：DDNS、证书与反向代理](/posts/lucky-guide/) 与 [ddns-go：自动更新域名的 IP 地址](/posts/ddns-go-guide/)；更多容器服务见 [NAS 服务清单](/posts/nas-software-websites/)。

## 远程访问方案对比

| 网络条件与使用场景                                | 推荐方案                         | 核心前提                                       |
| ------------------------------------------------- | -------------------------------- | ---------------------------------------------- |
| 有公网 IPv4，需通过浏览器直接访问相册、影音等服务 | DDNS + 端口映射 + HTTPS 反向代理 | 路由器具备公网 IPv4，可配置端口转发与防火墙    |
| 无公网 IPv4，但有可用的公网 IPv6                  | IPv6 DDNS + 防火墙放行 + HTTPS   | 家庭与外部访问端（如手机流量）均支持 IPv6      |
| 仅供自己或家人使用，访问端方便安装客户端          | Tailscale / ZeroTier 等组网 VPN  | NAS 与客户端加入同一虚拟局域网                 |
| 无家庭公网入口，但希望对外提供固定域名的 Web 访问 | 公网 VPS + frp 等反向代理隧道    | 拥有一台公网服务器，带宽上限取决于服务器与上行 |
| 不想维护网络组件，仅需日常传文件、看相册          | NAS 厂商自带的远程访问服务       | 使用成品 NAS 系统，接受厂商中继的带宽限制      |
| 无公网 IPv4，但宽带属于全锥型 NAT（NAT1）         | Lucky STUN 穿透                  | NAT 类型允许打洞，能接受外部端口号不定期变化   |

如果是个人或家庭内部使用，即使家里具备公网 IP，也可以优先使用 Tailscale 等异地组网 VPN，避免将 NAS 管理后台或 SMB（`445` 端口）直接暴露到公网；需要免客户端直接用浏览器打开的相册、影视库，再单独通过 HTTPS 反向代理对外发布。

## 判断宽带的公网条件

### 1. 检查公网 IPv4

登录负责宽带拨号的主路由或光猫后台，查看 WAN 口获取到的 IPv4 地址，并与直连网络（关闭代理与 VPN）下通过外部 IP 查询网站看到的出口 IPv4 地址对比。

若 WAN 口地址属于以下范围，说明当前处于内网或运营商共享网络（CGNAT），无法直接接收外网入站连接：

| 地址范围                            | 地址类型                      |
| ----------------------------------- | ----------------------------- |
| `10.0.0.0/8`                        | 局域网私有地址                |
| `172.16.0.0/12`（`172.16–31.*.*`）  | 局域网私有地址                |
| `192.168.0.0/16`                    | 局域网私有地址                |
| `100.64.0.0/10`（`100.64–127.*.*`） | 运营商级 NAT（CGNAT）共享地址 |

- 如果主路由 WAN 口显示 `192.168.1.x`，通常是光猫负责拨号、主路由处于二级路由模式。此时需登录光猫查看其 WAN 口是否为公网 IP；若有公网 IP，可将光猫改为桥接模式由主路由拨号。
- 如果拨号设备的 WAN IPv4 与外部查询到的出口 IP 一致，即具备公网 IPv4。家用宽带重拨后 IP 会发生变化，配合 DDNS 即可将域名动态绑定到最新 IP（80、443 等常用端口通常被运营商封禁，对外服务需选用非标准高端口）。

### 2. 检查公网 IPv6

没有公网 IPv4 时，可检查 NAS 或运行反向代理的设备是否分配到了 `2000::/3` 开头（常见如 `2408:`、`2409:`、`240e:`）的全球单播 IPv6 地址（`fe80::/10` 为链路本地地址，`fc00::/7` 为内网唯一本地地址，均不可用于外网访问）。

通过公网 IPv6 直连需同时满足三个条件：

1. **家庭侧拿到可路由前缀**：运营商下发了公网 IPv6 前缀，且 NAS 获取到了全球单播地址。
2. **入站防火墙放行**：对外服务已监听 IPv6，且主路由 IPv6 防火墙与 NAS 防火墙放行了目标服务端口的入站流量。
3. **访问端具备 IPv6**：外网客户端所在的网络（如手机 4G/5G 移动网络）同样支持 IPv6 访问。

## 有公网 IP：DDNS 与反向代理直连

### Lucky 与 ddns-go 的分工

| 工具                                          | 核心功能                                                     | 适用场景                                   |
| --------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------ |
| [ddns-go](https://github.com/jeessy2/ddns-go) | 定时检测本机 IPv4 / IPv6 并更新 DNS 服务商的 A / AAAA 记录   | 已配好证书与端口转发，仅需补充动态域名更新 |
| [Lucky](https://lucky666.cn/)                 | 集成 DDNS、ACME 自动证书、Web 反向代理、端口转发与 STUN 穿透 | 一站式管理域名解析、HTTPS 证书与反向代理   |

两者选其一维护域名解析即可（切勿让两个工具同时更新同一个域名的同类型记录）。具体容器部署步骤见：

- **仅需动态域名解析**：[ddns-go：自动更新域名的 IP 地址](/posts/ddns-go-guide/)
- **DDNS + 证书 + 反向代理**：[Lucky：DDNS、证书与反向代理](/posts/lucky-guide/)

### 公网 IPv4 / IPv6 直连配置要点

- **公网 IPv4 直连**：在路由器中为 NAS 绑定固定内网 IP → 配置 DDNS 更新域名的 **A 记录** → 用 DNS-01 方式申请 ACME 证书 → 在 Lucky 中监听外部 HTTPS 端口（如 `18443`）并反代内网应用 → 在路由器中将外部 TCP `18443` 端口映射到 NAS。完整步骤见 [Lucky 的 IPv4 配置](/posts/lucky-guide/#方案一公网-ipv4--ddns--lucky-反向代理)。
- **公网 IPv6 直连**：配置 DDNS 将域名的 **AAAA 记录** 指向 Lucky 所在设备的公网 IPv6 地址 → 在 Lucky 中启用 IPv6 监听与 TLS 证书，后端仍可指向内网 IPv4 容器 → 在路由器 IPv6 防火墙中放行发往该设备对应端口的入站 TCP 连接。完整步骤见 [Lucky 的 IPv6 配置](/posts/lucky-guide/#方案二公网-ipv6--ddns--lucky)。

> [!NOTE]
> DNS 的 A / AAAA 记录仅解析 IP 地址，不包含端口号。使用 `18443` 等非标准端口时，浏览器访问需填写完整地址 `https://photos.example.com:18443`。若仅 IPv6 可用，请删除该域名下的无效 A 记录，避免客户端优先请求不通的 IPv4 地址。

## 无公网 IP：异地组网与内网穿透

当宽带既无公网 IPv4，又无可用 IPv6（或出差、公司等外部网络不支持 IPv6）时，可按使用场景选择以下方案：

### 方案一：Tailscale 等异地组网 VPN

[Tailscale](https://tailscale.com/) 与 ZeroTier 可将不同网络下的 NAS、电脑和手机加入同一个虚拟局域网：

1. 在 NAS 与外出使用的电脑、手机上分别安装客户端并登录同一账号（或通过分享机制加入同一网络）。
2. 客户端开启连接后，直接使用 Tailscale 分配的 `100.x.y.z` 虚拟局域网 IP 或 MagicDNS 主机名访问 NAS 上的各项服务。
3. 若部分设备不便安装客户端，可在 NAS 上启用 Subnet Router（子网路由）暴露家庭局域网网段。

Tailscale 会优先尝试建立点对点直连（Direct），打洞受阻时自动回退至 DERP 中继节点（Relay），可通过 `tailscale status` 或 `tailscale ping` 查看当前连接路径。

### 方案二：NAS 厂商自带远程访问

绿联、群晖、飞牛等成品 NAS 均内置了官方远程访问与中继服务，绑定账号后即可通过官方 App 或网页连接。该方式免去了网络配置，适合日常管理、手机相册备份与轻量文件存取；若需高频远程播放高码率原盘视频或访问自建 Docker 容器，仍需结合组网 VPN 或其他穿透方案。

### 方案三：公网 VPS + frp 反向隧道

若没有家庭公网入口，但希望外部设备免装客户端、直接通过固定域名访问 Web 服务，可借助一台带公网 IP 的云服务器（VPS）部署 [frp](https://github.com/fatedier/frp)：

- **工作方式**：VPS 运行服务端 `frps`，家里 NAS 运行客户端 `frpc` 并主动向 VPS 发起长连接；外部用户访问指向 VPS 的域名时，流量经由隧道转发回 NAS 指定服务。
- **配置要点**：开启 `frpc` 与 `frps` 之间的身份认证与传输加密（TLS），在 VPS 或 NAS 侧配置 HTTPS 证书，且仅映射已开启登录验证的 Web 应用。远程访问的速度上限取决于家庭上行带宽与 VPS 的公网带宽。

<span id="方案四lucky-stun适合愿意折腾的环境"></span>

### 方案四：Lucky STUN 内网穿透

在宽带属于全锥型 NAT（NAT1）的环境下，可使用 Lucky 提供的 [STUN 内网穿透模块](https://lucky666.cn/docs/modules/stun) 获取运营商 NAT 映射出的公网 IPv4 地址与端口：

1. 将光猫改为桥接、由主路由拨号，并在主路由上开启 UPnP 或指向 Lucky 所在设备的端口转发。
2. 在 Lucky 的 **STUN 内网穿透** 模块中添加规则，设置本地监听端口与转发目标，启动后从规则日志中查看探测到的外部公网地址与端口。
3. 使用手机移动网络访问该外部地址与端口验证连通性。

STUN 穿透获得的公网端口号由运营商 NAT 动态分配，重拨或映射超时后端口号会发生变化（Lucky 官方文档亦注明该功能受限于运营商 NAT 类型，无法固定公网端口），可通过 Webhook 通知或自定义重定向页跟踪最新端口。

## 安全加固与带宽预估

- **收敛管理入口**：路由器后台、SSH、NAS 系统桌面、Lucky（`16601`）、ddns-go（`9876`）以及 SMB 文件共享（`445`）建议仅通过内网或组网 VPN 访问，不要直接映射至公网。
- **启用强密码与二次验证**：对外开放的 Web 服务（如相册、影视库、网盘）需设置独立强密码，并在支持的应用中开启两步验证（2FA）。
- **家庭上行带宽换算**：在外网从 NAS 下载文件或播放视频时，消耗的是家庭宽带的**上行带宽**。例如家庭上行为 `50 Mbps`，理论峰值约为 `6.25 MB/s`（扣除协议开销后约 `5–5.8 MB/s`）；远程播放高码率 4K 视频时，若码率超过家庭上行带宽，需在影视服务端开启硬件转码限流。

## 常见问题

### DDNS 显示更新成功，但外网仍然打不开

按连接链路从外向内依次检查：

1. **验证 DNS 解析**：确认域名解析出的 IP 不是代理节点地址或内网保留地址，且已度过 DNS 缓存 TTL。测试连通性时直接用浏览器或 `curl` 访问实际的 HTTPS 端口（路由器 WAN 口默认禁 `ping`，无需以 `ping` 结果为准）。
2. **核对公网与转发规则**：IPv4 需确认主路由 WAN 口确为公网 IP 且已配置端口映射（若光猫拨号则需桥接或两级映射）；IPv6 需确认客户端具备 IPv6 网络，且路由器 IPv6 防火墙已放行目标设备的对应端口。
3. **核对反向代理与后端**：确认 Lucky 的 Web 规则已勾选对应的监听类型（IPv4 / IPv6），子规则的前端域名拼写无误，且 Lucky 容器能够正常访问后端的 `http://NAS_IP:端口`。

### 手机用流量能打开，连家里 Wi-Fi 反而打不开域名

这是由于主路由未开启或不支持 **NAT 回环（NAT Loopback / Hairpin NAT）**，导致内网设备请求本机公网 IPv4 时无法正确折返。可在路由器设置中开启 NAT 回环，或在局域网 DNS（如路由器 `dnsmasq`、AdGuard Home）中添加一条自定义劫持规则，将该域名在内网直接解析为 `NAS_IP`。

### ACME 证书申请成功，为何外网还是连不上

使用 **DNS-01** 方式申请证书时，证书颁发机构（Let's Encrypt 等）仅通过查询域名的公共 DNS TXT 记录验证域名所有权，不会向家庭宽带发起入站连接。证书签发成功后，仍需完成上面的路由器端口映射（IPv4）或防火墙放行（IPv6）配置。
