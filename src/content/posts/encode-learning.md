压完一遍，手上只剩一个能播放的文件，说不清体积和画面的变化来自哪一步。留一段能反复回看的样片，记下输入，做出基线，一次只改一项，遇到报错再按问题查文档；练习结束时应该剩下样片、命令或设置、日志和比较记录。

各操作篇已经写过流程本身，这里不预设一组对所有素材都适用的编码参数。首次练习可选图形工具，已有脚本需求时再接 VapourSynth；旧教程里的 Python、插件和编码器组合，要与本机版本对应。软件选型、系统教程、博客与官方文档集中在[压制软件与资料清单](/posts/encode-software/)。

## 从概念到一轮短片练习

先分清容器、编码格式和编码器，再理解帧率、位深、色度采样、码率与色彩范围。读概念时可以从[压制清单的系统教程](/posts/encode-software/#入门与完整流程)选一套作为主线，不必同时读完全部资料。

接下来用一段短片走完一轮练习。只有单个任务能稳定完成，才继续研究批量任务、自动生成脚本、分段和异常复检。自动化会重复同一组设置，先确认这组设置对目标素材成立。

## 第一步：记录来源与目标

选择自己能够正常读取的一份源文件，用 MediaInfo 或 ffprobe 保存输入信息。蓝光素材先确认正确的节目与播放列表；不同剪辑版本不能只靠片名判断。

| 记录项         | 要写清什么                                             |
| -------------- | ------------------------------------------------------ |
| 来源与时间范围 | 影片版本、使用的文件或播放列表、样片起止位置           |
| 视频规格       | 编码、分辨率、帧率、位深、色度采样及色彩信息           |
| 音轨与字幕     | 需要保留的轨道、语言、延迟与字体                       |
| 输出目标       | 目标设备、容器、尺寸，以及画质、体积和速度的取舍       |
| 工具环境       | 前端、帧服务器、源滤镜与编码器版本；只写实际用到的组件 |

先选一段能连续回看的素材。需要比较不同画面问题时，再补充暗部、渐变、运动、细线和颗粒片段；保留各片段的来源位置，下一轮使用相同范围。

## 第二步：建立可播放的基线

根据任务选一条路线，先完成输入到输出的闭环。

- **图形工具路线**：按[一键压制教程](/posts/encode-one-click/)打开来源，从合适的预设开始，核对尺寸、帧率、音轨与字幕，输出一段短片。
- **脚本路线**：按[VapourSynth 教程](/posts/encode-vapoursynth/)验证环境，先用最小脚本读出画面，再按需裁边、缩放并交给编码器。
- **编码器比较**：按[编码教程](/posts/encode-codecs/)准备同一输入片段，核对具体实现及调用接口，保存完整命令。

初次输出先不叠加一长串滤镜。检查视频是否完整、画幅和颜色是否符合预期，再加入音轨与字幕完成封装。先播放成品，确认没有明显的时间线问题，之后才把它作为比较基线。

基线文件与后续试验文件分别保存。每一份输出都应能对应到一份设置、脚本或命令，避免比较时已经忘记文件是怎样生成的。

## 第三步：一次只比较一个问题

先写出本轮要回答的问题，例如：某个滤镜是否减轻了渐变色带，同时有没有损失细节。不要在同一轮同时更换源滤镜、缩放方法、编码器和质量设置，否则难以判断变化来自哪里。

| 比较条件 | 做法                                           |
| -------- | ---------------------------------------------- |
| 输入     | 使用相同的源片段与时间范围                     |
| 处理     | 保留基线设置，只修改本轮要观察的一项           |
| 播放     | 使用相同播放器设置、显示条件和画面位置         |
| 结果     | 记录画面变化、输出体积、编码耗时及日志中的异常 |

先连续回看，再对代表帧做细看。更小的体积不是单独的结论：需要写清保留或损失了什么、是否符合目标。不同编码器的同一个 CRF 数字也不是相同质量，编码比较的方法见[编码篇](/posts/encode-codecs/#怎样比较试压结果)。

如果一个改动没有回答原先的问题，保留记录并回到基线。不要把所有试过的参数继续堆进最终设置。

## 第四步：按问题查文档

先保存完整报错、命令、最小脚本和软件版本，再判断问题发生在哪个环节。教程帮助解释思路；参数名称、默认值和接口按所用版本的项目文档核对。

| 现象或疑问                               | 先定位到哪里                   | 查阅时核对什么                                           |
| ---------------------------------------- | ------------------------------ | -------------------------------------------------------- |
| 脚本不能导入片源，或 `vspipe` 没有输出帧 | VapourSynth 环境、源滤镜与输入 | Python 和插件接口、实际报错、源文件支持情况              |
| 编码器拒绝某个参数                       | 编码器或前端包装层             | 构建版本、调用接口、完整帮助；第三方修改版可能有额外选项 |
| 输出颜色、范围或画幅不符合预期           | 源信息、滤镜处理与输出标记     | 输入解释与实际像素是否变化；只改显示标签不会改变画面     |
| 封装后字幕样式不对                       | 字幕轨、字体与渲染方式         | 是否保留 ASS、所需字体，以及播放端对标签的支持           |
| 声音或字幕逐渐偏移                       | 来源版本与时间线               | 起始偏移、帧率及剪辑是否一致，避免把版本差异当成固定延迟 |

当前项目文档见[压制清单的文档表](/posts/encode-software/#查当前用法时回到项目文档)。记录所查页面与版本号；`latest` 页面、旧博客和本机二进制未必对应同一版本。

读取旧教程时，先区分长期适用的分析方法与当时使用的软件组合。例如，AviSynth 脚本不能直接作为 VapourSynth 脚本使用，社区修改版编码器的参数也未必存在于上游。只摘录与当前问题有关的部分，再回到最小样片验证。

## 第五步：封装验收与保存记录

确认样片结果可以接受后，再把同一套已核对的处理用于完整素材。检查全片画幅或来源变化，不能用一个局部样片代替所有场景。

完成视频编码后，继续检查最终封装：音轨语言、默认标记、字幕字体、章节，以及开头、中段、结尾的音画字幕同步。还要在目标设备上播放；编码器正常结束只说明这一环节结束。

每次练习保留以下内容：

- 输入规格、来源位置、目标要求与软件版本。
- 实际采用的设置、脚本、完整命令和日志。
- 基线与试验样片，以及代表场景的比较记录。
- 最终采用或放弃某项调整的原因，仍未解决的问题。

后续更新插件或编码器时，可以用相同样片重做比较，分清变化来自素材、处理步骤还是软件版本。
